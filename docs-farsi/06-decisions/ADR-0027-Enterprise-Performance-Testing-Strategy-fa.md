# هدف

این سند تصمیم‌گیری معماری، استراتژی لایه‌بندی‌شده تست عملکرد، بار و مقیاس‌پذیری را در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

بر اساس ارزیابی فنی TE-0033، هیچ ابزار واحدی نمی‌تواند به تنهایی تمامی ابعاد تست عملکرد (مانند الگوریتم‌ها، جریان‌های کاری سیستم و APIهای REST) را پوشش دهد.

---

# ۲. تصمیم (Decision)

پلتفرم سه فناوری مکمل زیر را برای سنجش عملکرد اتخاذ می‌کند:

| مسئولیت | فناوری تاییدشده |
|---------------|------------|
| **میکرو بنچمارکینگ الگوریتم‌ها و کد** | **BenchmarkDotNet** |
| **تست بار و جریان‌های کاری سازمانی** | **NBomber** |
| **تست بار و مقیاس‌پذیری APIهای REST** | **k6** |

- **BenchmarkDotNet**: برای بنچمارک دقیق الگوریتم‌ها، نگاشت‌ها، سریال‌سازی و محاسبات داینامیک درون برنامه استفاده می‌شود.
- **NBomber**: برای شبیه‌سازی کاربران همزمان، فشار روی دیتابیس، سیستم پیام‌رسانی و کارایی کلی جریان‌های کاری پلتفرم استفاده می‌شود.
- **k6**: برای سنجش رفتار، تاخیر و مقیاس‌پذیری نقاط پایانی HTTP/REST و API Gateway در خارج از برنامه استفاده می‌شود.

---

# ۳. پیامدها (Consequences)

پیامدهای مثبت:
- پوشش کامل تمامی لایه‌های عملکردی نرم‌افزار؛
- شناسایی دقیق گلوگاه‌های عملکردی در لایه‌های مختلف؛
- ادغام تست‌های عملکرد در پایپ‌لاین CI/CD.
