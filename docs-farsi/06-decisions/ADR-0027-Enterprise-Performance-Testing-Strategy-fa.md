# زمینه و بستر (Context)

سامانه MachineryManagerEnterprise یک برنامه کاربردی توزیع‌شده در سطح سازمانی است که شامل موارد زیر است:

- کلاینت دسکتاپ (Desktop Client)
- سرویس‌های کاربرد (Application Services)
- SQL Server
- RabbitMQ
- Redis
- Qdrant
- پردازشگران پس‌زمینه (Background Workers)

بنابراین، اعتبارسنجی کارایی و عملکرد باید در چندین لایه معماری رخ دهد.

هیچ فریم‌ورک منفردی برای آزمون عملکرد به اندازه کافی موارد زیر را پوشش نمی‌دهد:

- کارایی الگوریتم‌ها؛
- بار کاری برنامه (Application Workload)؛
- مقیاس‌پذیری HTTP/API.

---

# بیان مسئله (Problem)

استفاده از یک فناوری آزمون منفرد باعث می‌شود ریسک‌های عمده کارایی و عملکرد آزموده نشده باقی بمانند.

نمونه‌ها شامل:

- الگوریتم‌های سریع اما رابط‌های برنامه‌نویسی (API) کند؛
- رابط‌های برنامه‌نویسی مقیاس‌پذیر اما منطق تجاری ناکارآمد؛
- کد بهینه‌سازی‌شده اما رفتار ضعیف در پردازش همزمان (Concurrent).

بنابراین یک استراتژی لایه‌بندی‌شده آزمون عملکرد مورد نیاز است.

---

# محرک‌های تصمیم‌گیری (Decision Drivers)

معماری باید از موارد زیر پشتیبانی کند:

- بنچ‌مارک در مقیاس ریز (Micro Benchmarking)
- آزمون بار (Load Testing)
- آزمون استرس (Stress Testing)
- آزمون استقامت (Endurance Testing)
- آزمون مقیاس‌پذیری رابط‌های برنامه‌نویسی (API Scalability Testing)
- شناسایی مداوم پس‌رفت عملکرد (Continuous Performance Regression Detection)
- اتوماسیون CI/CD
- قابلیت نگهداری بلندمدت

---

سامانه MachineryManagerEnterprise سه فناوری مکمل آزمون عملکرد را اتخاذ می‌نماید.

| آزمون بار API | k6 |

هر فناوری دارای یک مسئولیت معماری انحصاری است.

# معماری عملکرد سازمانی (Enterprise Performance Architecture)

```text
                Performance Validation
                (اعتبارسنجی عملکرد)

                         │

        ┌────────────────┼────────────────┐

        ▼                ▼                ▼

 BenchmarkDotNet      NBomber            k6

        │                │                │

   Algorithms     Business Workflows   REST APIs
  (الگوریتم‌ها)   (گردش‌کارهای تجاری) (رابط‌های REST)

```

---

# استراتژی بنچ‌مارک (Benchmarking Strategy)

ابزار BenchmarkDotNet باید برای موارد زیر استفاده شود:

- الگوریتم‌ها؛
- مخازن داده (Repositories)؛
- سریال‌سازی (Serialization)؛
- کش‌گذاری (Caching)؛
- تجزیه و پارس کردن (Parsing)؛
- کارایی محاسباتی.

ابزار BenchmarkDotNet **نباید** برای آزمون بار سیستم استفاده شود.

---

# استراتژی آزمون بار سازمانی (Enterprise Load Testing Strategy)

ابزار NBomber باید موارد زیر را اعتبارسنجی کند:

- کاربران همزمان؛
- گردش کارهای تجاری؛
- پیام‌رسانی؛
- توان عملیاتی پایگاه داده (Database Throughput)؛
- اجرای طولانی‌مدت؛
- مقیاس‌پذیری سیستم.

ابزار NBomber فریم‌ورک اصلی آزمون بار سازمانی می‌شود.

---

# استراتژی آزمون بار رابط‌های برنامه‌نویسی (API Load Testing Strategy)

ابزار k6 باید موارد زیر را اعتبارسنجی نماید:

- رابط‌های REST API؛
- اندپوینت‌های HTTP؛
- درگاه‌های API (API Gateways)؛
- مقیاس‌پذیری زیرساخت؛
- زمان تاخیر قابل مشاهده از بیرون.

ابزار k6 **نباید** برای بنچ‌مارک کردن الگوریتم‌های داخلی .NET استفاده شود.

```text

   │

Publish Reports (انتشار گزارش‌ها)
```

# خط‌مشی پس‌رفت عملکرد (Performance Regression Policy)

هر پیاده‌سازی که کار محاسباتی قابل اندازه‌گیری ایجاد می‌کند باید بنچ‌مارک شود.

با پس‌رفت‌های عملکردی باید مشابه پس‌رفت‌های عملکردی رفتاری و کارکردی برخورد شود.

---

# گزارش‌گیری (Reporting)

گزارش‌های عملکرد باید برای هر بار اجرای CI آرشیو شوند.

انواع گزارش‌های پشتیبانی‌شده شامل موارد زیر است:

- Markdown
- HTML
- JSON
- CSV

گزارش‌های تاریخی تحلیل روند را در سراسر نسخه‌ها فراهم می‌آورند.

---

# محیط‌های آزمون (Test Environments)

اعتبارسنجی عملکرد باید در محیط‌های زیر اجرا گردد:

- توسعه محلی (Local Development)
- یکپارچه‌سازی مداوم (Continuous Integration)
- محیط اختصاصی عملکرد (Dedicated Performance Environment)

محیط‌های عملیاتی (Production) نباید برای آزمون بار مصنوعی مورد استفاده قرار گیرند.

---

# معیارهای عملکرد (Performance Metrics)

معیارهای زیر در صورت کاربرد باید جمع‌آوری شوند:

- زمان اجرا (Execution Time)
- توان عملیاتی (Throughput)
- زمان پاسخ (Response Time)
- تاخیر (Latency)
- تخصیص حافظه (Memory Allocation)
- مصرف پردازنده (CPU Usage)
- نرخ خطا (Error Rate)
- کاربران همزمان (Concurrent Users)

# پیامدها (Consequences)

مثبت:

- اعتبارسنجی قابل اطمینان عملکرد
- اندازه‌گیری‌های تکرارپذیر
- یکپارچگی با CI
- تضمین مقیاس‌پذیری سازمانی

منفی:

- چندین ابزار تخصصی
