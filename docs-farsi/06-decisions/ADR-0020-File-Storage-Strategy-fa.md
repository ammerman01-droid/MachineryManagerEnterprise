# هدف

این سند تصمیم‌گیری معماری، استراتژی ذخیره‌سازی فایل‌های پیوست، اسناد و فایل‌های باینری را در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

در سند ADR-0012 (معماری فضای کاری توزیع‌شده) مقرر شد که پیوست‌های فایل (مانند تصاویر، اسناد بازرسی و دفترچه‌ها) به صورت مجزا از متاداده‌ها منتقل شوند.

ارزیابی فنی TE-0026 راه‌حل‌های مختلف شامل ذخیره‌سازی محلی (Local Storage)، Azure Blob Storage، MinIO و الگوی انتزاعی S3-Compatible را بررسی کرد و یک لایه انتزاعی سازگار با API S3 را توصیه کرد.

---

# ۲. تصمیم (Decision)

پلتفرم تمامی محتواهای باینری پیوست را صرفاً از طریق یک انتزاع در لایه Application به نام `IFileStorage` دسترسی خواهد داشت:

- **پیاده‌سازی اصلی `IFileStorage` بر اساس API Amazon S3** ساخته می‌شود که از طریق تنظیمات قابل انتقال به هر سرویس‌دهنده سازگار با S3 است.
- **MinIO به عنوان گزینه پیش‌فرض، متن‌باز و قابل میزبانی محلی** برای استقرارهای در محل (On-Premise) و ایزوله (Air-Gapped) انتخاب می‌شود.
- سرویس‌دهندگان ابری سازگار با S3 (مانند AWS S3) می‌توانند بدون تغییر کد برنامه‌نویسی برای استقرارهای ابری تنظیم شوند.
- پیاده‌سازی ثانویه **Local Storage** برای استقرارهای بسیار کوچک و تک‌سروری حفظ می‌شود.

---

# ۳. قوانین انطباق (Compliance Rules)

1. تمامی دسترسی‌ها به محتوای باینری باید از طریق انتزاع `IFileStorage` انجام شود.
2. پیاده‌سازی پیش‌فرض `IFileStorage` باید بر اساس SDK S3 باشد.
3. MinIO سرویس‌دهنده پیش‌فرض محلی برای استقرارهای On-Premise است.
4. پیاده‌سازی `LocalFileStorage` تنها برای سیستم‌های تک‌سرور کوچک استفاده می‌شود.

---

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- یکسانی کد برای محیط‌های On-Premise، Air-Gapped و Cloud؛
- عدم وابستگی به یک ارائه دهنده ابری خاص (Cloud Neutrality)؛
- امکان استفاده از URLهای دارای امضا (Presigned URLs) حتی در استقرارهای محلی از طریق MinIO.
