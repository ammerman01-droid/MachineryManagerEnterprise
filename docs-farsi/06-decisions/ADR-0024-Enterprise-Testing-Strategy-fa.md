# هدف

این سند تصمیم‌گیری معماری، استراتژی لایه‌بندی‌شده و جامع تست‌های نرم‌افزاری را در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

پلتفرم از معماری پاک، CQRS، DDD و معماری رویدادمحور استفاده می‌کند. برای تضمین صحت عملکرد و عدم بروز خطا در لایه‌های مختلف، یک استراتژی یکپارچه تست بر اساس **هرم تست (Test Pyramid)** نیازمند است.

سند ارزیابی فنی TE-0030 ابزارهای زیر را برای تست انتخاب کرده است:
- **xUnit v3**
- **FluentAssertions**
- **NSubstitute**
- **Testcontainers**
- **Playwright**

---

# ۲. تصمیم (Decision)

پلتفرم هرم تست لایه‌بندی‌شده زیر را اتخاذ می‌کند:

- **تست‌های واحد (Unit Tests)**: بخش اعظم تست‌ها را تشکیل می‌دهند (xUnit + FluentAssertions + NSubstitute). لایه‌های Domain و Application بدون نیاز به دیتابیس یا شبکه تست می‌شوند.
- **تست‌های یکپارچه‌سازی (Integration Tests)**: تعامل با زیرساخت‌های واقعی (SQL Server, RabbitMQ, Redis) را با استفاده از **Testcontainers** سنجش می‌کنند.
- **تست‌های سرتاسری (End-to-End Tests)**: سناریوهای کامل کاربری و رابط کاربری را از طریق **Playwright** اعتبارسنجی می‌کنند.
- **تست‌های معماری (Architecture Tests)**: قوانین وابستگی لایه‌ها و مرزهای معماری پاک را بررسی می‌کنند.

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- بازخورد سریع به توسعه‌دهندگان؛
- اطمینان بالا در ریفکتورینگ و توسعه؛
- اجرای خودکار و ایزوله تست‌های زیرساخت با Testcontainers؛
- جلوگیری از انحراف معماری پاک.
