# زمینه و مسئله (Context)

سامانه MachineryManagerEnterprise نیازمند یک پلتفرم نرم‌افزاری مدرن و با کارایی بالا است که بتواند از توسعه سازمانی بلندمدت پشتیبانی کند.

پلتفرم انتخاب‌شده باید موارد زیر را ارائه دهد:

- کارایی عالی زمان اجرا (Runtime performance)
- پشتیبانی بلندمدت (LTS)
- ویژگی‌های زبان مدرن
- قابلیت چندپلتفرمی (Cross-platform)
- ابزارهای توسعه قوی
- اکوسیستم فعال
- پشتیبانی بومی از محیط‌های ابری

همچنین این پلتفرم باید با اصول معماری پاک و اولویت با متن‌باز در پروژه همراستا باشد.

---

# تصمیم (Decision)

پروژه باید از **.NET 10** به عنوان پلتفرم اصلی توسعه استفاده کند.

تمامی پروژه‌های راهکار باید SDK هدف خود را .NET 10 قرار دهند مگر اینکه یک استثنای صریح معماری تصویب شده باشد.

---

# محرک‌های تصمیم (Decision Drivers)

- کارایی (Performance)
- پشتیبانی بلندمدت (Long-Term Support)
- قابلیت نگهداری (Maintainability)
- استقلال از فناوری (Technology Independence)
- اکوسیستم (Ecosystem)
- ابزارها (Tooling)
- آمادگی برای ابر (Cloud Readiness)
- بهره‌وری توسعه‌دهندگان (Developer Productivity)

---

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

## .NET 9

رد شد زیرا .NET 10 آخرین بهبودهای پلتفرم را ارائه داده و به عنوان پایه بلندمدت پروژه عمل می‌کند.

---

## Java Spring Boot

رد شد زیرا یک استک فناوری اضافی وارد می‌کرد بدون اینکه مزیت معماری قابل توجهی برای این راهکار ارائه دهد.

---

## Node.js

رد شد زیرا برای معماری سازمانی و نیازمندهای بک‌اند تایپ‌شدگی قوی (Strongly-typed) این پروژه مناسب‌تر نبود.

---

# پیامدها (Consequences)

## مثبت

- استک فناوری یکپارچه
- کارایی عالی زمان اجرا
- پشتیبانی قوی مایکروسافت
- ویژگی‌های مدرن زبان #C
- ابزارهای عالی توسعه
- قابلیت نگهداری بالا

## منفی

- ارتقاء نسخه‌های اصلی در آینده نیازمند برنامه‌ریزی است.
- به‌روزرسانی‌های SDK باید پیش از پذیرش اعتبارسنجی شوند.

# قوانین انطباق (Compliance Rules)

۱. تمامی پروژه‌ها باید .NET 10 را هدف قرار دهند.

۲. نسخه‌های پیش‌نمایش SDK نباید در محیط تولید استفاده شوند.

۳. نسخه‌های زمان اجرا در سراسر راهکار باید یکنواخت باقی بمانند.

۴. وابستگی‌های جدید باید از .NET 10 پشتیبانی کنند.
