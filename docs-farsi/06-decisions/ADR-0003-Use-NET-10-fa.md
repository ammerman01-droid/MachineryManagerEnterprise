# زمینه و مسئله (Context)

سامانه MachineryManagerEnterprise نیازمند یک پلتفرم نرم‌افزاری مدرن با کارایی و عملکرد فوق‌العاده بالا است که بتواند از توسعه بلندمدت سیستم‌های سازمانی پشتیبانی به عمل آورد.

پلتفرم انتخابی باید ویژگی‌های زیر را فراهم سازد:

- عملکرد و کارایی عالی در زمان اجرا (Runtime performance)
- پشتیبانی بلندمدت (Long-term support)
- ویژگی‌ها و امکانات مدرن زبان برنامه‌نویسی
- قابلیت اجرای چندسکویی و مستقل از سیستم‌عامل (Cross-platform capability)
- ابزارهای توسعه قدرتمند (Strong tooling)
- اکوسیستم فعال و پویا
- پشتیبانی بومی از محیط‌های ابری (Native cloud support)

همچنین این پلتفرم باید با اصول معماری پاک (Clean Architecture) و سیاست اولویت متن‌باز (Open Source First) پروژه کاملاً همخوانی داشته باشد.

---

# تصمیم (Decision)

این پروژه **.NET 10** را به عنوان پلتفرم اصلی توسعه برمی‌گزیند.

تمامی پروژه‌های درون Solution باید SDK دات‌نت ۱۰ را هدف قرار دهند، مگر آنکه یک استثنای صریح معماری به تصویب رسیده باشد.

---

- کارایی و عملکرد (Performance)
- پشتیبانی بلندمدت (Long-Term Support)
- قابلیت نگهداری (Maintainability)

- بهره‌وری توسعه‌دهندگان (Developer Productivity)

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

## پلتفرم .NET 9

رد شد؛ زیرا .NET 10 جدیدترین بهبودهای پلتفرم را ارائه داده و به عنوان پایه و فونداسیون بلندمدت پروژه عمل خواهد کرد.

---

## پلتفرم Java Spring Boot

رد شد؛ زیرا یک پشته فناوری متفاوت و اضافی را وارد پروژه می‌کرد، در حالی که هیچ مزیت معماری قابل توجهی برای این راهکار به همراه نداشت.

---

## پلتفرم Node.js

رد شد؛ زیرا برای معماری سازمانی این پروژه و نیازمندی‌های بک‌اند دارای سیستم نوع‌بندی قوی (Strongly typed) تناسب کمتری دارد.

---

# پیامدها (Consequences)

## پیامدهای مثبت (Positive)

- پشته فناوری یکپارچه و منسجم (Unified technology stack)
- کارایی و سرعت اجرای فوق‌العاده (Excellent runtime performance)
- پشتیبانی قوی مایکروسافت (Strong Microsoft support)
- ویژگی‌های مدرن زبان سی‌شارپ (Modern C# language features)
- ابزارهای توسعه بی‌نظیر (Excellent tooling)
- قابلیت نگهداری بسیار بالا (High maintainability)

## پیامدهای منفی (Negative)

- ارتقاهای نسخه‌های اصلی در آینده نیازمند برنامه‌ریزی است.
- به‌روزرسانی‌های SDK باید پیش از به‌کارگیری ارزیابی و اعتبارسنجی شوند.

---

# تأثیر بر معماری (Architecture Impact)

پلتفرم .NET 10 فونداسیون و پایه فنی تمامی لایه‌های معماری را شکل می‌دهد.

انتخاب‌های فناوری در آینده باید با ران‌تایم انتخاب‌شده کاملاً سازگار باقی بمانند.

---

# نکات پیاده‌سازی (Implementation Notes)

تمامی پروژه‌ها باید تارگت زیر را داشته باشند:

```xml
<TargetFramework>net10.0</TargetFramework>
```

انتخاب و تثبیت نسخه SDK در صورت لزوم باید از طریق فایل زیر کنترل شود:

```
global.json
```

---

# قوانین انطباق (Compliance Rules)

۱. کلیه پروژه‌ها باید .NET 10 را هدف قرار دهند.

۲. نسخه‌های پیش‌نمایش (Preview SDKs) نباید در محیط‌های عملیاتی و پروداکشن استفاده شوند.

۳. نسخه ران‌تایم باید در سراسر تمام پروژه‌های Solution کاملاً یکنواخت و هماهنگ باشد.

۴. وابستگی‌های جدید حتماً باید از .NET 10 پشتیبانی کنند.
