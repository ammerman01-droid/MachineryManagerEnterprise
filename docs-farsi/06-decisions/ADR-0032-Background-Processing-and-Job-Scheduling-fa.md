# زمینه و بستر (Context)

پلتفرم سازمانی نیازمند مکانیسم‌های قدرتمندی برای پردازش ناهمگام، اجرای وظایف پس‌زمینه، و زمان‌بندی کارهای مبتنی بر CRON/فواصل زمانی در هر دو محیط نودهای زمان اجرای یکپارچه و ورکر‌های توزیع‌شده است. این وظایف شامل نگهداری و پاکسازی زمان‌بندی‌شده داده‌ها، پردازش ناهمگام پیام‌ها، تولید گزارش‌ها، و همگام‌سازی‌های دوره‌ای می‌باشد.

نیازمندی‌های کلیدی:
- اجرای مطمئن وظایف تکرارشونده (پشتیبانی از عبارات CRON، تریگرهای مبتنی بر بازه زمانی).
- پردازش پس‌زمینه درون‌حافظه‌ای ناهمگام و سبک‌وزن برای پیام‌رسانی غیرجفت‌شده (Decoupled).
- پشتیبانی از مخازن ماندگار وظایف (SQLite برای نودهای فضای کاری محلی/مستقل، PostgreSQL/SQL Server برای کلاسترهای ابری مرکزی) جهت تضمین اجرای کارها در سراسر راه‌اندازی‌های مجدد برنامه.
- یکپارچگی کامل با سرویس‌های میزبانی‌شده .NET 10 (`IHostedService` / `BackgroundService`)، OpenTelemetry، و لاگ‌گیری Serilog.
- انطباق با خط‌مشی اولویت متن‌باز (ADR-0002).

---

# تصمیم (Decision)

۱. **تصویب Quartz.NET** به عنوان موتور اصلی زمان‌بندی کارهای سازمانی برای وظایف پس‌زمینه زمان‌بندی‌شده، دوره‌ای و ماندگار (رسمی‌سازی سند **TE-0014** و **TE-0019**).
۲. **تصویب System.Threading.Channels** برای صف‌های پس‌زمینه تولیدکننده-مصرف‌کننده (Producer-Consumer) درون‌حافظه‌ای با توان بالا در نمونه‌های انفرادی برنامه در جاهایی که زمان‌بندی ماندگار مورد نیاز نیست.
۳. پیکربندی Quartz.NET جهت استفاده از:
   - **SQLite JobStore / ADO.NET JobStore** در محیط‌های فضای کاری دسکتاپ محلی/آفلاین.
   - **PostgreSQL / SQL Server JobStore** در استقرارهای سرور کلاسترشده برای مدیریت قفل‌های توزیع‌شده و اعزام وظایف با تحمل‌پذیری خطا (Fault-tolerant).
۴. یکپارچه‌سازی وظایف Quartz.NET با تزریق وابستگی .NET 10 از طریق `IJobFactory` و ابزارسازی استاندارد OpenTelemetry.

# محرک‌های تصمیم‌گیری (Decision Drivers)

- **کامل بودن ویژگی‌ها (Feature Completeness):** ابزار Quartz.NET زمان‌بندی بالغ بر پایه CRON، مدیریت اجرای از دست رفته (Misfire Handling)، وضعیت ماندگار وظایف، و کلاسترینگ را ارائه می‌دهد.
- **انعطاف‌پذیری (Flexibility):** از ذخیره‌سازی درون‌حافظه‌ای برای استقرارهای سبک و JobStore مبتنی بر پایگاه داده برای عملیات سازمانی تاب‌آور پشتیبانی می‌کند.
- **خط‌مشی اولویت متن‌باز (Open Source First Policy):** ابزار Quartz.NET کاملاً متن‌باز (تحت لایسنس Apache 2.0) بدون دیواره‌های پرداخت تجاری است (برخلاف ویژگی‌های پولی Hangfire Pro).
- **یکپارچگی بومی با دات‌نت (Native .NET Integration):** همراستایی یکپارچه با `IHostedService` و چرخه حیات ASP.NET Core.

---

# گزینه‌های بررسی‌شده (Alternatives Considered)

- **ابزار Hangfire:** رابط کاربری و API فوق‌العاده، اما ویژگی‌های هسته سازمانی (مانند چندمستاجری، وظایف دسته‌ای) نیازمند مجوزهای تجاری پولی (Hangfire Pro) هستند، که ناقض ADR-0002 است.
- **استفاده از `BackgroundService` بومی همراه با `System.Threading.Timer`:** سبک‌وزن است اما فاقد مخزن ذخیره‌سازی ماندگار وظایف، تجزیه‌کننده سینتکس CRON، خط‌مشی‌های misfire، و هماهنگی کلاستر می‌باشد.
- **ابزار Coravel:** ساده و سبک‌وزن است، اما فاقد کلاسترینگ وظایف در سطح سازمانی، زمان‌بندی پیچیده CRON، و بک‌اندهای ذخیره‌سازی ماندگار و بالغ مورد نیاز برای بارهای کاری حساس سازمانی است.

# پیامدها (Consequences)

### مثبت (Positive)
- معماری زمان‌بندی وظایف یکپارچه و در سطح سازمانی در سراسر فضاهای کاری محلی و کلاسترهای سرور.
- هزینه صفر برای مجوزهای تجاری (کاملاً متن‌باز تحت Apache 2.0).
- تضمین‌های اجرای بادوام وظایف با استفاده از JobStoreهای ماندگار.
- یکپارچگی بومی با تله‌متری و لاگ‌گیری پلتفرم.

### منفی (Negative)
- نیازمند ایجاد اسکیما و جداول پایگاه داده برای ADO.NET JobStore در حالت کلاسترشده.
- نیازمند مدیریت صحیح همزمانی وظایف و سریال‌سازی وضعیت.
