# زمینه و مسئله (Context)

سامانه MachineryManagerEnterprise نیازمند یک نگاشت‌کننده شیء-رابطه‌ای (ORM) مدرن است که بتواند از اپلیکیشن‌های سازمانی پشتیبانی کرده و در عین حال جداسازی معماری و قابلیت نگهداری بلندمدت را حفظ کند.

نگاشت‌کننده ORM انتخاب‌شده باید موارد زیر را ارائه دهد:

- کارایی بالا
- یکپارچه‌سازی قوی با .NET
- پشتیبانی از LINQ
- مدیریت مهاجرت‌ها (Migrations)
- پشتیبانی از تراکنش‌ها (Transactions)
- توسعه فعال
- ابزارهای عالی

همچنین ORM باید به صورت طبیعی با معماری پاک (Clean Architecture) یکپارچه شود.

---

# تصمیم (Decision)

لایه زیرساخت (Infrastructure Layer) باید از **Entity Framework Core** به عنوان ORM اصلی استفاده کند.

تمامی دسترسی‌ها به دیتابیس‌های رابطه‌ای باید از طریق Entity Framework Core پیاده‌سازی شوند.

لایه‌های Application و Domain باید مستقل از EF Core باقی بمانند.

---

# محرک‌های تصمیم (Decision Drivers)

- پشتیبانی بومی در .NET
- کارایی (Performance)
- قابلیت نگهداری (Maintainability)
- اکوسیستم بالغ
- پشتیبانی از مهاجرت‌ها (Migrations)
- پشتیبانی از LINQ
- ابزارهای قوی
- پشتیبانی جامعه کاربری

---

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

## Dapper

رد شد زیرا با وجود ارائه کارایی فوق‌العاده، فاقد مدیریت تغییرات داخلی (Built-in change tracking)، مهاجرت‌ها و قابلیت‌های سطح بالای ORM مورد نیاز در این راهکار است.

---

## NHibernate

رد شد زیرا دارای پیچیدگی بالاتر و نرخ پذیرش پایین‌تری در اپلیکیشن‌های مدرن .NET است.

---

## Linq2Db

رد شد زیرا اکوسیستم و جامعه کاربری آن کوچک‌تر از EF Core است.

---

# پیامدها (Consequences)

## مثبت

- مدل ماندگاری داده‌ها یکپارچه
- ابزارهای عالی
- پشتیبانی قوی از LINQ
- سیستم مهاجرت‌های داخلی
- قابلیت نگهداری بالا
- مستندات عالی

## منفی

- اورهد انتزاعی کمی بالاتر در مقایسه با Micro ORMها.
- توسعه‌دهندگان باید ردیابی تغییرات (Change tracking) و چرخه حیات DbContext را به خوبی درک کنند.

---

# تاثیر بر معماری (Architecture Impact)

فناوری Entity Framework Core تنها باید درون **لایه زیرساخت (Infrastructure Layer)** وجود داشته باشد.

لایه Domain هرگز نباید به EF Core ارجاع دهد.

لایه Application تنها از طریق انتزاع‌های مخزن داده (Repository) یا واحد کاری (Unit of Work) به داده‌ها دسترسی خواهد داشت.

لایه Infrastructure این انتزاع‌ها را پیاده‌سازی می‌کند.

---

# نکات پیاده‌سازی (Implementation Notes)

لایه Infrastructure باید شامل موارد زیر باشد:

- کلاس DbContext
- پیکربندی موجودیت‌ها (Entity configurations)
- پیاده‌سازی مخازن داده (Repository implementations)
- مهاجرت‌ها (Migrations)

لایه Application اینترفیس‌های مخازن داده را تعریف می‌کند.

لایه Domain بدون اطلاع از جزئیات ماندگاری داده باقی می‌ماند (Persistence-ignorant).

---

# قوانین انطباق (Compliance Rules)

۱. فناوری Entity Framework Core تنها باید درون Infrastructure وجود داشته باشد.

۲. لایه Domain هرگز نباید به Microsoft.EntityFrameworkCore ارجاع دهد.

۳. لایه Application هرگز نباید به Microsoft.EntityFrameworkCore ارجاع دهد.

۴. کلاس DbContext هرگز نباید به Domain تزریق شود.

۵. مهاجرت‌ها (Migrations) تنها باید درون Infrastructure نگهداری شوند.

۶. اینترفیس‌های مخازن داده متعلق به لایه Application هستند.

۷. پیاده‌سازی مخازن داده متعلق به لایه Infrastructure است.

۸. منطق ماندگاری داده‌ها هرگز نباید درون Presentation وجود داشته باشد.
