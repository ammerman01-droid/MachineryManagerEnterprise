# هدف

این سند تصمیم‌گیری معماری، معماری رابط کاربری (Presentation Layer) و الگوهای طراحی برنامه کلاینت دسکتاپ پلتفرم MachineryManagerEnterprise را تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

پلتفرم MachineryManagerEnterprise یک برنامه دسکتاپ مستقل از سیستم‌عامل (Cross-platform) است. لایه ارائه باید کاملاً از منطق کسب‌وکار ایزوله بوده و از اصول معماری پاک و الگوی **MVVM** تبعیت کند.

ارزیابی فنی TE-0034 گزینه‌های مختلف UI را بررسی کرده است.

---

# ۲. تصمیم (Decision)

برنامه کلاینت معماری UI زیر را اتخاذ می‌کند:

| مسئولیت | فناوری تاییدشده |
|---------------|------------|
| **فریم‌ورک دسکتاپ چندسکویی** | **Avalonia UI** |
| **کتابخانه کامپوننت‌های بصری** | **FluentAvalonia** |
| **فریم‌ورک MVVM** | **CommunityToolkit.Mvvm** |

- **Avalonia UI**: فریم‌ورک اصلی گرافیکی برای اجرای دسکتاپ روی ویندوز، لینوکس و مک.
- **FluentAvalonia**: کتابخانه کامپوننت‌های مدرن بصری (طراحی Fluent).
- **CommunityToolkit.Mvvm**: فریم‌ورک استاندارد، سبُک و مبتنی بر Source Generatorها برای پیاده‌سازی MVVM (Binding، Commands، ObservableProperties).
- **ReactiveUI اتخاذ نشده است** (به دلیل پیچیدگی غیرضروری).

---

# ۳. مسئولیت لایه‌ها در MVVM

- **Views (نمای بصری)**: صرفاً مسئول رندر عناصر بصری، چیدمان، Binding و وضعیت‌های بصری هستند. هیچ منطق کسب‌وکاری درون View قرار نمی‌گیرد.
- **ViewModels**: مسئول نگهداری وضعیت ارائه، دستورات کاربر (Commands) و ارتباط با لایه Application هستند. ViewModels مستقیماً به لایه Infrastructure دسترسی ندارند.
- **Application Layer**: مسئول اجرای موارد کاربری کسب‌وکار و برگرداندن DTOها بدون هیچ‌گونه وابستگی به UI.

---

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- ایزوله‌سازی کامل منطق کسب‌وکار از UI و تست‌پذیری بالای ViewModels؛
- تجربه کاربری یکنواخت و مدرن روی تمامی سیستم‌عامل‌ها؛
- معماری پاک و قابل نگهداری در بلندمدت.
