# زمینه و بستر (Context)

سند `TE-0018 — ارزیابی فناوری مدیریت پیکربندی و اسرار` تصویب شده بود اما هیچ سند ثبت تصمیم معماری (ADR) متناظری برای آن وجود نداشت. پلتفرم نیازمند یک رویکرد منسجم و با نوع‌بندی قوی (Strongly Typed) برای پیکربندی و یک مرز مشخص میان مقادیر پیش‌فرض غیرحساس و اسرار حساس در سراسر استقرارهای محیط توسعه، محلی (On-premises)، و آژور است.

---

# تصمیم (Decision)

سامانه MachineryManagerEnterprise معماری پیکربندی و اسرار زیر را اتخاذ می‌نماید که رسمی‌سازی سند TE-0018 است:

| مسئولیت | فناوری انتخاب‌شده |
|-----------------|---------------------|
| انتزاع پیکربندی | Microsoft.Extensions.Configuration |
| پیکربندی با نوع‌بندی قوی | Microsoft.Extensions.Options |
| پیکربندی پیش‌فرض | appsettings.json (صرفاً مقادیر غیرحساس) |
| بازنویسی‌های زمان استقرار | متغیرهای محیطی (Environment Variables) |
| اسرار محیط توسعه | .NET User Secrets |
| مخزن سازمانی اسرار | HashiCorp Vault |
| جایگزین آژور | Azure Key Vault |
| پرچم‌های ویژگی (Feature Flags) | Microsoft.FeatureManagement |

ماژول‌های تجاری هرگز نباید مستقیماً به ارائه‌دهندگان پیکربندی دسترسی داشته باشند. صرفاً اشیاء با نوع‌بندی قوی Options باید به درون سرویس‌های برنامه تزریق شوند. فایل‌های پیکربندی JSON صرفاً باید حاوی مقادیر پیش‌فرض غیرحساس باشند.

---

# محرک‌های تصمیم‌گیری (Decision Drivers)

- معماری پاک (عدم دسترسی مستقیم به ارائه‌دهنده از ماژول‌های تجاری)
- بی‌طرفی ابری (Vault به عنوان گزینه اصلی، Azure Key Vault به عنوان جایگزین)
- امنیت (عدم وجود اسرار در فایل‌های تحت کنترل سورس کد)
- انطباق با استانداردها

---

# گزینه‌های بررسی‌شده (Alternatives Considered)

برای مقایسه کامل کاندیداها در سراسر کتابخانه‌های پیکربندی و مخازن اسرار، به TE-0018 مراجعه نمایید.

---

# پیامدها (Consequences)

**مثبت (Positive)**

- تفکیک شفاف پیکربندی‌های غیرحساس از اسرار و کلیدها.
- پیکربندی با نوع‌بندی قوی خطاهای زمان اجرای پیکربندی را کاهش می‌دهد.

**منفی / سبک‌سنگین‌ها (Negative / Trade-offs)**

- نیازمند اجرای زیرساخت HashiCorp Vault (یا Azure Key Vault) در محیط‌های عملیاتی است.

---

# تاثیر معماری (Architecture Impact)

- لایه Infrastructure مالکیت ثبت ارائه‌دهنده‌ها را بر عهده دارد.
- لایه Application صرفاً Options با نوع‌بندی قوی را مصرف می‌نماید.

---

# نکات پیاده‌سازی (Implementation Notes)

- ثبت انواع Options از طریق `IOptions<T>` / `IOptionsSnapshot<T>`.
- استفاده از .NET User Secrets در حین توسعه محلی اجباری خواهد بود.
