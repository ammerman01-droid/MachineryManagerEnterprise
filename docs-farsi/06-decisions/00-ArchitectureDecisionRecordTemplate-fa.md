# قالب سند تصمیم‌گیری معماری (Architecture Decision Record Template)

| ویژگی | مقدار |
|----------|-------|
| **شناسه سند** | ADR-XXXX |
| **نسخه** | 4.0.0 |
| **وضعیت** | پیش‌نهادشده / پذیرفته‌شده / جایگزین‌شده / منسوخ‌شده |
| **مالک** | معمار راهکار (Solution Architect) |
| **تاریخ ایجاد** | YYYY-MM-DD |
| **آخرین به‌روزرسانی** | 2026-07-28 |

---

# عنوان

عنوان خلاصه‌ای که تصمیم معماری را توصیف می‌کند ارائه دهید.

مثال:

```
استفاده از Entity Framework Core
```

---

# وضعیت

مقادیر ممکن:

- پیش‌نهادشده (Proposed)
- پذیرفته‌شده (Accepted)
- منسوخ‌شده (Deprecated)
- جایگزین‌شده (Superseded)

---

# زمینه و مسئله (Context)

مسئله معماری را توصیف کنید.

توضیح دهید:

- زمینه کسب‌وکار
- زمینه فنی
- محدودیت‌ها
- وضعیت موجود

خواننده باید درک کند که **چرا** اتخاذ یک تصمیم لازم بوده است.

---

# تصمیم (Decision)

راهکار انتخاب‌شده را توصیف کنید.

این بخش باید تنها شامل خود تصمیم باشد.

از توضیح گزینه‌های جایگزین در این بخش خودداری کنید.

---

# محرک‌های تصمیم (Decision Drivers)

عوامل اصلی که بر این تصمیم تاثیر گذاشته‌اند را فهرست کنید.

مثال‌ها:

- قابلیت نگهداری (Maintainability)
- کارایی (Performance)
- سادگی (Simplicity)
- خط‌مشی متن‌باز (Open Source Policy)
- امنیت (Security)
- جامعه کاربری (Community)
- پشتیبانی بلندمدت (Long-Term Support)

---

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

تمامی گزینه‌های جایگزین مهم را فهرست کنید.

مثال:

- گزینه الف
- گزینه ب
- گزینه ج

هر گزینه جایگزین باید به اختصار توصیف شود.

---

# پیامدها (Consequences)

پیامدهای اتخاذ این تصمیم را توصیف کنید.

شامل:

- پیامدهای مثبت
- پیامدهای منفی
- موازنه و توافق‌ها (Trade-offs)
- محدودیت‌های آتی

---

# تاثیر بر معماری (Architecture Impact)

توصیف کنید که کدام لایه‌های معماری تحت تاثیر قرار می‌گیرند.

مثال:

- لایه ارائه (Presentation)
- لایه کاربرد (Application)
- لایه زیرساخت (Infrastructure)
- لایه دامنه (Domain)

همچنین هرگونه پیامد وابستگی را مستند کنید.

---

# نکات پیاده‌سازی (Implementation Notes)

راهنمای پیاده‌سازی ارائه دهید.

مثال‌ها:

- ثبت سرویس‌ها (Registration)
- پیکربندی (Configuration)
- قوانین کدنویسی
- نکات مهاجرت (Migration notes)

---

# قوانین انطباق (Compliance Rules)

قوانین اجباری که توسعه‌دهندگان باید رعایت کنند را تعریف کنید.

مثال:

```
Entity Framework Core تنها باید درون لایه زیرساخت (Infrastructure) قرار گیرد.
```

---

# ارزیابی فناوری مرتبط (Related Technology Evaluation)

به ارزیابی فناوری مربوطه ارجاع دهید.

مثال:

```
TE-0004
```

---

# اثبات مفهوم مرتبط (Related Proof of Concept)

در صورت وجود، به اثبات مفهوم ارجاع دهید.

مثال:

```
POC-0001
```

اگر POC وجود ندارد، صریحاً قید کنید:

```
نیاز نیست (Not Required)
```
