# عنوان (Title)

عنوان مختصری برای توصیف تصمیم معماری ارائه دهید.

مثال:

```
Use Entity Framework Core
```

---

# وضعیت (Status)

مقادیر ممکن:

- Proposed (پیشنهادشده)
- Accepted (پذیرفته‌شده)
- Deprecated (منسوخ)
- Superseded (جایگزین‌شده)

---

# زمینه و مسئله (Context)

مسئله معماری را توصیف کنید.

توضیح دهید:

- زمینه کسب‌وکار (Business context)
- زمینه فنی (Technical context)
- محدودیت‌ها (Constraints)
- وضعیت موجود (Existing situation)

خواننده باید متوجه شود که **چرا** اتخاذ یک تصمیم الزامی بوده است.

---

# تصمیم (Decision)

راهکار انتخاب‌شده را توصیف کنید.

این بخش باید فقط و فقط حاوی خود تصمیم باشد.

از توضیح گزینه‌های جایگزین در این قسمت خودداری کنید.

---

# پیش‌ران‌های تصمیم (Decision Drivers)

عوامل اصلی تأثیرگذار بر تصمیم را فهرست کنید.

مثال‌ها:

- قابلیت نگهداری (Maintainability)
- کارایی و عملکرد (Performance)
- سادگی (Simplicity)
- سیاست استفاده از نرم‌افزارهای متن‌باز (Open Source Policy)
- امنیت (Security)
- جامعه کاربری (Community)
- پشتیبانی بلندمدت (Long-Term Support)

---

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

تمامی گزینه‌های جایگزین بااهمیت را فهرست کنید.

مثال:

- گزینه الف (Option A)
- گزینه ب (Option B)
- گزینه ج (Option C)

هر گزینه جایگزین باید به صورت مختصر شرح داده شود.

---

# پیامدها (Consequences)

پیامدهای ناشی از اتخاذ این تصمیم را توصیف کنید.

شامل:

پیامدهای مثبت (Positive consequences)

پیامدهای منفی (Negative consequences)

بده‌بستان‌ها و موازنه‌ها (Trade-offs)

محدودیت‌های آینده (Future limitations)

---

# تأثیر بر معماری (Architecture Impact)

توصیف کنید کدام لایه‌های معماری تحت تأثیر قرار می‌گیرند.

مثال:

- لایه نمایش (Presentation)
- لایه اپلیکیشن (Application)
- لایه زیرساخت (Infrastructure)
- لایه دامنه (Domain)

همچنین هرگونه پیامد در وابستگی‌ها را مستند کنید.

---

# نکات پیاده‌سازی (Implementation Notes)

رهنمودهای پیاده‌سازی را ارائه دهید.

مثال‌ها:

- ثبت و رجیستریشن سرویس‌ها (Registration)
- پیکربندی و تنظیمات (Configuration)
- قواعد کدنویسی (Coding rules)
- نکات مایگریشن و ارتقا (Migration notes)

---

# قوانین انطباق (Compliance Rules)

قوانین الزامی که توسعه‌دهندگان باید رعایت کنند را تعریف کنید.

مثال:

```
Entity Framework Core shall exist only inside Infrastructure.
```

---

# ارزیابی فناوری مرتبط (Related Technology Evaluation)

به سند ارزیابی فناوری (TE) مربوطه ارجاع دهید.

مثال:

```
TE-0004
```

---

# اثبات مفهوم مرتبط (Related Proof of Concept)

در صورت وجود، به نمونه اثبات مفهوم (POC) ارجاع دهید.

مثال:

```
POC-0001
```

در صورتی که هیچ POC وجود ندارد، صراحتاً قید کنید:

```
Not Required
```
