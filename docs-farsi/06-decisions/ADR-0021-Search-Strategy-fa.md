# هدف

این سند تصمیم‌گیری معماری، استراتژی جستجوی متنی (Free-text search) را در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

تمامی ماژول‌های پلتفرم نیازمند قابلیت جستجوی متنی روی نام، توضیحات، یادداشت‌ها و سایر فیلدهای متنی هستند.

سند ارزیابی فنی TE-0027 گزینه‌های مختلف شامل Full-Text Search در SQL Server، PostgreSQL، Elasticsearch، OpenSearch و Azure AI Search را بررسی کرد.

---

# ۲. تصمیم (Decision)

تمامی دسترسی‌ها به قابلیت‌های جستجوی متنی صرفاً از طریق انتزاع `ISearchService` در لایه Application انجام می‌شود:

- **SQL Server Full-Text Search فناوری پیش‌فرض جستجوی متنی (Lexical Search)** برای تمامی استقرارها خواهد بود و نیازمند هیچ زیرساخت اضافی نیست.
- **OpenSearch** می‌تواند به عنوان یک پیاده‌سازی اختیاری `ISearchService` برای استقرارهای بزرگتر استفاده شود.
- **Elasticsearch و Azure AI Search** به دلیل محدودیت‌های مجوز و وابستگی ابری انتخاب نشدند.
- **جستجوی ترکیبی (Hybrid Search)** ترکیب‌کننده جستجوی واژگانی (Lexical) و معنایی (Semantic/Vector) به عنوان جهت‌گیری آینده پلتفرم تایید شد.

---

# ۳. قوانین انطباق (Compliance Rules)

1. تمامی دسترسی‌ها به جستجو باید از طریق `ISearchService` انجام شود.
2. SQL Server Full-Text Search پیاده‌سازی پیش‌فرض است.
3. OpenSearch تنها مسیر تاییدشده برای ارتقای توان جستجو در سیستم‌های بزرگ است.
4. ایندکس‌های جستجو هرگز نباید منبع مرجع داده‌ها باشند؛ آن‌ها همیشه از داده‌های اصلی ساخته می‌شوند.

---

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- قابلیت جستجوی متنی بدون هزینه زیرساختی اضافی در حالت پیش‌فرض؛
- حفظ استقلال از ابر (Cloud Neutrality)؛
- مسیر مشخص برای ارتقا به OpenSearch یا جستجوی ترکیبی.
