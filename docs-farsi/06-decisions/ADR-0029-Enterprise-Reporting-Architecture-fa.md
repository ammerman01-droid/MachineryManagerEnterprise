# هدف

این سند تصمیم‌گیری معماری، استراتژی و ابزارهای تولید گزارش‌های سازمانی (مانند دستورکارها، گزارش‌های ماشین‌آلات، بازرسی، گزارش‌های مالی و خروجی‌های اکسل) را در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

سیستم‌های گزارش‌گیری سنتی مبتنی بر طراح‌های بصری (Designer-based) باعث ایجاد فایل‌های بیرونی، عدم امکان کنترل نسخه مناسب در Git و ورود منطق کسب‌وکار به قالب‌ها می‌شوند. پلتفرم نیازمند یک استراتژی **کد محور (Code-First)** و کاملاً سازگار با معماری پاک است.

ارزیابی فنی TE-0035 ابزارهای گزارش‌گیری را بررسی کرده است.

---

# ۲. تصمیم (Decision)

پلتفرم معماری گزارش‌گیری کد-محور زیر را اتخاذ می‌کند:

| مسئولیت | فناوری تاییدشده |
|---------------|------------|
| **تولید اسناد PDF** | **QuestPDF** |
| **تولید فایل‌های Excel** | **ClosedXML** |

- **QuestPDF**: کتابخانه کد-محور پیشرفته در C# برای تولید گزارش‌های چاپی، دستورکارها و اسناد PDF با کارایی بسیار بالا.
- **ClosedXML**: کتابخانه کد-محور در C# برای ایجاد، قالب‌بندی و خروجی‌های اکسل، تحلیل داده‌ها و فاکتورها.
- ابزارهای طراح-محور مانند FastReport و RDLC اکیداً کنار گذاشته می‌شوند.

---

# ۳. جریان داده‌های گزارش‌گیری (Report Data Flow)

```text
Domain
  │
  ▼
Application DTO
  │
  ▼
Report Service
  │
  ▼
QuestPDF / ClosedXML
  │
  ▼
Generated Document (PDF / Excel)
```

موتورهای گزارش‌گیری فقط DTOها را مصرف می‌کنند و هرگز مستقیماً به دیتابیس یا موجودیت‌های دامنه دسترسی ندارند.

---

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- گزارش‌گیری کاملاً Code-First و تحت کنترل نسخه (Git)؛
- کیفیت بالا و خروجی کاملاً متوازن در تمامی سیستم‌عامل‌ها؛
- عدم وابستگی به طراح‌های بصری سنگین و پیچیده؛
- امکان اتوماسیون کامل در CI/CD و Jobهای پس‌زمینه.
