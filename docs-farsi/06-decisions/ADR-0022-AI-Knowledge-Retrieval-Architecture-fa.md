# هدف

این سند تصمیم‌گیری معماری، مدل بازیابی دانش و بازیابی مبتنی بر افزودن متون (RAG) را برای قابلیت‌های هوش مصنوعی در پلتفرم MachineryManagerEnterprise تعیین می‌کند.

---

# ۱. زمینه و مسئله (Context)

پلتفرم قابلیت‌های هوش مصنوعی مانند جستجوی معنایی، دستیار دانش سازمانی، RAG و توصیه‌های هوشمند ارائه می‌دهد.

سند ارزیابی فنی TE-0028 ابزار **Qdrant** را به عنوان دیتابیس برداری (Vector Database) انتخاب کرد، در حالی که Microsoft SQL Server دیتابیس اصلی عملیاتی است.

---

# ۲. تصمیم (Decision)

- **داده‌های عملیاتی**: Microsoft SQL Server همچنان **سیستم مرجع (System of Record)** برای تمام داده‌های کسب‌وکار باقی می‌ماند. بردارها در SQL Server ذخیره نمی‌شوند.
- **ذخیره‌سازی بردارها**: Qdrant به عنوان زیرساخت اختصاصی بازیابی معنایی عمل می‌کند (ذخیره‌سازی امبدینگ‌ها، ایندکس‌های ANN و جستجوی شباهت). Qdrant هرگز داده‌های عملیاتی کسب‌وکار را ذخیره نمی‌کند.
- **مالکیت امبدینگ‌ها**: امبدینگ‌ها مصنوعات مشتق‌شده هستند و داده‌های مرجع کسب‌وکار محسوب نمی‌شوند.
- **استراتژی همگام‌سازی**: همگام‌سازی بردارها به صورت رویدادمحور (Event-Driven) انجام می‌شود (`DocumentCreated`, `DocumentUpdated`, `DocumentDeleted`).

---

# ۳. جریان بازیابی (Retrieval Workflow)

1. پرسش کاربر به بردار (Embedding) تبدیل می‌شود.
2. جستجوی شباهت در Qdrant شناسه (ID) اسناد مرتبط را برمی‌گرداند.
3. اسناد کامل بر اساس شناسه از SQL Server فراخوانی می‌شوند.
4. بافت (Context) تشکیل شده و به مدل لغوی بزرگ (LLM) ارسال می‌شود.

---

# ۴. پیامدها (Consequences)

پیامدهای مثبت:
- بازیابی معنایی با کارایی بالا بدون وارد کردن بار اضافی به دیتابیس عملیاتی؛
- تفکیک کامل مسئولیت‌ها و امکان مقیاس‌پذیری مستقل؛
- حفظ استقلال از تامین‌کنندگان ابری.
