# زمینه و مسئله (Context)

راهکار MachineryManagerEnterprise نیازمند یک فریم‌ورک مدرن برای رابط کاربری وب است که به صورت طبیعی با پلتفرم انتخابی دات‌نت ادغام شده و پیچیدگی‌های فناوری را به حداقل برساند.

لایه نمایش (Presentation Layer) باید:

- از همان زبان برنامه‌نویسی اصلی بک‌اند (سی‌شارپ) استفاده نماید.
- از توسعه مبتنی بر کامپوننت (Component-based development) پشتیبانی کند.
- به صورت یکپارچه و بدون درز با ASP.NET Core ادغام شود.
- در طول سالیان متمادی قابلیت نگهداری داشته باشد.
- از وابستگی‌های غیرضروری به جاوااسکریپت اجتناب ورزد.
- با نقشه راه بلندمدت مایکروسافت همسو باشد.

---

# تصمیم (Decision)

لایه نمایش (Presentation Layer) باید از **Blazor** به عنوان فریم‌ورک اصلی رابط کاربری (UI) استفاده نماید.

سامانه Blazor Web Apps (.NET 10) به عنوان مدل میزبانی (Hosting model) برای این راهکار مورد استفاده قرار خواهد گرفت.

---

# پیش‌ران‌های تصمیم (Decision Drivers)

- توسعه تک‌زبانه با سی‌شارپ (Single-language development - C#)
- ادغام و یکپارچگی عمیق با دات‌نت (.NET integration)
- معماری کامپوننت‌محور (Component architecture)
- قابلیت نگهداری (Maintainability)
- پشتیبانی بلندمدت مایکروسافت (Long-term Microsoft support)
- بهره‌وری توسعه‌دهندگان (Developer productivity)
- ایمنی نوع داده‌ها در زمان کامپایل (Type safety)

---

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

## فریم‌ورک React

رد شد؛ زیرا زبان‌های JavaScript/TypeScript را به عنوان یک پشته فناوری اصلی و مجزا وارد پروژه می‌کرد.

---

## فریم‌ورک Angular

رد شد؛ به دلیل پیچیدگی بالاتر و منحنی یادگیری تندتر برای نیازمندی‌های این پروژه.

---

## فریم‌ورک Vue

رد شد؛ به دلیل ادغام ضعیف‌تر با اکوسیستم دات‌نت.

---

# پیامدها (Consequences)

## پیامدهای مثبت (Positive)

- پشته فناوری یکپارچه و منسجم (Unified technology stack)
- بررسی قوی خطاها در زمان کامپایل (Strong compile-time checking)
- ادغام فوق‌العاده با ASP.NET Core
- کاهش چشمگیر پیچیدگی‌های کدنویسی جاوااسکریپت (Reduced JavaScript complexity)
- بهبود قابلیت نگهداری (Improved maintainability)
- مهارت‌های مشترک توسعه میان برنامه‌نویسان بک‌اند و فرانت‌اند

## پیامدهای منفی (Negative)

- اکوسیستم ابزارهای شخص ثالث در مقایسه با React کوچک‌تر است.
- برخی ویژگی‌های خاص مرورگرها همچنان نیازمند تعامل با جاوااسکریپت (JS Interop) است.

---

# تأثیر بر معماری (Architecture Impact)

بلیزور صرفاً بر **لایه نمایش (Presentation Layer)** تأثیر می‌گذارد.

لایه‌های Application، Domain، Infrastructure و SharedKernel کاملاً مستقل از کامپوننت‌های Blazor باقی می‌مانند.

لایه Presentation صرفاً از طریق قراردادهای عمومی (Public Contracts) با لایه Application ارتباط برقرار می‌نماید.

---

# نکات پیاده‌سازی (Implementation Notes)

پروژه Presentation باید موارد زیر را به کار گیرد:

- کامپوننت‌های ریزور (Razor Components)
- تزریق وابستگی (Dependency Injection)
- ترکیب UI مبتنی بر کامپوننت (Component-based UI composition)

حالت رندر تعاملی (Interactive rendering mode) بر اساس نیازمندی‌های اپلیکیشن انتخاب خواهد شد.

---

# قوانین انطباق (Compliance Rules)

۱. بلیزور فقط و فقط باید درون لایه Presentation وجود داشته باشد.

۲. لایه Application هرگز نباید اسمبلی‌های Blazor را رفرنس دهد.

۳. لایه Domain هرگز نباید به Blazor رفرنس داشته باشد.

۴. منطق UI هرگز نباید شامل قواعد تجاری و بیزینس باشد.

۵. کامپوننت‌ها باید از طریق سرویس‌ها یا MediatR با لایه Application ارتباط برقرار کنند.
