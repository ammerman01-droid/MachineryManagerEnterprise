# زمینه و مسئله (Context)

سامانه MachineryManagerEnterprise نیازمند یک فریم‌ورک مدرن برای رابط کاربری وب است که به صورت طبیعی با پلتفرم انتخاب‌شده .NET یکپارچه شده و در عین حال پیچیدگی‌های غیرضروری فناوری را به حداقل برساند.

لایه ارائه (Presentation Layer) باید:

- از همان زبان برنامه‌نویسی اصلی بک‌اند استفاده کند.
- از توسعه مبتنی بر کامپوننت پشتیبانی کند.
- به صورت یکپارچه با ASP.NET Core ادغام شود.
- طی سالیان متمادی قابل نگهداری باشد.
- از وابستگی‌های غیرضروری به JavaScript اجتناب ورزد.
- با نقشه راه بلندمدت مایکروسافت همراستا باشد.

---

# تصمیم (Decision)

لایه ارائه (Presentation Layer) باید از **Blazor** به عنوان فریم‌ورک اصلی رابط کاربری استفاده کند.

مدل میزبانی **Blazor Web Apps (.NET 10)** به عنوان مدل میزبانی راهکار استفاده خواهد شد.

---

# محرک‌های تصمیم (Decision Drivers)

- توسعه تک‌زبانه (#C)
- یکپارچه‌سازی قوی با .NET
- معماری کامپوننت‌محور
- قابلیت نگهداری
- پشتیبانی بلندمدت مایکروسافت
- بهره‌وری توسعه‌دهندگان
- امنیت تایپ (Type Safety)

## React

## Angular

رد شد زیرا دارای پیچیدگی بیشتر و منحنی یادگیری تندتری برای نیازمندی‌های این پروژه بود.

---

## Vue

رد شد زیرا یکپارچه‌سازی ضعیف‌تری با اکوسیستم .NET داشت.

# پیامدها (Consequences)

## مثبت

- استک فناوری یکپارچه
- بررسی‌های قوی زمان کامپایل
- یکپارچه‌سازی عالی با ASP.NET Core
- کاهش پیچیدگی‌های JavaScript
- بهبود قابلیت نگهداری
- مهارت‌های توسعه مشترک بین بک‌اند و فرانت‌اند

## منفی

- اکوسیستم شخص ثالث کوچک‌تر در مقایسه با React.
- برخی ویژگی‌های مرورگر همچنان نیازمند تعامل‌پذیری با JavaScript (JS Interop) هستند.

---

# تاثیر بر معماری (Architecture Impact)

فریم‌ورک Blazor تنها بر **لایه ارائه (Presentation Layer)** تاثیر می‌گذارد.

لایه‌های Application، Domain، Infrastructure و SharedKernel کاملاً مستقل از کامپوننت‌های Blazor باقی می‌مانند.

لایه Presentation تنها از طریق قراردادهای عمومی (Public Contracts) با Application ارتباط برقرار می‌کند.

---

# نکات پیاده‌سازی (Implementation Notes)

پروژه Presentation باید موارد زیر را استفاده کند:

- کامپوننت‌های Razor (Razor Components)
- تزریق وابستگی (Dependency Injection)
- ترکیب UI مبتنی بر کامپوننت

حالت رندر تعاملی (Interactive rendering mode) بر اساس نیازمندی‌های اپلیکیشن انتخاب خواهد شد.

---

# قوانین انطباق (Compliance Rules)

۱. فریم‌ورک Blazor تنها باید درون لایه Presentation وجود داشته باشد.

۲. لایه Application هرگز نباید به اسمبلی‌های Blazor ارجاع دهد.

۳. لایه Domain هرگز نباید به Blazor ارجاع دهد.

۴. منطق UI هرگز نباید شامل قوانین کسب‌وکار باشد.

۵. کامپوننت‌ها باید از طریق سرویس‌ها یا MediatR با لایه Application ارتباط برقرار کنند.
