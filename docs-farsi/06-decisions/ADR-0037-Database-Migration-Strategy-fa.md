# زمینه و بستر (Context)

سند ADR-0006 فریم‌ورک Entity Framework Core را به عنوان ORM پلتفرم تصویب کرد (بر اساس TE-0004)، و سند ADR-0019 یک استراتژی ماندگاری ترکیبی را با افزودن Dapper برای پرس‌وجوهای سنگین خواندنی پایه‌گذاری نمود (بر اساس TE-0024). هیچ‌یک از این دو ADR به تکامل اسکیما و مالکیت مهاجرت (Migration Ownership) نپرداخته بودند. سند `TE-0025 — ارزیابی فناوری مهاجرت پایگاه داده` برای بستن این شکاف تصویب شد اما هیچ سند ثبت تصمیم معماری (ADR) متناظری نداشت.

---

# تصمیم (Decision)

سامانه MachineryManagerEnterprise ابزار **مهاجرت‌های EF Core (EF Core Migrations)** را به عنوان تنها مالک تکامل اسکیما اتخاذ می‌نماید که رسمی‌سازی سند TE-0025 است:

| مسئولیت | فناوری انتخاب‌شده |
|-----------------|---------------------|
| تکامل اسکیما (تنها مالک) | EF Core Migrations |

مهاجرت‌های EF Core باید از مدل دامنه EF Core تولید شوند (`dotnet ef migrations add`) و از طریق `dotnet ef database update` یا `Database.MigrateAsync()`، با محافظت بررسی‌های محیطی، به عنوان یک مرحله استقرار صریح اعمال گردند. ابزار Dapper (بر اساس ADR-0019 / TE-0024) کاملاً فقط‌خواندنی باقی می‌ماند و هرگز نباید اسکیما را تغییر دهد.

---

# محرک‌های تصمیم‌گیری (Decision Drivers)

- بازتایید قاعده حاکمیتی TE-0024 (دپر فقط‌خواندنی است)
- مهاجرت‌های مشتق‌شده از مدل نیازمند هیچ ابزار اضافی نیستند
- پشتیبانی بومی از بازگشت به عقب (Rollback)
- سازگاری و انطباق با استاندارد قبلاً تصویب‌شده EF Core (سند ADR-0006)

---

# گزینه‌های بررسی‌شده (Alternatives Considered)

ابزارهای Flyway و Liquibase در TE-0025 از جهت بی‌طرفی نسبت به موتور پایگاه داده (Cross-database-engine) مورد ارزیابی قرار گرفتند، که به دلیل استانداردسازی پلتفرم بر روی SQL Server یک نیازمندی فعلی پلتفرم نیست. برای مقایسه کامل به TE-0025 مراجعه نمایید.

---

# پیامدها (Consequences)

**مثبت (Positive)**

- منبع واحد و معتبر حقیقت اسکیما (مدل EF Core).
- عدم ایجاد سطح دسترسی و اعتبارنامه‌های جدید؛ مهاجرت‌ها از اعتبارنامه‌های موجود و حسابرسی‌شده پایگاه داده استفاده می‌کنند.

**منفی / سبک‌سنگین‌ها (Negative / Trade-offs)**

- قابلیت انتقال میان چندین موتور پایگاه داده (که نقطه قوت Flyway/Liquibase است) در دسترس نیست؛ پلتفرم برای مالکیت اسکیما متعهد به SQL Server است.

---

# تاثیر معماری (Architecture Impact)

- صرفاً لایه Infrastructure. پرس‌وجوهای خواندنی مبتنی بر Dapper (سند ADR-0019) تحت تاثیر قرار نمی‌گیرند و در برابر اسکیمای تحت مالکیت EF Core فقط‌خواندنی باقی می‌مانند.

---

# نکات پیاده‌سازی (Implementation Notes)

- دستور `dotnet ef database update` (یا متد `Database.MigrateAsync()`) باید به عنوان یک گام استقرار صریح و محافظت‌شده با محیط اجرا شود، تا در سند معماری ساخت و استقرار پلتفرم (ADR-0025) بیشتر رسمی‌سازی گردد.
