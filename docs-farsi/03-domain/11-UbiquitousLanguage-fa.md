# ۱. هدف (Purpose)

این مستند **زبان یکپارچه** (Ubiquitous Language) رسمی سامانه MachineryManagerEnterprise را بر اساس اصول طراحی دامنه-محور (DDD) تعریف می‌کند.

هدف اصلی این مستند ایجاد یک واژه‌نامه مشترک، صریح و دقیق است که به طور یکنواخت میان ذینفعان کسب‌وکار، معماران راهکار، مهندسان نرم‌افزار، سورس‌کد برنامه، اسکیماهای دیتابیس، قراردادهای API و رابط‌های کاربری استفاده می‌شود.

---

# ۲. اهداف (Objectives)

زبان یکپارچه موارد زیر را تضمین می‌کند:

- **ارتباطات شفاف و بدون ابهام**: حذف سوءتفاهم میان تیم کسب‌وکار و تیم توسعه نرم‌افزار.
- **انطباق مستقیم با کد**: تضمین این‌که کلاس‌ها، متدها، جداول دیتابیس و نقاط پایانی API دقیقاً از واژگان کسب‌وکار استفاده می‌کنند.
- **دقت در محدوده‌های زمینه**: شفاف‌سازی تعاریف اصطلاحات در محدوده‌های زمینه (Bounded Contexts) مختلف.
- **انطباق دو زبانه**: نگاشت ۱-به-۱ دقیق میان اصطلاحات انگلیسی دامنه و عناوین فارسی رابط کاربری.

---

# ۳. قوانین اصلی حاکمیت زبان (Core Governance Rules)

۱. **منبع واحد حقیقت**: تمامی موجودیت‌های مدل دامنه، شیءهای مقدار (Value Objects)، رویدادهای دامنه، دستورات (Commands)، پرس‌وجوها (Queries) و شناسه کدهای برنامه باید کاملاً با اصطلاحات این مستند مطابقت داشته باشند.
۲. **ممنوعیت مترادف‌ها**: استفاده از چند اصطلاح برای یک مفهوم (مانند استفاده همزمان از `Device` و `Asset`) اکیداً ممنوع است. اصطلاح `Asset` تنها واژه مجاز است.
۳. **عدم نفوذ مفاهیم فنی به واژگان کسب‌وکار**: جزئیات پیاده‌سازی فنی (مانند `AssetRowDTO` یا `EquipmentTableManager`) نباید واژگان دامنه کسب‌وکار را آلوده کنند.
۴. **ممیزی کد**: تحلیل ایستای کد و بازبینی‌های کد باید مطابقت شناسه کدهای برنامه با این مستند را اعتبارسنجی کنند.

# ۴. واژه‌نامه دامنه و نگاشت به کد (Domain Vocabulary Dictionary)

| اصطلاح انگلیسی | عنوان فارسی | محدوده زمینه (Bounded Context) | شناسه در کد (Code Identifier) | تعریف دقیق |
|----------------|-------------|---------------------------------|-------------------------------|------------|
| **Asset** | ماشین‌آلات / دارایی | مدیریت ماشین‌آلات | `Asset` | هرگونه ماشین‌آلات سنگین، تجهیزات یا خودروی تحت مدیریت سیستم. |
| **Asset Category** | دسته‌بندی ماشین‌آلات | مدیریت ماشین‌آلات | `AssetCategory` | طبقه‌بندی تجهیزات (مانند بیل مکانیکی، لودر، جرثقیل، بولدوزر). |
| **Tracked Component** | قطعه تحت‌ردیابی | قطعات تحت‌ردیابی | `TrackedComponent` | قطعه باارزش و دارای شماره سریال که چرخه حیات آن ردیابی می‌شود (مانند موتور، گیربکس). |
| **Meter Reading** | کارکرد کارکردسنج | عملیات ناوگان | `MeterReading` | ثبت کارکرد کارکردسنج (ساعت‌کار یا کیلومتر) برای ماشین‌آلات. |
| **Hour Meter** | ساعت‌کار | عملیات ناوگان | `HourMeter` | شمارنده اندازه‌گیری ساعات عملیاتی تراکمی. |
| **Tire** | تایـر / لاستیک | چرخه حیات تایـر | `Tire` | تایـر دارای شماره سریال که بر اساس موقعیت، عمق عاج و فشار باد ردیابی می‌شود. |
| **Tread Depth** | عمق عاج | چرخه حیات تایـر | `TreadDepth` | ضخامت باقی‌مانده عاج تایر به میلی‌متر. |
| **Battery** | باطری | چرخه حیات باطری | `Battery` | باطری دارای شماره سریال که بر اساس ولتاژ، شاخص سلامت و تاریخچه نصب ردیابی می‌شود. |
| **State of Health (SoH)** | شاخص سلامت باطری | چرخه حیات باطری | `StateOfHealth` | درصد نشان‌دهنده میزان استهلاک و سلامت باطری. |
| **Part** | قطعه / یدکی | کاتالوگ قطعات | `Part` | آیتم کاتالوگ نشان‌دهنده قطعات یدکی و مصرفی. |
| **Cross Reference** | مرجع متقابل قطعه | کاتالوگ قطعات | `PartCrossReference` | نگاشت میان شماره فنی اصلی (OEM) و قطعات معادل سایر سازندگان. |
| **Work Order** | دستور کار | نگهداری و تعمیرات | `WorkOrder` | مجوز رسمی انجام فعالیت‌های نگهداری و تعمیرات. |
| **Maintenance Forecast** | پیش‌بینی سرویس | پیش‌بینی سرویس | `MaintenanceForecast` | زمان‌بندی پیش‌بینانه سرویس‌های آتی بر اساس روند کارکردسنج. |
| **Incident** | حادثه / رخداد | مدیریت حوادث | `Incident` | خرابی ناخواسته، نقص فنی یا حادثه ایمنی گزارش‌شده برای ماشین‌آلات. |
| **Fault Code** | کد خطا | عیب‌یابی | `FaultCode` | کد خطای تشخیصی استاندارد (DTC) ثبت‌شده توسط تلمتری. |
| **Relationship** | رابطه / بستگی | مدیریت روابط | `Relationship` | رابطه کسب‌وکاری میان شرکت‌ها، پیمانکاران یا تامین‌کنندگان. |
| **Workspace** | فضای کاری | همگام‌سازی فضای کاری | `Workspace` | محیط اجرایی محلی یا ابری حاوی داده‌های عملیاتی مستاجر. |
| **Workspace Sync** | همگام‌سازی فضای کاری | همگام‌سازی فضای کاری | `WorkspaceSync` | فرآیند همگام‌سازی میان فضای کاری آفلاین و ابر سازمانی. |
| **AI Assistant** | دستیار هوشمند | دستیار هوشمند | `AIAssistant` | سرویس هوش مصنوعی داخلی برای ارائه تحلیل‌های پیش‌بینانه و پاسخ به پرسش‌ها. |

# ۵. تفاوت‌های معنایی در محدوده‌های زمینه (Context-Specific Variations)

برخی اصطلاحات بر اساس محدوده زمینه (Bounded Context) دارای تعاریف و وضعیت‌های متفاوتی هستند:

- **وضعیت (Status) در زمینه ماشین‌آلات**: نشان‌دهنده وضعیت عملیاتی دستگاه است (`Active`, `UnderMaintenance`, `Decommissioned`, `Sold`).
- **وضعیت (Status) در زمینه دستور کار**: نشان‌دهنده جریان کاری دستور کار است (`Draft`, `Approved`, `InProgress`, `Completed`, `Cancelled`).
- **وضعیت (Status) در زمینه تایـر**: نشان‌دهنده وضعیت فیزیکی است (`InStock`, `Mounted`, `Scrapped`, `Retreaded`).

# ۶. واژگان ممنوعه و الگوهای نادرست (Anti-Patterns & Banned Terminology)

استفاده از اصطلاحات زیر در کد، مستندات و گفتگوهای فنی اکیداً **ممنوع** است:

| اصطلاح ممنوعه / منسوخ | جایگزین الزامی | علت ممنوعیت |
|----------------------|----------------|-------------|
| `Equipment` / `Machine` | `Asset` | نقض استاندارد زبان یکپارچه که روی `Asset` توافق کرده است. |
| `FixTicket` / `Task` | `WorkOrder` | اصطلاح مبهم؛ `WorkOrder` استاندارد رسمی دامنه است. |
| `Item` / `Stuff` | `Part` / `Asset` | اصطلاح کلی و غیرتوصیفی. |
| `UserCompany` | `Company` / `Tenant` | ایجاد خلط مبحث میان احراز هویت و ساختار سازمانی. |
| `DeviceData` | `MeterReading` / `Telemetry` | اصطلاح فنی بدون معنای صریح کسب‌وکاری. |

# ۷. استراتژی ترجمه و بومی‌سازی (Translation & Localization)

۱. **سورس کد**: تمامی کلاس‌های C#، اینترفیس‌ها، Enumها، مشخصه‌ها (Properties)، ستون‌های جداول دیتابیس، فیلدهای JSON در API و پیام‌های کامیت باید الزاماً به زبان **انگلیسی** و با استفاده دقیق از شناسه کدهای جدول فوق نوشته شوند.
۲. **رابط کاربری**: تمامی کامپوننت‌های Blazor، دیالوگ‌های MudBlazor، برچسب‌ها، راهنماها و گزارش‌های PDF خروجی باید از **عناوین فارسی** مصوب استفاده کنند.
۳. **عدم ترجمه تحت‌اللفظی**: ترجمه‌ها باید مطابق با اصطلاحات تخصصی و رایج صنعت در زبان فارسی باشند (مثلاً استفاده از "دستور کار" برای `WorkOrder` به جای "سفارش کار").
