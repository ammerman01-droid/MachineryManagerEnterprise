# ۱. هدف (Purpose)

این سند، **زبان یکپارچه و همه‌جاحاضر (Ubiquitous Language)** رسمی را برای MachineryManagerEnterprise بر اساس اصول طراحی دامنه‌محور (DDD) تعریف می‌کند.

هدف آن ایجاد یک واژگان مشترک، صریح و دقیق است که به‌طور ثابت در میان خبرگان دامنه، معماران سیستم، مهندسان نرم‌افزار، سورس‌کد، اسکیمای پایگاه داده، قراردادهای API و عناوین رابط کاربری استفاده می‌شود.

---

# ۲. اهداف (Objectives)

زبان همه‌جاحاضر موارد زیر را فراهم می‌سازد:

- **ارتباط صریح و بدون ابهام:** سوءتفاهم‌های بین ذی‌نفعان کسب‌وکار و مهندسان نرم‌افزار را از بین می‌برد.
- **انطباق مستقیم کد:** تضمین می‌کند کلاس‌ها، متدها، جداول پایگاه داده و نقاط پایانی API دقیقاً از واژگان کسب‌وکار استفاده می‌کنند.
- **دقت در بافت (Contextual Precision):** تعاریف اصطلاحات را در بافت‌های محدودشده (Bounded Contexts) مشخص برطرف می‌کند.
- **انطباق دو زبانه:** نگاشت ۱ به ۱ بین اصطلاحات دامنه انگلیسی و عناوین رابط کاربری فارسی را تضمین می‌نماید.

---

# ۳. قواعد اصلی راهبری (Core Governance Rules)

۱. **منبع واحد حقیقت (Single Source of Truth):** تمامی موجودیت‌های مدل دامنه، اشیاء مقداری، رویدادهای دامنه، دستورات (Commands)، پرس‌وجوها (Queries) و شناساگرهای کد باید کاملاً با اصطلاحات تعریف‌شده در این سند مطابقت داشته باشند.
۲. **ممنوعیت مترادف‌ها (Zero Synonyms):** استفاده از چند اصطلاح برای یک مفهوم (مثلاً استفاده تبادل‌پذیر از `Device` و `Asset`) اکیداً ممنوع است. `Asset` تنها اصطلاح استاندارد است.
۳. **عدم نفوذ مفاهیم فنی به اصطلاحات کسب‌وکار:** جزئیات پیاده‌سازی فنی (مانند `AssetRowDTO` یا `EquipmentTableManager`) نباید واژگان دامنه کسب‌وکار را آلوده کنند.
۴. **حسابرسی کد:** تحلیل ایستا و بازبینی کد باید انطباق نام موجودیت‌ها با زبان همه‌جاحاضر را راستی‌آزمایی کنند.

# ۴. فرهنگ واژگان دامنه (Domain Vocabulary Dictionary)

| اصطلاح انگلیسی | عنوان فارسی | بافت محدودشده | شناساگر در کد | تعریف |
|--------------|---------------------------|-----------------|-----------------|------------|
| **Asset** | ماشین‌آلات / دارایی | Asset Management | `Asset` | هرگونه ماشین‌آلات سنگین، تجهیزات یا خودروی مدیریت‌شده در سیستم. |
| **Asset Category** | دسته‌بندی ماشین‌آلات | Asset Management | `AssetCategory` | طبقه‌بندی تجهیزات (مانند بیل مکانیکی، لودر، جرثقیل، بلدوزر). |
| **Tracked Component** | قطعه تحت‌ردیابی | Tracked Components | `TrackedComponent` | قطعه باارزش و دارای شماره سریال ردیابی‌شده در طول چرخه عمر (مانند موتور، گیربکس). |
| **Meter Reading** | کارکرد کارکردسنج / قرائت | Fleet Operations | `MeterReading` | ساعات کارکرد یا کیلومتر کارکرد ثبت‌شده برای دارایی. |
| **Hour Meter** | ساعت‌کار / کارکردسنج | Fleet Operations | `HourMeter` | شمارنده اندازه‌گیری ساعات کارکرد عملیاتی انباشته. |
| **Tire** | تایـر / لاستیک | Tire Lifecycle | `Tire` | تایر دارای شماره سریال ردیابی‌شده بر اساس موقعیت، عمق عاج و فشار باد. |
| **Tread Depth** | عمق عاج | Tire Lifecycle | `TreadDepth` | ضخامت باقی‌مانده عاج تایر به میلی‌متر. |
| **Battery** | باطری | Battery Lifecycle | `Battery` | باطری دارای شماره سریال ردیابی‌شده بر اساس ولتاژ، شاخص سلامت و تاریخچه نصب. |
| **State of Health (SoH)** | شاخص سلامت باطری | Battery Lifecycle | `StateOfHealth` | درصد نشان‌دهنده میزان افت کیفیت و سلامت باطری. |
| **Part** | قطعه / یدکی | Parts Catalog | `Part` | آیتم کاتالوگ نشان‌دهنده قطعات یدکی و مواد مصرفی. |
| **Cross Reference** | مرجع متقابل قطعه | Parts Catalog | `PartCrossReference` | نگاشت بین کدهای قطعه سازنده اصلی (OEM) و قطعات معادل سایر سازندگان. |
| **Work Order** | دستور کار | Maintenance | `WorkOrder` | مجوز رسمی انجام فعالیت‌های نگهداری و تعمیرات. |
| **Maintenance Forecast** | پیش‌بینی سرویس | Forecast | `MaintenanceForecast` | زمان‌بندی پیش‌بینانه برای سرویس‌های آتی بر اساس روند کارکرد. |
| **Incident** | حادثه / رخداد | Incident Management | `Incident` | خرابی غیرمنتظره، نقص یا حادثه ایمنی گزارش‌شده برای دارایی. |
| **Fault Code** | کد خطا | Diagnostics | `FaultCode` | کد تشخیص عیب استاندارد (DTC) ثبت‌شده توسط تله‌متری. |
| **Relationship** | رابطه / بستگی | Relationships | `Relationship` | رابطه کسب‌وکاری بین شرکت‌ها، پیمانکاران یا تامین‌کنندگان. |
| **Workspace** | فضای کاری | Workspace Sync | `Workspace` | بافت اجرایی محلی یا ابری شامل داده‌های عملیاتی مستاجر (Tenant). |
| **Workspace Sync** | همگام‌سازی فضای کاری | Workspace Sync | `WorkspaceSync` | فرآیند همگام‌سازی بین فضای کاری نود آفلاین و ابر سازمانی. |
| **AI Assistant** | دستیار هوشمند | AI Assistant | `AIAssistant` | سرویس هوش مصنوعی تعبیه‌شده برای ارائه تحلیل‌های پیش‌بینانه و توصیه‌ها. |

# ۵. تفاوت‌های معنایی بر اساس بافت (Context-Specific Variations)

برخی اصطلاحات بر اساس بافت محدودشده معنای مشخصی دارند:

- **Status در بافت دارایی (Asset):** نشان‌دهنده وضعیت عملیاتی (`Active`, `UnderMaintenance`, `Decommissioned`, `Sold`).
- **Status در بافت دستور کار (Work Order):** نشان‌دهنده وضعیت فرآیند کاری (`Draft`, `Approved`, `InProgress`, `Completed`, `Cancelled`).
- **Status در بافت تایر (Tire):** نشان‌دهنده وضعیت تخصیص فیزیکی (`InStock`, `Mounted`, `Scrapped`, `Retreaded`).

# ۶. الگوی‌های نادرست و اصطلاحات ممنوعه (Anti-Patterns & Banned Terminology)

اصطلاحات زیر در سورس‌کد، مستندات و گفتگوها **ممنوع** هستند:

| اصطلاح ممنوعه / منسوخ | جایگزین الزامی | علت ممنوعیت |
|--------------------------|----------------------|----------------|
| `Equipment` / `Machine` | `Asset` | نقض استاندارد زبان همه‌جاحاضر در تمرکز بر `Asset`. |
| `FixTicket` / `Task` | `WorkOrder` | اصطلاح مبهم؛ `WorkOrder` استاندارد دامنه است. |
| `Item` / `Stuff` | `Part` / `Asset` | عمومی و غیرتوصیفی. |
| `UserCompany` | `Organization` | خلط مفهوم هویت کاربر با سلسله‌مراتب سازمان. |
| `DeviceData` | `MeterReading` / `Telemetry` | اصطلاح فنی بدون معنای دقیق کسب‌وکاری. |

# ۷. قواعد ترجمه و بومی‌سازی (Translation & Localization Rules)

۱. **سورس‌کد:** تمامی کلاس‌های C#، اینترفیس‌ها، انام‌ها، پراپرتی‌ها، جداول پایگاه داده و پیام‌های کامیت باید به زبان **انگلیسی** و با شناساگرهای دقیق زبان همه‌جاحاضر نوشته شوند.
۲. **رابط کاربری:** تمامی کامپوننت‌های UI، دیالوگ‌ها، عناوین و گزارش‌های PDF باید از **ترجمه رسمی فارسی** مشخص‌شده در این سند استفاده کنند.
۳. **عدم ترجمه کلمه‌به‌کلمه:** ترجمه‌ها باید از اصطلاحات تخصصی و پذیرفته‌شده صنعت پیروی کنند (مثلاً استفاده از "دستور کار" برای `WorkOrder` نه "سفارش کار").
