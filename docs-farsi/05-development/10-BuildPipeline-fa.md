# ۱. هدف

این سند استراتژی خط لوله یکپارچه‌سازی مداوم (CI) و تحویل مداوم (CD) را برای راهکار **MachineryManagerEnterprise** تعریف می‌کند.

هدف اطمینان از این است که هر تغییر در کد، پیش از ادغام در شاخه‌های اصلی توسعه به صورت خودکار اعتبارسنجی شود.

---

# ۲. اهداف

خط لوله باید:

- راهکار را به صورت خودکار بسازد (Build).
- آزمون‌های خودکار را اجرا کند.
- قوانین معماری را راستی‌آزمایی نماید.
- مشکلات وابستگی را شناسایی کند.
- از ادغام کدهای شکسته و دارای ایراد جلوگیری کند.
- خروجی‌های ساخت تکرارپذیر تولید نماید.

---

# ۳. اصول خط لوله

خط لوله ساخت باید دارای ویژگی‌های زیر باشد:

- خودکار (Automated)
- تکرارپذیر (Repeatable)
- قطعی (Deterministic)
- سریع (Fast)
- شفاف (Transparent)

راستی‌آزمایی دستی ساخت هرگز نباید مورد نیاز باشد.

---

# ۴. استراتژی شاخه‌ها (Branch Strategy)

خط لوله از استراتژی شاخه‌بندی Git پیروی می‌کند:

```text
main
    │
develop
    │
feature/*
```

شاخه‌های مختلف، مراحل مختلف خط لوله را اجرا می‌کنند.

---

# ۵. خط لوله شاخه ویژگی (Feature Branch Pipeline)

هر شاخه ویژگی (Feature Branch) باید موارد زیر را اجرا کند:

- بازیابی پکیج‌ها (Restore packages)
- ساخت راهکار (Build solution)
- تحلیل ایستا (Static analysis)
- آزمون‌های واحد (Unit tests)
- آزمون‌های معماری (Architecture tests)

هیچ استقراری (Deployment) انجام نخواهد شد.

---

# ۶. خط لوله شاخه توسعه (Develop Branch Pipeline)

خط لوله Develop علاوه بر موارد فوق، مراحل زیر را نیز انجام می‌دهد:

- آزمون‌های یکپارچه‌سازی (Integration tests)
- اعتبارسنجی پکیج‌ها (Package validation)
- تولید مصنوعیات (Artifact generation)

---

# ۷. خط لوله شاخه اصلی (Main Branch Pipeline)

خط لوله Main مراحل زیر را انجام می‌دهد:

- ساخت کامل (Full build)
- اجرای کامل مجموعه‌آزمون‌های خودکار
- تولید مصنوعات نسخه نهایی (Release artifact generation)
- برچسب‌گذاری نسخه (Version tagging)
- تایید استقرار (در صورت فعال بودن)

---

# ۸. مراحل خط لوله (Pipeline Stages)

ترتیب اجرای معمول:

```text
بازیابی (Restore)

↓

ساخت (Build)

↓

تحلیل ایستا (Static Analysis)

↓

آزمون‌های معماری (Architecture Tests)

↓

آزمون‌های واحد (Unit Tests)

↓

آزمون‌های یکپارچه‌سازی (Integration Tests)

↓

انتشار مصنوعات (Publish Artifacts)
```

---

# ۹. پیکربندی ساخت (Build Configuration)

پیکربندی پیش‌فرض:

```text
Release
```

ساخت‌های Debug تنها باید در طول توسعه محلی استفاده شوند.

فریم‌ورک هدف (`TargetFramework`) به صورت متمرکز در `Directory.Build.props` تعریف شده است.

فایل‌های پروژه فردی نباید `TargetFramework` را مجدداً تعریف کنند مگر اینکه صریحاً مستند شده باشد.

---

# ۱۰. تحلیل ایستا (Static Analysis)

تحلیل ایستا باید پیش از آزمون‌های خودکار اجرا شود.

ابزارهای پیشنهادی:

- .NET SDK Analyzers
- Roslyn Analyzers

هشدارها تا حد امکان باید به عنوان نقص (Defect) تلقی شوند.

---

# ۱۱. اعتبارسنجی معماری (Architecture Validation)

اعتبارسنجی معماری باید موارد زیر را راستی‌آزمایی کند:

- قوانین وابستگی
- مرزهای لایه‌ها
- قوانین فضای نام

ابزارهای پیشنهادی:

- NetArchTest
- ArchUnitNET

---

# ۱۲. اجرای آزمون‌ها (Test Execution)

خط لوله باید موارد زیر را اجرا کند:

- آزمون‌های واحد
- آزمون‌های یکپارچه‌سازی (در شاخه‌های Develop/Main)
- آزمون‌های معماری

افزوده‌های آتی می‌تواند شامل موارد زیر باشد:

- آزمون‌های UI
- آزمون‌های کارایی و بار
- اسکن‌های امنیتی

---

# ۱۳. مصنوعات ساخت (Artifacts)

ساخت‌های موفقیت‌آمیز باید مصنوعات تکرارپذیر تولید کنند.

مثال‌ها:

- اپلیکیشن منتشرشده
- فایل‌های نمادین (Symbols)
- پکیج‌ها

مصنوعات باید تغییرناپذیر باقی بمانند.

---

# ۱۴. نسخه‌گذاری (Versioning)

نسخه‌گذاری از نسخه‌گذاری معنایی (Semantic Versioning) پیروی می‌کند:

```text
MAJOR.MINOR.PATCH
```

مثال:

```text
1.4.2
```

---

# ۱۵. امنیت (Security)

خط لوله هرگز نباید موارد زیر را افشا کند:

- کلیدها و اسرار (Secrets)
- کلیدهای API
- توکن‌ها
- رشته‌های اتصال

اسرار باید توسط پلتفرم CI مدیریت شوند.

---

# ۱۶. بهبودهای آتی

ارتقاهای آتی خط لوله می‌تواند شامل موارد زیر باشد:

- تولید SBOM (صورت مواد نرم‌افزاری)
- اسکن آسیب‌پذیری‌های وابستگی‌ها
- اسکن ایمیج‌های کانتینر
- استقرار خودکار
- استقرار Blue-Green
- استقرار Canary

---

# ۱۷. انطباق و رعایت

تمامی درخواست‌های ادغام (Pull Requests) باید پیش از تصویب نهایی ادغام، مراحل اجباری خط لوله را با موفقیت پشت سر بگذارند.

کومیت‌های مستقیم روی شاخه‌های حفاظت‌شده ممنوع است.
