# ۱. هدف (Purpose)

این مستند چک‌لیست الزامی را تعریف می‌کند که باید قبل از هر انتشار پروداکشن در MachineryManagerEnterprise تکمیل شود.

هیچ استقرار پروداکشنی تا زمانی که تمام موارد الزامی اعتبارسنجی نشده باشند، نباید آغاز شود.

---

# فلسفه چک‌لیست (Checklist Philosophy)

انتشارهای پروداکشن هرگز نباید به حافظه افراد متکی باشند.

هر استقرار باید از یک چک‌لیست مستندشده استفاده کند.

هیچ موردی از چک‌لیست نباید بدون تایید رسمی نادیده گرفته شود.

---

# ۲. اصول عمومی (General Principles)

چک‌لیست باید دارای ویژگی‌های زیر باشد:

- تکرارپذیر
- قابل ممیزی
- الزامی
- مستقل از افراد

هر چک‌لیست تکمیل‌شده باید همراه با انتشار مربوطه آرشیو شود.

---

# نقش‌های انتشار (Release Roles)

| فعالیت | مسئول |
|----------|-------------|
| کنترل سورس کد | تیم توسعه (Development Team) |
| ساخت | پایپ‌لاین CI |
| تست | تیم تضمین کیفیت (QA Team) |
| دیتابیس | راهبر دیتابیس / دوآپس |
| استقرار | تیم دوآپس (DevOps) |
| اعتبارسنجی | تیم عملیات (Operations) |
| تاییدیه | شورای معماری (Architecture Board) |

---

# ۳. کنترل سورس کد (Source Control)

اعتبارسنجی:

- سورس کد کامیت شده است
- Pull Requestها ادغام (Merge) شده‌اند
- شاخه اصلی (Main Branch) همگام‌سازی شده است
- شاخه انتشار (Release Branch) ایجاد شده است (در صورت نیاز)
- برچسب گیت (Git Tag) آماده شده است

---

# ۴. اعتبارسنجی ساخت (Build Verification)

اعتبارسنجی:

- ساخت با موفقیت انجام شده است
- خطای کامپایل وجود ندارد
- هشدار بحرانی وجود ندارد
- تحلیل ایستای کد با موفقیت به پایان رسیده است
- پایپ‌لاین ساخت با موفقیت اجرا شده است
- مصنوعات با موفقیت تولید شده‌اند

---

# ۵. تست و آزمون (Testing)

اعتبارسنجی:

- تست‌های واحد (Unit Tests) قبول شده‌اند
- تست‌های یکپارچه‌سازی (Integration Tests) قبول شده‌اند
- تست‌های عملکردی (Functional Tests) قبول شده‌اند
- تست‌های معماری (Architecture Tests) قبول شده‌اند
- تست‌های رگرسیون (Regression Tests) قبول شده‌اند

---

# ۶. مستندسازی (Documentation)

اعتبارسنجی:

- مستندات API به‌روزرسانی شده‌اند
- مستندات معماری به‌روزرسانی شده‌اند
- یادداشت‌های انتشار (Release Notes) تکمیل شده‌اند
- اطلاعات نسخه به‌روزرسانی شده است
- مستندات مهاجرت به‌روزرسانی شده‌اند (در صورت نیاز)

---

# ۷. دیتابیس (Database)

اعتبارسنجی:

- Migrationهای دیتابیس بازبینی شده‌اند
- اسکریپت‌های Migration اعتبارسنجی شده‌اند
- دستورالعمل پشتیبان‌گیری (Backup) اعتبارسنجی شده است
- دستورالعمل بازگشت (Rollback) آماده شده است

---

# ۸. امنیت (Security)

اعتبارسنجی:

- اطلاعات حساس (Secrets) پیکربندی شده‌اند
- گواهی‌نامه‌ها معتبر هستند
- احراز هویت اعتبارسنجی شده است
- مجوزدهی اعتبارسنجی شده است
- بازبینی امنیتی تکمیل شده است

---

# ۹. پیکربندی (Configuration)

اعتبارسنجی:

- پیکربندی محیط بازبینی شده است
- رشته‌های اتصال (Connection Strings) اعتبارسنجی شده‌اند
- نقاط پایانی سرویس‌های خارجی اعتبارسنجی شده‌اند
- پیکربندی لاگ‌گیری اعتبارسنجی شده است
- پیکربندی مانیتورینگ اعتبارسنجی شده است

---

# ۱۰. آمادگی استقرار (Deployment Readiness)

اعتبارسنجی:

- پکیج استقرار آماده شده است
- محیط مقصد در دسترس است
- مجوزهای استقرار تایید شده‌اند
- پنجره زمانی نگهداری (Maintenance Window) تایید شده است (در صورت نیاز)

---

# ۱۱. اعتبارسنجی پروداکشن (Production Verification)

پس از استقرار اعتبارسنجی کنید:

- برنامه با موفقیت راه‌اندازی می‌شود
- بررسی سلامت (Health Check) با موفقیت انجام می‌شود
- اتصال به دیتابیس برقرار است
- پردازش‌های پس‌زمینه عملیاتی هستند
- جریان‌های کاری حیاتی کسب‌وکار عملیاتی هستند

---

# ۱۲. آمادگی بازگشت (Rollback Readiness)

اعتبارسنجی:

- نسخه قبلی در دسترس است
- دستورالعمل‌های بازگشت بازبینی شده‌اند
- پشتیبان‌گیری انجام شده است
- رویکرد بازیابی اعتبارسنجی شده است

---

# ۱۳. تاییدیه انتشار (Release Approval)

قبل از استقرار پروداکشن باید تاییدیه‌های زیر وجود داشته باشند:

- تاییدیه فنی
- تاییدیه معماری
- تاییدیه کسب‌وکار (در صورت نیاز)

---

# ۱۴. تکمیل (Completion)

یک انتشار تنها زمانی کامل تلقی می‌شود که:

- استقرار با موفقیت انجام شود
- اعتبارسنجی با موفقیت انجام شود
- مانیتورینگ نشان‌دهنده عملکرد عادی باشد
- مستندات انتشار آرشیو شده باشند

---

# ۱۵. بهبودهای آتی

نسخه‌های آینده ممکن است بخش‌هایی از این چک‌لیست را خودکارسازی کنند از طریق:

- درگاه‌های کیفیت در CI/CD
- اعتبارسنجی زیرساخت
- تست‌های دود (Smoke Tests) خودکار
- اعتبارسنجی سلامت استقرار
- تشخیص خودکار بازگشت

---

# شواهد و مستندات انتشار (Release Evidence)

هر چک‌لیست تکمیل‌شده باید به موارد زیر ارجاع دهد:

- شناسه ساخت (Build ID)
- شناسه پایپ‌لاین (Pipeline ID)
- برچسب گیت (Git Tag)
- یادداشت‌های انتشار (Release Notes)
- لاگ استقرار (Deployment Log)
- گزارش اعتبارسنجی (Verification Report)
