# هدف

این سند فناوری‌های کاندید برای «ارزیابی فناوری مدیریت پیکربندی و اسرار» در MachineryManagerEnterprise را ارزیابی می‌کند.

هدف، دستیابی به یک انتخاب فناوری واحد است که تمام الزامات عملکردی و معماری را برآورده کرده و در عین حال اصول معماری پاک (Clean Architecture) را حفظ نماید.

این ارزیابی فناوری بر پایه اصولی بنا شده است که در TE-0001 (پلتفرم .NET 10) ایجاد شده و با قوانین معماری سازمانی تعریف‌شده در کل راهکار، هم‌راستا است.

# الزامات عملکردی

فناوری انتخاب‌شده باید از موارد زیر پشتیبانی کند:

- قابلیت‌های اصلی سازمانی مورد نیاز MachineryManagerEnterprise؛
- جداسازی مدل‌های دامنه از جزئیات زیرساخت بر اساس معماری پاک؛
- یکپارچه‌سازی بی‌نقص با زمان اجرای .NET 10 و تزریق وابستگی (Dependency Injection)؛
- اجرای با کارایی بالا و عملیات غیرهمگام (Asynchronous).

# الزامات غیرعملکردی

این راهکار باید موارد زیر را فراهم کند:

- قابلیت اطمینان و مقیاس‌پذیری سازمانی؛
- قابلیت نگهداری بلندمدت و خنثی بودن نسبت به ابر (Cloud Neutrality)؛
- عدم وابستگی به فروشنده (Zero vendor lock-in)؛

ارزیابی فناوری — مدیریت پیکربندی و کلیدهای امنیتی (Configuration & Secrets Management)

# خلاصه مدیریتی

این ارزیابی فنی به مقایسه راهکارهای مدیریت پیکربندی و کلیدهای حساس (Secrets) برای سیستم MachineryManagerEnterprise مطابق با ADR-0023 می‌پردازد.

هدف، انتخاب یک الگوی امن و انعطاف‌پذیر است که ذخیره‌سازی، خواندن و بازخوانی داینامیک پیکربندی‌ها را بدون هاردکد کردن کلیدها فراهم کند.

---

# دامنه ارزیابی

این ارزیابی موارد زیر را پوشش می‌دهد:

- مدیریت پیکربندی‌های عمومی (Application Settings)
- مدیریت کلیدهای حساسی مانند Connection Strings و API Keys
- بارگذاری داینامیک و بدون نیاز به Restart (Reload on change)
- یکپارچگی با `IConfiguration` و `IOptions<T>` در .NET 10
- امنیت و رمزنگاری کلیدها در محیط‌های توسعه و عملیات

# ارزیابی کاندیداها و پیشنهاد معماری

پلتفرم MachineryManagerEnterprise استراتژی چندلایه‌ای زیر را انتخاب می‌کند:

1. **الگوی تزریق پیکربندی در کد:** استفاده از الگوی **`IOptions<T>` / `IOptionsMonitor<T>`** دات‌نت در لایه Application.
2. **محیط توسعه (Development):** استفاده از `.NET User Secrets` و `appsettings.Development.json`.
3. **محیط عملیات درون‌سازمانی (On-Premise Production):** استفاده از **Environment Variables** به همراه **HashiCorp Vault** (اختیاری).
4. **محیط عملیات ابری (Cloud Production):** استفاده از سرویس‌های بومی ابری (مانند Azure Key Vault) متصل به `IConfiguration` دات‌نت.
