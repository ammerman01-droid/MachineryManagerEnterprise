# هدف (Purpose)

این ارزیابی فناوری، پشته فناوری‌های ساخت (Build)، بسته‌بندی (Packaging) و استقرار (Deployment) را برای پلتفرم MachineryManagerEnterprise تعیین می‌کند.

فناوری‌های انتخاب‌شده باید موارد زیر را پشتیبانی کنند:

- اتوماسیون ساخت در سطح سازمانی
- یکپارچه‌سازی پیوسته (Continuous Integration - CI)
- تحویل و استقرار پیوسته (Continuous Delivery - CD)
- کانتینری‌سازی (Containerization)
- محیط توسعه محلی استاندارد
- استقرار در بستر ابری (Cloud Deployment)
- استقرار ترکیبی و محلی (Hybrid/On-Premise Deployment)
- یکدستی زیرساخت و محیط‌های اجرایی
- قابلیت نگهداری بلندمدت

# معماری فعلی فرآیند ساخت (Current Build Architecture)

معماری مصوب نیازمند یک خط لوله ساخت یکپارچه است که توانایی پشتیبانی از موارد زیر را داشته باشد:

- ساخت محلی توسط توسعه‌دهنده
- اعتبارسنجی و تست خودکار
- استقرار مبتنی بر کانتینر
- استقرار ابری و ترکیبی

```text
توسعه‌دهنده (Developer)
       │
       ▼
ساخت و کامپایل (Build)
       │
       ▼
آزمون‌های خودکار (Test)
       │
       ▼
بسته‌بندی آرتیفکت‌ها (Package)
       │
       ▼
استقرار (Deploy)
```

---

# نیازمندی‌های کارکردی (Functional Requirements)

پلتفرم ساخت و استقرار باید موارد زیر را پشتیبانی کند:

- ساخت کل سلوشن (Solution Build)
- ساخت افزایشی (Incremental Build)
- اجرای خودکار آزمون‌ها
- بسته‌بندی بسته‌ها و خروجی‌ها (Packaging)
- تولید ایمیج‌های کانتینری Docker
- استقرار در محیط‌های چندگانه (Dev, Staging, Prod)
- اتوماسیون کامل خط لوله (Pipeline Automation)
- مدیریت نسخه‌های منتشرشده

---

# نیازمندی‌های غیرکارکردی (Non-Functional Requirements)

فناوری‌های این حوزه باید ویژگی‌های زیر را دارا باشند:

- قابلیت اطمینان بسیار بالا
- ساخت‌های بازتولیدپذیر (Reproducible Builds)
- پشتیبانی از چند پلتفرم (Windows, Linux, macOS)
- مقیاس‌پذیری سازمانی
- سادگی و شفافیت عملیاتی
- پشتیبانی و ابزارسازی عالی
- سازگاری کامل با فرآیندهای CI/CD

# اصل معماری (Architecture Principle)

مؤلفه ارزیابی‌شده به‌عنوان یک سرویس ایزوله زیرساختی عمل کرده و کاملاً از وابستگی‌های لایه‌ای معماری تمیز و قواعد ایزولاسیون دامنه پیروی می‌نماید.

---

# ۸. ارزیابی .NET 10 SDK (پلتفرم پایه ساخت)

کیت توسعه نرم‌افزار .NET 10 SDK ابزار رسمی، مرجع و یکتای کامپایل، بازیابی پکیج‌ها (Restore)، اجرای تست‌ها، ایجاد بسته‌های NuGet و انتشار خروجی‌ها در سراسر پروژه است.

- **ارزیابی:** **عالی (تصویب شد)**.

---

# ۹. ارزیابی Docker (استانداردسازی بسته‌بندی و اجرا)

داکر (Docker) بستر استاندارد کانتینری‌سازی سرویس‌ها، ایمیج‌های چندمرحله‌ای (Multi-stage builds) و تضمین یکنواختی صددرصدی میان محیط‌های محلی، تست و سرورهای عملیاتی است.

- **ارزیابی:** **عالی (تصویب شد)**.

---

# ۱۰. ارزیابی .NET Aspire (ارکستراسیون توسعه توزیع‌شده)

پلتفرم .NET Aspire برای ارکستراسیون محلی سرویس‌های چندگانه (شامل Backend، SQL Server، Redis، RabbitMQ و Qdrant)، قابلیت‌های مانیتورینگ بلادرنگ OpenTelemetry و مدیریت متمرکز Connection Stringها در محیط توسعه و استقرار محلی استفاده می‌شود.

- **ارزیابی:** **عالی (تصویب شد)**.

---

# ۱۱. ارزیابی GitHub Actions (پلتفرم اصلی CI/CD)

سامانه GitHub Actions به دلیل میزبانی مخزن سورس‌کد در GitHub، یکپارچگی بومی، سادگی تعریف گردش‌کارهای YAML، امنیت فوق‌العاده و اکوسیستم وسیع اکشن‌ها، به‌عنوان **پلتفرم اصلی اتوماسیون CI/CD** تصویب شد.

- **ارزیابی:** **عالی (تصویب شد)**.

---

# ۱۲. ارزیابی Azure DevOps (جایگزین سازمانی پشتیبانی‌شده)

سرویس Azure DevOps به‌عنوان یک پلتفرم کامل ALM سازمانی برای سازمان‌هایی که پیش‌تر بر بستر Azure DevOps استاندارد شده‌اند، پشتیبانی می‌شود اما گزینه پیش‌فرض مخزن عمومی نخواهد بود.

---

# ۱۳. مقایسه جامع پشته ساخت و استقرار (Overall Technology Comparison)

| مسئولیت | فناوری انتخاب‌شده | نقش در معماری |
|---|---|---|
| **پلتفرم ساخت و کامپایل** | **.NET 10 SDK** | ساخت، بازیابی، آزمون و انتشار استاندارد دات‌نت |
| **کانتینری‌سازی** | **Docker** | بسته‌بندی و تحویل ایمیج‌های استاندارد و ایزوله |
| **ارکستراسیون محلی** | **.NET Aspire** | مدیریت سرویس‌های توزیع‌شده و تله‌متری توسعه |
| **اتوماسیون CI/CD** | **GitHub Actions** | اعتبارسنجی کد، اجرای تست‌ها و انتشار خودکار |
| **پلتفرم سازمانی جایگزین** | **Azure DevOps** | گزینه پشتیبانی‌شده برای محیط‌های سازمانی خاص |
