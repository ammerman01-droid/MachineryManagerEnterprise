# هدف (Purpose)

این سند به ارزیابی فناوری مورد استفاده برای مدیریت تکامل ساختار پایگاه داده رابطه‌ای (Database Schema Evolution) در سراسر راهکار MachineryManagerEnterprise می‌پردازد.

اسناد TE-0004 / ADR-0006 فریم‌ورک Entity Framework Core را به‌عنوان ORM پلتفرم تصویب کردند و متذکر شدند که EF Core دارای پشتیبانی بالغ از مایگریشن‌ها است. این ارزیابی این دغدغه خاص را با همان عمق استاندارد مورد بررسی دقیق قرار می‌دهد و به این پرسش صریح پاسخ می‌دهد که آیا **EF Core Migrations** همچنان مکانیزم صحیح تکامل ساختار دیتابیس است، یا اینکه استفاده از یک ابزار اختصاصی و مستقل از ORM (مانند DbUp، Flyway یا Liquibase) راهکار بهتری خواهد بود — به‌ویژه پس از آنکه در سند TE-0024، ابزار Dapper به‌عنوان مکمل فقط-خواندنی EF Core معرفی شد و موضوع «چه کسی مالک و متولی ساختار دیتابیس است» را به یک پرسش معماری صریح تبدیل کرد.

هدف از این ارزیابی عبارت است از:

- تایید رسمی EF Core Migrations به‌عنوان مکانیزم تکامل ساختار دیتابیس پلتفرم، منطبق با ADR-0006 و قاعده حاکمیتی مالکیت ساختار در استراتژی ترکیبی TE-0024؛
- ارزیابی ابزارهای مستقل از ORM شامل DbUp، Flyway و Liquibase؛
- تعیین اینکه آیا هیچ‌یک از این جایگزین‌ها باید جایگزین EF Core Migrations شده یا در کنار آن اجرا شوند یا خیر.

این ارزیابی موارد زیر را پوشش می‌دهد:

- مکانیزم ایجاد، نسخه‌گذاری، اعمال و بازگردانی (Rollback) تغییرات ساختار پایگاه داده رابطه‌ای در تمامی محیط‌ها (توسعه محلی، CI، تست، عملیات)؛
- رابطه میان مایگریشن‌های ساختار و مدل EF Core مورد استفاده در سمت نوشتن و خواندن.

# اصل معماری (Architecture Principle)

تکامل ساختار پایگاه داده باید **دقیقاً یک مالک و متولی واحد (Single Owner)** داشته باشد. ابزار انتخاب‌شده اسکریپت‌های معتبر و ترتیبی تغییرات را تولید و اعمال می‌کند و هیچ ابزار یا فرآیند دستی دیگری مجاز به تغییر ساختار خارج از این مکانیزم نیست.

```text
EF Core Model (مدل موجودیت‌های دامنه - منبع اصلی)
        │
        ▼
Migration Tool (ابزار مایگریشن - تولید و اعمال ترتیبی اسکریپت‌ها)
        │
        ▼
SQL Server Database (ساختار واحد و معتبر پایگاه داده)
        ▲
        │
Dapper (TE-0024) — فقط-خواندنی، هرگز ساختار را تغییر نمی‌دهد
```

# ۵. ارزیابی EF Core Migrations (کاندید مستقر)

## نمای کلی و نقش در معماری

مایگریشن‌های EF Core مستقیماً از کلاس‌های موجودیت و پیکربندی‌های فلوئنت در لایه زیرساخت C# تولید شده و به کمک متدهای `Up()` و `Down()` تغییرات ترتیبی را اعمال می‌نمایند:

```bash
dotnet ef migrations add AddAssetWarrantyExpiryDate --project src/Infrastructure
dotnet ef database update --project src/Infrastructure
```

---

## نقاط قوت معماری

- تولید مستقیم از مدل EF Core، تضمین‌کننده این اصل حیاتی است که ساختار دیتابیس و نگاشت موجودیت‌ها هرگز دچار انحراف (Drift) خاموش نمی‌شوند؛
- مایگریشن‌ها کدهای خوانای C# هستند و در فرآیند Code Review در کنار سایر تغییرات بررسی می‌شوند؛
- وجود متدهای بومی `Up()` و `Down()` برای اعمال و بازگردانی تمیز تغییرات؛
- بدون نیاز به پکیج اضافی یا ران‌تایم خارجی (به‌صورت پیش‌فرض در پشته دات‌نت موجود است)؛
- ادغام بی‌واسطه و ساده با CI/CD و Startup برنامه‌ها.

---

## نقاط ضعف معماری

- کدهای SQL تولیدشده خودکار در سناریوهای بسیار پیچیده (نظیر بک‌فیل‌های داده‌ای سنگین) ممکن است نیاز به بازبینی و شخصی‌سازی دستی داشته باشند؛
- تغییرات غیروابسته به مدل (نظیر ایندکس‌های خاص DBA) همچنان باید در قالب مایگریشن‌های C# ثبت شوند تا یکپارچگی منبع حقیقت حفظ شود.

---

# ۶. ارزیابی DbUp (DbUp Evaluation)

## نمای کلی

ابزار DbUp یک کتابخانه سبک متن‌باز در دات‌نت است که فولدری از فایل‌های ترتیبی `.sql` را خوانده و اسکریپت‌های اجرا‌نشده را در پایگاه داده اعمال کرده و سوابق را در جدول ژورنال نگهداری می‌کند.

---

## نقاط قوت و ضعف

- **نقاط قوت:** کنترل کامل روی کدهای خام SQL، مدل ذهنی بسیار ساده، لایسنس MIT.
- **نقاط ضعف:** گسستگی کامل از مدل EF Core؛ هیچ تضمینی وجود ندارد که تغییر فیلد در C# با اسکریپت SQL هماهنگ بماند و خطر انحراف مدل/ساختار بسیار بالا است؛ فاقد مکانیزم Rollback خودکار؛ ایجاد دو متولی موازی برای دیتابیس.

به دلیل ریسک انحراف ساختار از مدل، این ابزار **رد می‌شود**.

---

# ۷. ارزیابی Flyway (Flyway Evaluation)

## نمای کلی

ابزار Flyway یک سامانه مدیریت نسخه‌های دیتابیس مبتنی بر قرارداد فایل‌های SQL است که به‌طور گسترده در سازمان‌های چندزبانه (Java/Node/...) استفاده می‌شود.

---

## نقاط ضعف و دلایل رد

- ابزاری غیربومی برای دات‌نت (وابسته به ران‌تایم جاوا یا باینری مجزا)، که پیچیدگی غیرضروری به پایپ‌لاین کاملاً دات‌نتی پروژه اضافه می‌کند؛
- گسستگی کامل از مدل EF Core و ایجاد ریسک انحراف ساختار؛
- امکانات پیشرفته Rollback در نسخه پولی (Flyway Teams) قرار دارد که با ADR-0002 در تضاد است.

به این دلایل، Flyway **رد می‌شود**.

---

# ۸. ارزیابی Liquibase (Liquibase Evaluation)

## نمای کلی

ابزار Liquibase ساختار دیتابیس را بر پایه فایل‌های Changelog (به فرمت XML/YAML/JSON/SQL) مدیریت می‌کند و قابلیت‌های دکلراتیو قوی برای Rollback دارد.

---

## نقاط ضعف و دلایل رد

- غیربومی برای دات‌نت (وابسته به جاوا)؛
- پیچیدگی فرمت‌های XML/YAML نسبت به کدهای خالص C#؛
- گسستگی کامل از مدل EF Core؛
- افزودن سربار ابزاری در CI/CD بدون مزیت ملموس.

به این دلایل، Liquibase **رد می‌شود**.
