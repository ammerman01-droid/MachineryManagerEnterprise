# هدف (Purpose)

این سند فناوری‌های کاندید را برای ارزیابی فناوری مستندسازی API و تولید کلاینت (.NET 10) در MachineryManagerEnterprise ارزیابی می‌کند.

هدف، ایجاد یک انتخاب فناوری یکپارچه است که تمامی نیازمندی‌های کارکردی و معماری را ضمن حفظ اصول معماری تمیز (Clean Architecture) برآورده سازد.

مستندات باید همواره به‌صورت خودکار از پیاده‌سازی تولید شوند:

```text
Controllers / Endpoints (کنترلرها و اندپوینت‌ها)

        │

        ▼

OpenAPI Generation (تولید OpenAPI)

        │

        ▼

        │
```

# ۵. ارزیابی OpenAPI (OpenAPI Evaluation)

## نمای کلی (Overview)

مشخصات OpenAPI استاندارد صنعتی و بدون وابستگی به ارائه‌دهنده برای توصیف APIهای RESTful HTTP است که اندپوینت‌ها، متدها، مدل‌های ورودی/خروجی، نیازمندی‌های احراز هویت و کدهای خطا را به فرمتی ماشین‌خوان و انسان‌خوان ارائه می‌دهد.

---

## یکپارچگی بومی با .NET 10

فریم‌ورک ASP.NET Core در .NET 10 تولید مستندات OpenAPI 3.x را به‌صورت توکار و بومی (Native) بدون نیاز به پکیج‌های شخص ثالث برای تولید مشخصات پایه پشتیبانی می‌کند.

---

## نتیجه‌گیری اولیه (Preliminary Conclusion)

مشخصات OpenAPI باید به‌عنوان تنها فرمت مجاز و مرجع قراردادهای API در MachineryManagerEnterprise تعیین شود و تمامی ابزارهای بعدی (مستندات تعاملی، تولید کلاینت، ابزارهای تست و هوش مصنوعی) از آن تغذیه کنند.

---

# ۶. ارزیابی Scalar (Scalar Evaluation)

## نمای کلی (Overview)

واسط کاربری تعاملی مدرن، پرسرعت و بهینه‌ای است که به‌عنوان رابط پیش‌فرض پیشنهادی مایکروسافت در برنامه‌های مدرن ASP.NET Core معرفی شده است.

---

## نقاط قوت معماری (Architectural Strengths)

- رابط کاربری بسیار مدرن، زیبا و ارگونومیک با پشتیبانی تم‌های روشن/تاریک؛
- تجربه کاربری (DX) فوق‌العاده برای توسعه‌دهندگان و کاوش اندپوینت‌ها؛
- رندرینگ پرسرعت و سبک بر پایه استانداردهای OpenAPI 3.x؛
- انطباق و همگامی کامل با جهت‌گیری .NET 10.

---

## نتیجه‌گیری اولیه (Preliminary Conclusion)

واسط Scalar به‌عنوان رابط کاربری تعاملی اصلی مستندات API پلتفرم انتخاب می‌شود.

---

# ۷. ارزیابی سازگاری با Swagger UI (Swagger UI Compatibility Evaluation)

## نمای کلی و وضعیت (Overview and Status)

رابط Swagger UI سال‌ها استاندارد اکوسیستم .NET بوده است. بسیار بالغ و پایدار است، اما ظاهر آن سنتی‌تر و سنگین‌تر از Scalar است. Swagger UI صرفاً جهت حفظ سازگاری با ابزارهای قدیمی یا در صورت وجود الزامات سازمانی خاص پشتیبانی خواهد شد و رابط پیش‌فرض نخواهد بود.

---

# ۸. ارزیابی NSwag (NSwag Evaluation)

## نمای کلی (Overview)

یکی از بالغ‌ترین اکوسیستم‌های ابزاری برای تولید خودکار کدهای کلاینت C# و TypeScript با نوع‌بندی قوی بر اساس مشخصات OpenAPI است.

---

## نقاط قوت معماری (Architectural Strengths)

- ادغام عالی با فرایند بیلد (MSBuild) و پایپ‌لاین‌های CI/CD؛
- تولید کدهای کلاینت تمیز، تست‌پذیر و بدون نیاز به نوشتن دستی wrapperهای HTTP؛
- ایمنی نوع داده در زمان کامپایل برای کلاینت دسکتاپ Avalonia و سایر سرویس‌های .NET؛
- بلوغ و جامعه کاربری بسیار گسترده.

---

## نتیجه‌گیری اولیه (Preliminary Conclusion)

سامانه NSwag فناوری اصلی برای تولید خودکار SDK کلاینت در پلتفرم تعیین می‌شود.

---

# ۹. ارزیابی Kiota (Kiota Evaluation)

## نمای کلی (Overview)

ابزار مدرن مایکروسافت برای تولید SDK کلاینت در چندین زبان برنامه‌نویسی (C#, TypeScript, Python, Go, Java, PHP) بر پایه OpenAPI است.

---

## ارزیابی و نتیجه‌گیری (Assessment and Conclusion)

برای اکوسیستم‌های چندزبانه فوق‌العاده است. اما از آنجا که پلتفرم فعلی MachineryManagerEnterprise عمدتاً متمرکز بر .NET (با کلاینت دسکتاپ Avalonia) است، NSwag انتخاب اصلی بوده و Kiota به‌عنوان یک گزینه اختیاری برای آینده در صورت نیاز به انتشار SDK عمومی چندزبانه در نظر گرفته می‌شود.

---

# ۱۰. مقایسه جامع فناوری‌ها (Overall Technology Comparison)

# ۱۱. پیشنهاد نهایی (Final Recommendation)

## پشته اصلی فناوری‌ها (Core Technology Stack)

| مسئولیت | فناوری انتخاب‌شده | دلیل انتخاب |
|---|---|---|
| استاندارد قرارداد API | OpenAPI 3.x | استاندارد صنعتی، بی‌طرف، پایه اکوسیستم |
| مستندات تعاملی | Scalar | رابط کاربری مدرن، هماهنگ با .NET 10، تجربه کاربری عالی |
| تولید SDK کلاینت | NSwag | بالغ، پشتیبانی بی‌نظیر از C#، اتوماسیون در بیلد |
| تولید کلاینت چندزبانه | Kiota | گزینه اختیاری آتی برای انتشار SDK چندزبانه |
| واسط قدیمی | Swagger UI | صرفاً جهت سازگاری در صورت نیاز |

# تصمیم نهایی (Final Decision)

هیئت بازبینی معماری پشته فناوری زیر را به تصویب رساند:
- سند OpenAPI تنها مرجع قراردادهای API است.
- رابط Scalar به‌عنوان واسط کاربری پیش‌فرض مستندات تعاملی تعیین شد.
- ابزار NSwag برای تولید خودکار کلاینت‌های C# و TypeScript در پایپ‌لاین بیلد انتخاب شد.
- ابزار Kiota برای سناریوهای چندزبانه آتی تایید شد.
- نوشتن دستی کلاینت‌های HTTP یا مستندسازی دستی اندپوینت‌ها ممنوع است.
