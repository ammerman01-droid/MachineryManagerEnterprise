# 5. ارزیابی OpenAPI (OpenAPI Evaluation)

## نمای کلی (Overview)

استاندارد OpenAPI مشخصه استاندارد صنعتی برای توصیف APIهای مبتنی بر HTTP است.

این استاندارد موارد زیر را تعریف می‌نماید:

- اندپوینت‌ها؛
- پارامترها؛
- بدنه درخواست‌ها؛
- پاسخ‌ها؛
- احراز هویت؛
- طرح‌واره‌ها (schemas)؛
- متادیتا.

استاندارد OpenAPI یک فریم‌ورک رابط کاربری نیست.

این مشخصه، قراردادی است که توسط ابزارهای مستندسازی، ابزارهای تست، درگاه‌ها (gateways) و تولیدکنندگان SDK مصرف می‌شود.

# 5. ارزیابی OpenAPI (OpenAPI Evaluation)

## نمای کلی (Overview)

استاندارد OpenAPI (که قبلاً با نام Swagger Specification شناخته می‌شد) استاندارد صنعتی برای توصیف APIهای مبتنی بر RESTful HTTP است.

این استاندارد یک قرارداد ماشین‌خوان فراهم می‌آورد که موارد زیر را به طور کامل توصیف می‌کند:

- اندپوینت‌ها؛
- متدهای HTTP؛
- مدل‌های درخواست؛
- مدل‌های پاسخ؛
- نیازمندی‌های احراز هویت؛
- قراردادهای خطا؛
- متادیتا.

سند OpenAPI به توصیف رسمی و استاندارد (canonical description) از سطح عمومی API تبدیل می‌شود.

# 6. ارزیابی Scalar (Scalar Evaluation)

## نمای کلی (Overview)

رابط کاربری Scalar رابط کاربری مدرن و تعاملی مستندسازی API است که به عنوان تجربه مستندسازی پیشنهادی برای برنامه‌های مدرن ASP.NET معرفی شده است.

برخلاف Swagger UI که در درجه اول بر رندر مشخصات OpenAPI تمرکز دارد، Scalar بر موارد زیر تاکید می‌ورزد:

- تجربه توسعه‌دهنده؛
- خوانایی؛
- رابط کاربری مدرن؛
- رندر با کارایی بالا؛
- جریان کاری اولویت‌دار با OpenAPI (OpenAPI-first).

با آغاز انتشار نسخه‌های مدرن ASP.NET، اسکالر (Scalar) در حال تبدیل شدن به رابط تعاملی مستندسازی برتر و ارجح است.

در MachineryManagerEnterprise، رابط Scalar به عنوان رابط اصلی کاوش API ارزیابی می‌شود.

با این حال، MachineryManagerEnterprise در حال حاضر یک اکوسیستم عمدتاً مبتنی بر .NET را همراه با یک کلاینت دسکتاپ Avalonia و مصرف‌کنندگان سرویس‌های داخلی هدف قرار داده است.

به همین دلیل:

- **ابزار NSwag باید فناوری اصلی تولید کلاینت باشد.**
- **ابزار Kiota ممکن است در آینده در صورتی که توزیع عمومی SDKهای چندزبانه به یک نیازمندی پروژه تبدیل شود، معرفی گردد.**
