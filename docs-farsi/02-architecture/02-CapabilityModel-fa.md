# هدف

این سند، «مدل قابلیت‌های کسب‌وکار» (Business Capability Model) پلتفرم MachineryManagerEnterprise را تعریف می‌کند.

یک قابلیت، توصیف می‌کند که **کسب‌وکار قادر به انجام چه کاری است**، فارغ از نحوه پیاده‌سازی فنی آن.

مدل قابلیت‌ها، زیربنای موارد زیر است:

- طراحی دامنه-محور (Domain Driven Design)
- مرزبندی ماژول‌ها
- ساختار ناوبری
- سیستم مجوزها
- طراحی API
- گزارش‌گیری
- استخراج میکروسرویس‌های آتی

این سند به‌طور آگاهانه بر قابلیت‌های کسب‌وکار متمرکز است و نه مؤلفه‌های نرم‌افزاری.

---

# اصل بنیادین

این پلتفرم بر پایه مفهوم **دارایی (Asset)** طراحی شده است، نه **ماشین (Machine)**.

هر شیء قابل نگهداری که دارای چرخه حیات مستقل باشد، یک «دارایی» محسوب می‌شود.

نمونه‌هایی از آن عبارتند از:

- ماشین‌آلات سنگین
- کامیون‌ها
- لیفتراک‌ها
- موتورها
- ادوات جانبی
- ژنراتورها
- کمپرسورها
- انواع تجهیزات آتی

این اصل، توسعه‌پذیری بلندمدت را تضمین می‌کند.

# اصول طراحی قابلیت‌ها

هر قابلیت باید:

- نماینده یک مسئولیت تجاری باشد؛
- از تکنولوژی پیاده‌سازی مستقل بماند؛
- دارای مالکیت مشخص باشد؛
- از اصطلاحات تجاری شفاف استفاده کند؛
- تا حد امکان به‌طور مستقل تکامل یابد.

قابلیت‌ها هرگز نباید بر اساس جداول پایگاه‌داده یا صفحات رابط کاربری (UI) تعریف شوند.

---

# روابط بین قابلیت‌ها

قابلیت‌ها با یکدیگر همکاری می‌کنند اما همچنان به‌صورت سست‌جفت (Loosely Coupled) باقی می‌مانند.

مثال‌ها:

- «نگهداری» (Maintenance) از داده‌های «کنتور» (Meter) استفاده می‌کند.
- «پیش‌بینی» (Forecasting) از داده‌های تاریخی «نگهداری» و «سوخت» استفاده می‌کند.
- «اعلان‌ها» (Notifications) از داده‌های «نگهداری»، «اسناد» و «گارانتی» استفاده می‌کنند.
- «مدیریت مالی» (Financial Management) از اطلاعات «خرید» و «نگهداری» استفاده می‌کند.
- «گزارش‌گیری» (Reporting) از داده‌های تمام قابلیت‌های تجاری استفاده می‌کند.

تمامی قابلیت‌های تجاری به‌گونه‌ای طراحی شده‌اند که مستقل از توپولوژی استقرار عمل کنند.

عملیات تجاری ممکن است در محیط‌های کاری (Workspaces) «سازمانی»، «پروژه‌ای» یا «کاربری» اجرا شوند، بدون اینکه قوانین تجاری (Business Rules) تغییر کنند.

همگام‌سازی توزیع‌شده، تغییرات تجاری تأییدشده را بین محیط‌های کاری منتشر می‌کند، در حالی که ثبات تجاری حفظ می‌شود.

این رفتار توسط ADR-0012 (معماری محیط کاری توزیع‌شده) تعریف شده است.

# گسترش آتی

مدل قابلیت به‌صورت تعمدی از گسترش‌های آتی پشتیبانی می‌کند، از جمله:

- محیط‌های چند-شرکتی
- مدیریت ناوگان
- یکپارچه‌سازی اینترنت اشیاء (IoT)
- تلماتیک
- نگهداری پیش‌بینانه
- تشخیص با کمک هوش مصنوعی
- اپلیکیشن‌های موبایل
- همگام‌سازی محیط کاری توزیع‌شده
- اجرای پروژه با اولویت آفلاین (Offline-first)
- همگام‌سازی دوطرفه بین محیط‌های کاری سازمان، پروژه و کاربر
- یکپارچه‌سازی با ERP خارجی
- یکپارچه‌سازی GIS
- بازرسی‌های دیجیتال

# نگاشت ماژول‌ها

انتظار می‌رود مدل قابلیت به ماژول‌های نرم‌افزاری تبدیل شود.

مثال‌ها:

| قابلیت | ماژول آتی |
|------------|---------------|
| سازمان | Organization |
| مدیریت دارایی | Asset |
| مدیریت قطعات | Components |
| نگهداری | Maintenance |
| موجودی | Inventory |
| امور مالی | Finance |
| اسناد | Documents |
| دانش | Knowledge |
| پیش‌بینی | Forecasting |
| گزارش‌گیری | Reporting |

مرزهای ماژول‌ها در طول مدل‌سازی دامنه (Domain Modeling) دقیق‌تر خواهند شد.
