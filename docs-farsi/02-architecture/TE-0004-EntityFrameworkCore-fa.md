# هدف (Purpose)

این سند فناوری‌های کاندید را برای ارزیابی فناوری EntityFrameworkCore در NET 10. در MachineryManagerEnterprise ارزیابی می‌کند.

هدف، ایجاد یک انتخاب فناوری یکپارچه است که تمامی نیازمندی‌های کارکردی و معماری را ضمن حفظ اصول معماری تمیز (Clean Architecture) برآورده سازد.

# نیازمندی‌های کارکردی (Functional Requirements)

فناوری انتخاب‌شده باید از موارد زیر پشتیبانی کند:

- قابلیت‌های سازمانی هسته مورد نیاز در MachineryManagerEnterprise؛
- جداسازی مدل‌های دامنه از جزئیات زیرساخت بر اساس معماری تمیز؛
- یکپارچگی روان با زمان اجرای NET 10. و تزریق وابستگی (Dependency Injection)؛
- عملکرد اجرایی بالا و عملیات ناهمگام (Asynchronous).

# خلاصه اجرایی (Executive Summary)

این سند فریم‌ورک **Entity Framework Core** را به‌عنوان نگاشت‌کننده شیء-رابطه‌ای (ORM) اصلی برای راهکار MachineryManagerEnterprise ارزیابی می‌کند.

فریم‌ورک Entity Framework Core به این دلیل انتخاب شده است که یکپارچگی عالی با NET 10.، ابزارهای قدرتمند، پشتیبانی بالغ از مایگریشن‌ها، قابلیت نگهداری بالا و اکوسیستم متن‌باز فعالی ارائه می‌دهد و در عین حال برای برنامه‌های سازمانی به‌اندازه کافی منعطف باقی می‌ماند.

---

# مزایا (Advantages)

- یکپارچگی بومی با NET.
- پشتیبانی عالی از LINQ
- ردیابی خودکار تغییرات (Automatic change tracking)
- فریم‌ورک مایگریشن بالغ
- استقلال از ارائه‌دهنده دیتابیس
- ابزارهای عالی در Visual Studio
- مستندات قوی
- جامعه کاربری بزرگ
- پشتیبانی دست اول مایکروسافت

---

# معایب (Disadvantages)

- در کوئری‌های ساده اندکی کندتر از میکرو ORMها عمل می‌کند.
- عبارات پیچیده LINQ در صورت عدم بازبینی ممکن است SQL ناکارآمد تولید کنند.

---

# ریسک‌ها (Risks)

ریسک‌های بالقوه عبارتند از:

- افت عملکرد ناشی از طراحی نادرست کوئری‌ها.
- بارگذاری زودهنگام افراطی (Excessive eager loading).
- مشکلات کوئری‌های N+1.

این ریسک‌ها می‌توانند از طریق بازبینی کد (Code Review) و آزمون‌های عملکردی کاهش یابند.

---

# ملاحظات عملکردی (Performance Considerations)

فریم‌ورک Entity Framework Core عملکرد بسیار خوبی برای برنامه‌های سازمانی ارائه می‌دهد.

شیوه‌های توصیه‌شده:

- استفاده از پروژکشن‌ها (Projections).
- غیرفعال کردن ردیابی (Tracking) در زمان‌های مناسب (AsNoTracking).
- استفاده از کوئری‌های کامپایل‌شده در صورت توجیه‌پذیر بودن.
- اجتناب از Includeهای غیرضروری.
- بازبینی SQL تولیدشده.

---

# ملاحظات امنیتی (Security Considerations)

فریم‌ورک Entity Framework Core موارد زیر را فراهم می‌آورد:

- تولید SQL پارامتری‌شده
- محافظت در برابر تزریق کد SQL (SQL Injection protection)
- مدل امن ارائه‌دهندگان پایگاه داده

امنیت در نهایت به طراحی برنامه بستگی دارد.

# تاثیر معماری (Architecture Impact)

فریم‌ورک Entity Framework Core **تنها درون لایه زیرساخت (Infrastructure)** قرار خواهد گرفت.

لایه‌های زیر هرگز نباید پکیج‌های EF Core را رفرنس دهند:

- SharedKernel
- Domain
- Application
- Presentation

مخازن داده (Repositories) انتزاع‌های تعریف‌شده توسط لایه کاربرد (Application) را پیاده‌سازی می‌کنند.

---

# پیچیدگی مهاجرت (Migration Complexity)

**درجه سختی:** متوسط (Medium)

فریم‌ورک Entity Framework Core قابل جایگزینی است در صورتی که:

- اینترفیس‌های مخزن (Repository interfaces) پایدار باقی بمانند.
- منطق کسب‌وکار بدون وابستگی به مکانیزم ذخیره‌سازی داده باقی بماند.
- لایه زیرساخت کاملاً ایزوله بماند.

تلاش لازم برای مهاجرت تحت معماری فعلی قابل مدیریت ارزیابی می‌شود.

# گزینه‌های جایگزین بررسی‌شده (Alternatives Considered)

## کتابخانه Dapper
عملکرد عالی دارد.

رد شد زیرا:
- نگاشت دستی هزینه‌های نگهداری را افزایش می‌دهد.
- فاقد فریم‌ورک مایگریشن است.
- بهره‌وری کمتری برای دامنه‌های پیچیده دارد.

---

## فریم‌ورک NHibernate
یک ORM بسیار بالغ است.

رد شد زیرا:
- منحنی یادگیری بالاتری دارد.
- اکوسیستم کوچک‌تری در NET. مدرن دارد.
- همسویی کمتری با پشته فناوری فعلی مایکروسافت دارد.

---

## کتابخانه Linq2Db
عملکرد عالی دارد.

رد شد زیرا:
- جامعه کاربری کوچک‌تری دارد.
- اکوسیستم مایگریشن محدودی دارد.
