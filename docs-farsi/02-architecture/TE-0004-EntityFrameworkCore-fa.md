# هدف

این سند به ارزیابی فناوری‌های کاندید برای ارزیابی فناوری EntityFrameworkCore (دات‌نت 10) در MachineryManagerEnterprise می‌پردازد.

هدف، ایجاد یک انتخاب فناوری واحد است که ضمن حفظ اصول Clean Architecture، تمامی نیازمندی‌های عملکردی و معماری را برآورده سازد.

# نیازمندی‌های عملکردی

فناوری انتخاب‌شده باید از موارد زیر پشتیبانی کند:

- قابلیت‌های اصلی سازمانی مورد نیاز MachineryManagerEnterprise؛
- جداسازی مدل‌های دامنه از جزئیات زیرساختی مطابق با Clean Architecture؛
- یکپارچگی بی‌نقص با زمان اجرای .NET 10 و تزریق وابستگی (Dependency Injection)؛
- اجرای با کارایی بالا و عملیات غیرهمگام (Asynchronous).

---

# نیازمندی‌های غیرعملکردی

راهکار باید موارد زیر را فراهم کند:

- قابلیت اطمینان و مقیاس‌پذیری سازمانی؛
- قابلیت نگهداری بلندمدت و بی‌طرفی نسبت به ابر (Cloud Neutrality)؛
- عدم وابستگی به تامین‌کننده (Vendor Lock-in)؛
- تجربه توسعه‌دهنده بهینه و قابلیت تست‌پذیری.

---

# خلاصه مدیریتی

این سند به ارزیابی **Entity Framework Core** به عنوان نگاشت‌گر شیء-رابطه‌ای (ORM) اصلی برای راهکار MachineryManagerEnterprise می‌پردازد.

Entity Framework Core به این دلیل انتخاب شد که یکپارچگی عالی با .NET 10، ابزارهای قدرتمند، پشتیبانی بالغ از مهاجرت‌های پایگاه داده، قابلیت نگهداری بالا و اکوسیستم متن‌باز فعالی را ارائه می‌دهد، در حالی که برای کاربردهای سازمانی به اندازه کافی انعطاف‌پذیر باقی می‌ماند.

---

# بیان مسئله

پروژه به یک ORM نیاز دارد که موارد زیر را فراهم کند:

- بهره‌وری بالا
- یکپارچگی قدرتمند با .NET
- مهاجرت‌های (Migrations) قابل اطمینان
- پشتیبانی از LINQ
- استقلال از تامین‌کننده (Provider Independence)
- ابزارهای عالی
- قابلیت نگهداری بلندمدت

# مزایا

- یکپارچگی بومی با .NET
- پشتیبانی عالی از LINQ
- ردیابی خودکار تغییرات (Change Tracking)
- چارچوب مهاجرت (Migration) بالغ
- استقلال از ارائه‌دهنده (Provider)
- ابزارهای عالی در Visual Studio
- مستندات قوی
- جامعه کاربری بزرگ
- پشتیبانی رسمی از طرف مایکروسافت

---

# معایب

- سرعت کمی پایین‌تر نسبت به micro ORMها برای کوئری‌های ساده.
- عبارات پیچیده LINQ در صورت عدم بازبینی، ممکن است SQL ناکارآمد تولید کنند.

---

# ریسک‌ها

ریسک‌های احتمالی شامل موارد زیر است:

- افت عملکرد ناشی از طراحی نادرست کوئری‌ها.
- بارگذاری مشتاقانه (Eager loading) بیش از حد.
- مشکلات کوئری N+1.

این ریسک‌ها از طریق بازبینی کد (Code Reviews) و تست‌های عملکرد قابل کاهش هستند.

# ملاحظات عملکرد

Entity Framework Core عملکرد بسیار خوبی برای برنامه‌های سازمانی ارائه می‌دهد.

شیوه‌های پیشنهادی:

- استفاده از Projectionها.
- غیرفعال کردن ردیابی (Tracking) در صورت لزوم.
- استفاده از کوئری‌های کامپایل‌شده (Compiled Queries) در صورت توجیه‌پذیری.
- اجتناب از Includeهای غیرضروری.
- بازبینی SQL تولید شده.

# تأثیر بر معماری

Entity Framework Core باید **فقط در لایه Infrastructure** قرار گیرد.

لایه‌های زیر هرگز نباید به بسته‌های EF Core ارجاع داشته باشند:

- SharedKernel
- Domain
- Application
- Presentation

مخازن (Repositories) انتزاع‌هایی را که توسط لایه Application تعریف شده‌اند، در معرض دید قرار می‌دهند.

---

# پیچیدگی مهاجرت

**سختی:** متوسط

Entity Framework Core در صورتی قابل جایگزینی است که:

- اینترفیس‌های Repository پایدار باقی بمانند.
- منطق تجاری (Business logic) نسبت به نحوه ماندگاری داده‌ها (Persistence) خنثی باقی بماند.
- لایه Infrastructure مجزا باقی بماند.

تلاش برای مهاجرت در معماری فعلی قابل مدیریت ارزیابی می‌شود.

---

# جایگزین‌های بررسی شده

## Dapper

عملکرد عالی.

رد شد به این دلیل که:

- نگاشت دستی (Manual mapping) باعث افزایش هزینه نگهداری می‌شود.
- فاقد چارچوب مهاجرت است.
- برای دامنه‌های پیچیده، بهره‌وری کمتری دارد.

---

## NHibernate

یک ORM بسیار بالغ.

رد شد به این دلیل که:

- منحنی یادگیری بالاتری دارد.
- اکوسیستم کوچک‌تری در دنیای مدرن .NET دارد.
- همسویی کمتری با پشته (Stack) فعلی مایکروسافت دارد.

---

## Linq2Db

عملکرد عالی.

رد شد به این دلیل که:

- جامعه کاربری کوچک‌تری دارد.
- اکوسیستم مهاجرت محدودی دارد.
