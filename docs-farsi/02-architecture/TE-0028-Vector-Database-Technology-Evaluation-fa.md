# هدف (Purpose)

این ارزیابی فناوری به تعیین مناسب‌ترین فناوری **پایگاه داده برداری (Vector Database)** برای پلتفرم MachineryManagerEnterprise می‌پردازد.

فناوری انتخاب‌شده، زیرساخت بازیابی معنایی (Semantic Retrieval) مورد نیاز برای قابلیت‌های آتی هوش مصنوعی پلتفرم را فراهم می‌آورد و در عین حال معماری مصوب پایداری داده‌ها را بدون تغییر حفظ می‌کند.

فناوری منتخب باید موارد زیر را پشتیبانی کند:

- جستجوی معنایی (Semantic Search)
- تولید تقویت‌شده با بازیابی (Retrieval-Augmented Generation - RAG)
- جستجوی دانش سازمانی (Enterprise Knowledge Search)
- دستیار هوش مصنوعی (AI Assistant)
- ذخیره‌سازی امبدینگ‌ها (Embedding Storage)
- جستجوی شباهت (Similarity Search)
- جستجوی ترکیبی (Hybrid Search)

این سند صرفاً فناوری پایگاه داده برداری را مورد ارزیابی قرار می‌دهد. پایگاه داده رابطه‌ای عملیاتی سامانه پیش‌تر به‌صورت جداگانه تصویب شده است.

---

# دامنه ارزیابی (Evaluation Scope)

این ارزیابی فناوری **صرفاً انتخاب فناوری** را مورد بررسی قرار می‌دهد.

هدف این سند مقایسه فناوری‌های کاندید پایگاه داده برداری در برابر نیازمندی‌های معماری مصوب MachineryManagerEnterprise است.

این سند موارد زیر را تعریف **نمی‌کند**:

- جزئیات پیاده‌سازی؛
- استراتژی ایندکس‌گذاری؛
- مکانیزم همگام‌سازی؛
- چرخه حیات امبدینگ‌ها؛
- ارکستراسیون هوش مصنوعی؛
- معماری بازیابی تقویت‌شده با تولید (RAG).

این تصمیمات به‌صورت جداگانه در سوابق تصمیمات معماری (ADR) مربوطه مستند خواهند شد.

# معماری فعلی (Current Architecture)

معماری مصوب پایداری داده‌ها به شرح زیر است:

```text
                Application (لایه کاربرد)

                      │
                      ▼

           Microsoft SQL Server
           (پایگاه داده عملیاتی - System of Record)

                      │
             داده‌های ساخت‌یافته تجاری
                      │
────────────────────────────────────────
زیرساخت آینده هوش مصنوعی:

             تولید امبدینگ
                   │
                   ▼
       پایگاه داده برداری منتخب
                   │
            جستجوی شباهت
                   │
             لایه بازیابی
                   │
                   ▼
         مدل زبانی بزرگ (LLM)
```

پایگاه داده رابطه‌ای همچنان **تنها منبع رسمی حقیقت (System of Record)** باقی می‌ماند و پایگاه داده برداری صرفاً بازنمایی‌های معنایی را نگهداری می‌کند.

# ۸. ارزیابی Qdrant (کاندید برگزیده)

## نمای کلی

پایگاه داده Qdrant یک دیتابیس برداری متن‌باز مبتنی بر زبان Rust است که اختصاصاً برای جستجوی معنایی و کاربردهای هوش مصنوعی طراحی شده است. Qdrant برای الگوریتم HNSW بهینه‌سازی شده و قابلیت‌های فوق‌العاده‌ای در فیلترگذاری متادیتا (Payload Filtering) هم‌زمان با جستجوی برداری ارائه می‌دهد.

```text
                 Application Layer
                        │
                        ▼
               Embedding Generation
                        │
                        ▼
                     Qdrant
        ┌──────────────────────────┐
        │      Vector Storage       │
        │      Metadata Store       │
        │      ANN Indexes (HNSW)   │
        └──────────────────────────┘
                        │
                        ▼
               Semantic Retrieval
```

---

## نقاط قوت معماری

- طراحی تخصصی برای جستجوی معنایی و RAG؛
- ایندکس‌گذاری بومی ANN و HNSW بسیار سریع؛
- فیلترگذاری غنی متادیتا روی Payload بدون کاهش دقت؛
- ردپای عملیاتی بسیار کم و اجرای ساده با یک ایمیج کانتینری Docker یا کلاستر Kubernetes؛
- متن‌باز (Apache 2.0) و انطباق کامل با ADR-0002؛
- استقرار کامل در محیط‌های محلی و ایزوله آفلاین (On-Premise/Air-gapped)؛
- یکپارچگی عالی با اکوسیستم‌های Semantic Kernel، LangChain و LlamaIndex.

# ۹. ارزیابی Milvus (Milvus Evaluation)

## نمای کلی و دلایل عدم انتخاب

میلوس (Milvus) یک پایگاه داده برداری توزیع‌شده برای مقیاس‌های بسیار عظیم (میلیاردها بردار) است. این سامانه از چندین نوع نود مجزا (Query Nodes, Data Nodes, Index Nodes, Coordinators) تشکیل شده است.

- **نقاط قوت:** مقیاس‌پذیری خارق‌العاده برای سامانه‌های غول‌پیکر داده، پشتیبانی از شتاب‌دهنده GPU؛
- **نقاط ضعف:** پیچیدگی بسیار زیاد عملیاتی؛ نیازمند کلاسترینگ چندبخشی و منابع سنگین سروری که برای نیازهای پلتفرم MachineryManagerEnterprise فراتر از حد نیاز بوده و سربار بیهوده ایجاد می‌کند.

به دلیل پیچیدگی عملیاتی نامتناسب، Milvus **انتخاب نمی‌شود**.

---

# ۱۰. ارزیابی Pinecone (Pinecone Evaluation)

## نمای کلی و دلایل عدم انتخاب

پاین‌کون (Pinecone) یک سرویس ابری کاملاً مدیریت‌شده (SaaS) است که بدون نیاز به مدیریت سرور، مقیاس‌پذیری خودکار را ارائه می‌دهد.

- **نقاط قوت:** صفر درصد زحمت عملیاتی، پرفورمنس بسیار بالا، مقیاس‌پذیری خودکار ابری؛
- **نقاط ضعف:** سرویس کاملاً انحصاری و ابری؛ عدم امکان استقرار محلی (On-premise) یا ایزوله (Air-gapped)؛ وابستگی شدید به ارائه‌دهنده (Vendor Lock-in) و هزینه‌های متغیر دلاری که با اصول معماری پلتفرم و ADR-0002 در تضاد است.

به دلیل عدم بی‌طرفی ابری و عدم پشتیبانی از استقرار محلی، Pinecone **انتخاب نمی‌شود**.

# ۱۲. مقایسه سازگاری با هوش مصنوعی (AI Compatibility Comparison)

تمام پایگاه‌های برداری کاندید قابلیت اتصال به مدل‌های امبدینگ استاندارد (مانند Azure OpenAI، Ollama، HuggingFace، Sentence Transformers) و چارچوب‌های ارکستراسیون (مانند Microsoft Semantic Kernel و LangChain) را دارند. پایگاه Qdrant به دلیل پشتیبانی فوق‌العاده از ترکیب جستجوی معنایی و فیلترهای سازمانی (مانند تفکیک بر اساس شناسه سازمان، نوع سند و دسته‌بندی تجهیزات) بالاترین امتیاز سازگاری را کسب می‌کند.
