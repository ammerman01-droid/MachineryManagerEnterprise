# خلاصه اجرایی (Executive Summary)

این ارزیابی فنی فناوری‌های پایگاه داده تعبیه‌شده (Embedded Database) مناسب برای پیاده‌سازی معماری داده ورک‌اسپیس تعریف‌شده در ADR-0014 را مقایسه می‌کند.

هدف، شناسایی یک موتور ذخیره‌سازی است که از عملکرد اولویت با آفلاین (Offline-first)، قابلیت نگهداری بلندمدت، استقرار چندسکویی و یکپارچگی روان با پشته فناوری مصوب NET. پشتیبانی نماید.

این ارزیابی به‌جای تمرکز صرف بر فناوری، ساختارمحور و مبتنی بر معماری است.

# کاندید ۱ — SQLite

## نمای کلی (Overview)

پایگاه داده SQLite یک موتور پایگاه داده رابطه‌ای تعبیه‌شده سبک‌وزن است که به‌صورت یک کتابخانه بدون سرور (Serverless) پیاده‌سازی شده است.

این فناوری یکی از گسترده‌ترین پایگاه‌های داده تعبیه‌شده مستقر در جهان است و عملاً بر روی تمامی سیستم‌های عامل مدرن در دسترس است.

پایگاه داده SQLite داده‌ها را درون یک فایل دیتابیس منفرد و قابل حمل ذخیره می‌کند و تضمین‌های کامل تراکنشی ACID را فراهم می‌سازد.

---

## مزایا (Advantages)

- فوق‌العاده بالغ و پایدار.
- لایسنس مالکیت عمومی (Public Domain).
- در دسترس بودن چندسکویی عالی.
- پشتیبانی بومی در سراسر Windows، Android و iOS.
- عملکرد عالی برای بارهای کاری تعبیه‌شده.
- تراکنش‌های منطبق بر اصول ACID.
- ردپای استقرار بسیار کوچک.
- یکپارچگی عالی با اکوسیستم NET.
- جامعه کاربری بزرگ و مستندات جامع.
- پذیرش سازمانی اثبات‌شده.
- عدم نیاز به سرور پایگاه داده مجزا.
- پشتیبانی عالی از پشتیبان‌گیری و بازیابی (Backup and Recovery).

---

## معایب (Disadvantages)

- معماری تک‌نویسنده (Single-writer).
- پشتیبانی محدود از بارهای کاری با همزمانی نوشتن بسیار بالا.
- فاقد مدل ذخیره‌سازی داده‌های سندی به‌صورت درون‌ساخت.
- مقیاس‌پذیری افقی قابل اعمال نیست.

این محدودیت‌ها قابل قبول هستند زیرا پایگاه‌های داده ورک‌اسپیس برای عملیات محلی تعبیه‌شده طراحی شده‌اند نه بارهای کاری سروری با همزمانی بسیار بالا.

# کاندید ۲ — LiteDB

## نمای کلی (Overview)

پایگاه داده LiteDB یک پایگاه داده سندی NoSQL تعبیه‌شده است که کاملاً در NET. پیاده‌سازی شده است.

این دیتابیس اسناد BSON را درون یک فایل دیتابیس واحد ذخیره می‌کند و به هیچ سرور خارجی نیاز ندارد.

پایگاه داده LiteDB بر سادگی برای توسعه‌دهنده و یکپارچگی بومی با NET. تاکید دارد.

---

## مزایا (Advantages)

- پیاده‌سازی خالص در NET.
- مجوز MIT.
- استقرار بسیار آسان.
- پایگاه داده تک‌فایلی.
- ماندگاری بومی اشیاء (Native object persistence).
- یکپارچگی قوی با #C.
- ردپای کم.
- عملکرد خوب برای بارهای کاری سندمحور.
- استراتژی پشتیبان‌گیری ساده.

---

## معایب (Disadvantages)

- اکوسیستم کوچک‌تر در مقایسه با SQLite.
- پذیرش سازمانی کمتر.
- فاقد زبان کوئری SQL.
- اکوسیستم ابزارهای محدود.
- ابزارهای تشخیصی کمتر.
- سابقه پشتیبانی بلندمدت با بلوغ کمتر.

- مدل داده شیء‌گرای بومی.
- ماندگاری اشیاء بسیار کارآمد.
- در دسترس بودن چندسکویی.
- تجربه توسعه‌دهندگی قوی در موبایل.

- معماری مدرن.

---

## معایب (Disadvantages)

- پایگاه داده شیء‌گرا به جای پایگاه داده رابطه‌ای.

- پیچیدگی معماری اضافه برای سازمان‌هایی که از MongoDB استفاده نمی‌کنند.

با این حال، جفت‌شدگی محکم‌تر آن با اکوسیستم MongoDB در مقایسه با SQLite برای یک پلتفرم سازمانی مستقل از فناوری، مزایای معماری کمتری دارد.

# کاندید ۴ — SQL Server LocalDB

## نمای کلی (Overview)

ابزار SQL Server LocalDB نسخه سبک‌وزن مایکروسافت از SQL Server است که اساساً برای سناریوهای توسعه محلی در نظر گرفته شده است.

اگرچه سازگاری کامل با SQL Server دارد، اما تنها بر روی Windows در دسترس است.

---

## مزایا (Advantages)

- سازگاری کامل با SQL Server.
- موتور رابطه‌ای بالغ.
- قابلیت‌های عالی SQL.
- ابزارهای قدرتمند از طریق اکوسیستم SQL Server.
- یکپارچگی عالی با Entity Framework.

---

## معایب (Disadvantages)

- منحصر به ویندوز (Windows-only).
- عدم پشتیبانی از Android.
- عدم پشتیبانی از iOS.
- نامناسب برای استقرار تعبیه‌شده چندسکویی.
- نیازمند کامپوننت‌های زمان اجرای SQL Server.
- ردپای استقرار بزرگ‌تر.

---

سازگاری کلی **نامناسب (Unsuitable)** ارزیابی می‌شود.

| ریسک | احتمال | شدت اثر | اقدام کاهنده |

### منطق و دلایل تصمیم (Decision Rationale)

پایگاه داده SQLite تمامی نیازمندی‌های معماری اجباری تعیین‌شده توسط اسناد زیر را برآورده می‌سازد:

- ADR-0001 — معماری تمیز (Clean Architecture)
- ADR-0012 — معماری فضای کاری توزیع‌شده (Distributed Workspace Architecture)
- ADR-0013 — معماری برنامه کلاینت (Client Application Architecture)
- ADR-0014 — معماری داده‌های ورک‌اسپیس (Workspace Data Architecture)

پایگاه داده SQLite موارد زیر را فراهم می‌آورد:

- در دسترس بودن چندسکویی عالی.
- بلوغ سازمانی اثبات‌شده.
- ثبات تراکنشی ACID.
- قابلیت‌های آفلاین فوق‌العاده.
- استقلال فناوری.
- حداقل پیچیدگی استقرار.
- پایداری بلندمدت.
- یکپارچگی عالی با اکوسیستم NET.

هیچ‌یک از گزینه‌های ارزیابی‌شده تناسب معماری برتری ارائه ندادند.

بنابراین SQLite به‌عنوان فناوری پایداری تعبیه‌شده برای پیاده‌سازی‌های ورک‌اسپیس تصویب می‌شود.

---

## راهنمای پیاده‌سازی (Implementation Guidance)

پیاده‌سازی باید معماری منطقی داده‌های ورک‌اسپیس تعریف‌شده در ADR-0014 را حفظ کند.

انتخاب SQLite تفکیک منطقی میان بخش‌های زیر را تغییر **نمی‌دهد**:

- داده‌های پایه (Master Data)
- داده‌های پروژه (Project Data)
- داده‌های کاربر (User Data)

توپولوژی فیزیکی ذخیره‌سازی باید در طول پیاده‌سازی ضمن حفظ مرزهای ساختاری تعیین‌شده در ADR-0014 مشخص گردد.
