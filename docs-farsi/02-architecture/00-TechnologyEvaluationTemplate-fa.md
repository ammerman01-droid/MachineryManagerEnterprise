# هدف

توضیح دهید که این ارزیابی فناوری شامل چه مواردی است.

این بخش باید موارد زیر را بیان کند:

- چه قابلیت یا دغدغه معماری‌ای در حال بررسی است؛
- چرا این ارزیابی در حال حاضر انجام می‌شود؛
- نتیجه مورد انتظار (یک پشته فناوری توصیه‌شده، نه یک ADR نهایی).

---

# محدوده ارزیابی

این ارزیابی فناوری صرفاً به انتخاب فناوری می‌پردازد.

جزئیات پیاده‌سازی توسط سوابق تصمیم‌گیری معماری (ADRs) مربوطه تعیین می‌شوند.

---

# ارتباط با ارزیابی‌های فناوری قبلی

اگر این ارزیابی، یک ارزیابی فناوری و ADR تأییدشده قبلی را گسترش می‌دهد، تکمیل می‌کند یا مجدداً ارزیابی می‌کند، آن رابطه را به‌صراحت در اینجا ذکر کنید.

مثال‌ها:

- این ارزیابی بر پایه TE-000X / ADR-000X بنا شده و جایگزین آن نمی‌شود.
- این ارزیابی، TE-000X / ADR-000X را مجدداً ارزیابی می‌کند. فناوری تأییدشده قبلی به‌عنوان کاندیدای فعلی (Incumbent) در نظر گرفته شده است.

اگر هیچ ارتباطی با ارزیابی‌های پیشین وجود ندارد، ذکر کنید:

```text
This evaluation does not supersede or depend on any previously approved
Technology Evaluation.
```

# الزامات غیرعملکردی

ویژگی‌هایی را که راهکار باید فراهم کند فهرست کنید، برای مثال:

- کارایی (Performance)؛
- قابلیت نگهداری؛
- سازگاری با .NET 10؛
- بی‌طرفی نسبت به ابر (Cloud neutrality)؛
- امنیت؛
- تجربه توسعه‌دهنده.

# خلاصه تصمیم

چک‌لیستی که تأیید می‌کند پشته توصیه‌شده اهداف معماری را برآورده می‌کند، برای مثال:

- معماری تمیز (Clean Architecture)
- سازگاری با .NET 10
- انطباق با استانداردها
- تجربه توسعه‌دهنده
- خنثی‌بودن نسبت به فضای ابری
- قابلیت نگهداری
- آمادگی برای هوش مصنوعی

به‌طور شفاف بیان کنید که آیا این ارزیابی جایگزین ADR قبلی می‌شود یا آن را تأیید و تثبیت می‌کند.

# ADR مرتبط

به رکورد تصمیم معماری (ADR) که نتیجه این ارزیابی را رسمی می‌کند، ارجاع دهید.

```
ADR-000X
```

اگر این ارزیابی به جای نیاز به یک ADR جدید، یک ADR موجود را تأیید می‌کند، آن را به‌صراحت ذکر کنید.
