# هدف (Purpose)

این ارزیابی فناوری استراتژی ارائه‌دهنده هوش مصنوعی (AI Provider Strategy) را برای پلتفرم MachineryManagerEnterprise تعیین می‌کند.

فناوری انتخاب‌شده باید موارد زیر را فراهم آورد:

- تولید امبدینگ (Embedding Generation)
- تکمیل گفتگو و تولید متن (Chat Completion)
- تولید تقویت‌شده با بازیابی (Retrieval-Augmented Generation - RAG)
- دستیار هوش مصنوعی (AI Assistant)
- جستجوی دانش (Knowledge Search)
- توصیه‌های هوشمند تعمیر و نگهداری (Intelligent Maintenance Recommendations)
- توسعه‌های آتی هوش مصنوعی سازمانی

این ارزیابی منحصراً بر **ارائه‌دهندگان هوش مصنوعی (AI Providers)** تمرکز دارد. انتخاب پایگاه داده برداری پیش‌تر در **TE-0028** تکمیل شده است.

---

# دامنه ارزیابی (Evaluation Scope)

این ارزیابی فناوری موارد زیر را مورد بررسی قرار می‌دهد:

- ارائه‌دهندگان هوش مصنوعی ابری (Cloud AI Providers)
- ارائه‌دهندگان هوش مصنوعی محلی (Local/Self-Hosted AI Providers)
- استراتژی هوش مصنوعی ترکیبی (Hybrid AI Strategy)
- یکپارچگی هوش مصنوعی سازمانی
- ملاحظات عملیاتی
- مدل هزینه
- امنیت
- انعطاف‌پذیری استقرار

این سند موارد زیر را تعریف **نمی‌کند**:

- مهندسی پرامپت (Prompt Engineering)؛
- معماری ایجنت‌ها (Agent Architecture)؛
- معماری بازیابی داده‌ها (Retrieval Architecture)؛
- جریان‌های کاری هوش مصنوعی؛
- قوانین تجاری.

این تصمیمات معماری به‌صورت جداگانه در ADRهای مربوطه مستند خواهند شد.

# ۸. ارزیابی Azure OpenAI (کاندید اصلی سازمانی)

## نمای کلی

سرویس Azure OpenAI پیاده‌سازی سازمانی مایکروسافت از مدل‌های بنیادی OpenAI است که درون اکوسیستم مایکروسافت آژور میزبانی می‌شود. این سرویس بدون نیاز به اتصال مستقیم به پلتفرم عمومی OpenAI، همان مدل‌ها را با امنیت، انطباق‌پذیری و حاکمیت داده‌های سازمانی ارائه می‌دهد.

```text
                  Application Layer
                         │
                         ▼
               AI Orchestration Layer
                         │
                         ▼
                Azure OpenAI Service
        ┌────────────────────────────────┐
        │ Embedding Models               │
        │ Chat Completion Models         │
        │ Function Calling & Streaming   │
        │ Content Filtering (Enterprise) │
        └────────────────────────────────┘
                         │
                         ▼
                AI Generated Response
```

---

## نقاط قوت معماری

- میزبانی سازمانی با SLA معتبر مایکروسافت؛
- یکپارچگی بومی با Microsoft Entra ID (Azure AD) و Managed Identities؛
- پشتیبانی از شبکه‌بندی کاملاً خصوصی (Private Endpoints / VNet)؛
- انطباق با استانداردهای سخت‌گیرانه امنیتی (ISO 27001, SOC, GDPR)؛
- مدل‌های پایدار با چرخه حیات شرکتی بدون افشای داده‌های سازمان برای آموزش مدل‌ها.

# ۹. ارزیابی OpenAI (کاندید ثانویه ابری)

## نمای کلی و تحلیل

پلتفرم OpenAI دسترسی مستقیم و فوری به جدیدترین مدل‌های روز (GPT-4o و مدل‌های استدلالی جدید) را از طریق API عمومی فراهم می‌کند.

- **مزایا:** دسترسی فوری به آخرین نوآوری‌ها، SDKهای بالغ، جامعه کاربری وسیع؛
- **معایب:** عدم یکپارچگی بومی با اکوسیستم احراز هویت مایکروسافت و محدودیت در اتصال به شبکه‌های خصوصی ایزوله درون‌سازمانی نسبت به Azure.

OpenAI به‌عنوان یک ارائه‌دهنده ابری ثانویه و تکمیلی پشتیبانی خواهد شد اما گزینه پیش‌فرض برای سازمان نخواهد بود.

---

# ۱۰. ارزیابی Ollama (کاندید هوش مصنوعی محلی و آفلاین)

## نمای کلی و تحلیل

اولاما (Ollama) یک ابزار متن‌باز سبک برای اجرای مدل‌های زبانی متن‌باز (مانند Llama، Mistral، Phi و Gemma) و مدل‌های تولید امبدینگ (مانند BGE و Nomic) به‌صورت کاملاً محلی و آفلاین بر روی سرورهای سازمان است.

- **مزایا:** استقلال کامل از ابر و اینترنت؛ امنیت و حاکمیت صددرصدی داده‌ها؛ بدون هزینه ترافیک یا توکن؛ قابلیت استقرار در محیط‌های کاملاً ایزوله (Air-Gapped)؛
- **معایب:** نیازمند سخت‌افزار سروری قدرتمند (GPUهای اختصاصی سازمانی)؛ پیچیدگی بالاتر در عملیات و مانیتورینگ نسبت به سرویس‌های ابری.

Ollama به‌عنوان ارائه‌دهنده محلی برای سناریوهای آفلاین یا حریم خصوصی حساس در پلتفرم پشتیبانی می‌شود.

# ۱۱. ارزیابی استراتژی هوش مصنوعی ترکیبی (Hybrid AI Strategy)

استراتژی ترکیبی، هسته مرکزی معماری هوش مصنوعی MachineryManagerEnterprise است. بر اساس این استراتژی، لایه کاربرد هرگز مستقیماً با یک سرویس‌دهنده خاص جفت (Couple) نمی‌شود، بلکه از طریق واسط `IAIProvider` و الگوهای Dependency Inversion تعامل می‌نماید.

```text
                     Application Layer
                            │
                            ▼
                  IAIProvider Interface
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
  Azure OpenAI            OpenAI              Ollama
(ارائه‌دهنده اصلی)      (پشتیبان ثانویه)    (محلی و آفلاین)
```

# ۱۳. پیشنهاد نهایی (Final Recommendation)

هیئت بازنگری معماری استفاده از **استراتژی هوش مصنوعی ترکیبی (Hybrid AI Strategy)** با اولویت‌بندی زیر را پیشنهاد می‌نماید:

| مؤلفه | فناوری منتخب | نقش در معماری |
|---|---|---|
| **ارائه‌دهنده اصلی (Primary)** | **Azure OpenAI** | پردازش پیش‌فرض درخواست‌های ابری سازمانی، RAG و امبدینگ |
| **ارائه‌دهنده ثانویه (Secondary)** | **OpenAI** | پشتیبان ابری و سناریوهای ارزیابی مدل |
| **ارائه‌دهنده محلی (Local)** | **Ollama** | استقرارهای آفلاین، مشتریان درون‌سازمانی (On-Premise) و محیط‌های ایزوله |
