## هدف

این سند فناوری‌های نامزد را برای ارزیابی فناوری تست عملکرد و بار در MachineryManagerEnterprise ارزیابی می‌کند.
هدف، ایجاد یک انتخاب فناوری یکپارچه است که تمام الزامات کارکردی و معماری را برآورده کند و در عین حال اصول معماری تمیز (Clean Architecture) را حفظ نماید.
فناوری‌های انتخاب‌شده باید از اعتبارسنجی مستمر عملکرد در طول چرخه عمر نرم‌افزار پشتیبانی کنند.

## محدوده ارزیابی

این ارزیابی فناوری موارد زیر را ارزیابی می‌کند:

- BenchmarkDotNet
- NBomber
- k6

این سند موارد زیر را تعریف نمی‌کند:

- SLA عملکرد
- نظارت محیط تولید
- پلتفرم مشاهده‌پذیری
- سیاست برنامه‌ریزی ظرفیت
- استراتژی مقیاس‌پذیری خودکار

این تصمیمات معماری به‌طور جداگانه در ADR مربوطه مستند شده‌اند.

## رابطه با ADRهای مرتبط

این ارزیابی فناوری از موارد زیر پشتیبانی می‌کند:

## ۸. ارزیابی BenchmarkDotNet

### نمای کلی

BenchmarkDotNet چارچوب بنچمارک رسمی برای اکوسیستم .NET است.
این چارچوب به‌طور خاص برای اندازه‌گیری ویژگی‌های عملکردی قطعات کوچک کد با دقت علمی طراحی شده است.
برخلاف اندازه‌گیری‌های زمانی معمولی، BenchmarkDotNet به‌طور خودکار موارد زیر را کنترل می‌کند:

- کامپایل JIT
- گرم کردن CPU
- جمع‌آوری زباله
- تکرارهای متعدد
- تحلیل آماری

در MachineryManagerEnterprise، BenchmarkDotNet به‌عنوان چارچوب اصلی ریزبنچمارک ارزیابی می‌شود.

### نقش معماری

```
        مؤلفه برنامه
              │
              ▼
      BenchmarkDotNet
 ┌────────────────────────────┐
 │ گرم‌کردن                   │
 │ تکرارهای متعدد             │
 │ تحلیل GC                   │
 │ تحلیل حافظه                │
 │ ارزیابی آماری              │
 └────────────────────────────┘
              │
              ▼
        گزارش عملکرد
```

BenchmarkDotNet الگوریتم‌های منفرد را ارزیابی می‌کند نه رفتار کامل سیستم را.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- چارچوب بنچمارک رسمی .NET
- دقت آماری
- عیب‌یابی حافظه
- عیب‌یابی CPU
- اجرای قابل‌تکرار
- گزارش‌دهی عالی
- تشخیص مستمر پسرفت عملکرد
- یکپارچه‌سازی بومی با .NET

### قابلیت‌های کارکردی

BenchmarkDotNet از موارد زیر پشتیبانی می‌کند:

- اندازه‌گیری زمان اجرا
- تحلیل تخصیص حافظه
- معیارهای جمع‌آوری زباله
- تحلیل عملکرد CPU
- بنچمارک‌های پارامتری
- مقایسه با خط مبنا
- قالب‌های خروجی
- گزارش‌دهی آماری

### گردش کار معمول بنچمارک

```

      │
گرم‌کردن
      │

      │

      │
گزارش بنچمارک
```

این چارچوب به‌طور خودکار گرم‌کردن و اجرای مکرر را برای بهبود دقت اندازه‌گیری انجام می‌دهد.

### دقت آماری

BenchmarkDotNet به‌طور خودکار موارد زیر را محاسبه می‌کند:

- میانگین
- میانه
- انحراف معیار
- خطا
- بازه اطمینان

این موضوع قابلیت اطمینان اندازه‌گیری‌های عملکرد را در مقایسه با زمان‌سنجی دستی به‌طور قابل‌توجهی بهبود می‌بخشد.

### عیب‌یابی حافظه

این چارچوب موارد زیر را گزارش می‌دهد:

- حافظه تخصیص‌یافته
- جمع‌آوری‌های زباله
- نرخ تخصیص

این امکان به توسعه‌دهندگان می‌دهد تخصیص‌های غیرضروری را شناسایی و مصرف حافظه را بهینه کنند.

### گزارش‌دهی

قالب‌های خروجی پشتیبانی‌شده شامل موارد زیر است:

- Markdown
- HTML
- CSV
- JSON

گزارش‌ها می‌توانند به‌عنوان مصنوعات CI/CD بایگانی شوند.

### سازگاری CI/CD

BenchmarkDotNet به‌خوبی با موارد زیر یکپارچه می‌شود:

- GitHub Actions

- .NET CLI

بنچمارک‌های عملکرد می‌توانند به‌عنوان بخشی از اعتبارسنجی مستمر به‌صورت خودکار اجرا شوند.

این چارچوب برای تست بار در سطح کل سیستم طراحی نشده است.

### تأثیر عملکردی

اجرای بنچمارک عمداً کندتر است زیرا دقت آماری بر سرعت اجرا اولویت دارد.
این موضوع مناسب است زیرا بنچمارک‌ها خارج از بارهای کاری محیط تولید اجرا می‌شوند.

این چارچوب به‌عنوان چارچوب استاندارد برای بنچمارک عملکرد و تشخیص پسرفت تأیید می‌شود.

## ۹. ارزیابی NBomber

### نمای کلی

NBomber یک چارچوب تست بار متن‌باز است که به‌طور خاص برای برنامه‌های .NET طراحی شده است.
برخلاف BenchmarkDotNet که عملکرد متدهای منفرد را اندازه‌گیری می‌کند، NBomber رفتار سیستم‌های کامل را تحت بارهای کاری همزمان ارزیابی می‌کند.
در MachineryManagerEnterprise، NBomber به‌عنوان چارچوب اصلی تست بار سازمانی ارزیابی می‌شود.

### نقش معماری

```
        کاربران همزمان

          NBomber

 └────────────────────────────┘
              │
              ▼
        گزارش عملکرد
```

NBomber رفتار کامل برنامه را تحت بارهای کاری همزمان واقع‌گرایانه ارزیابی می‌کند.

مزایا شامل موارد زیر است:

- پیاده‌سازی بومی .NET

- تست مبتنی بر سناریو
- معیارهای بلادرنگ
- اجرای خوشه‌ای
- گزارش‌دهی عالی
- خودکارسازی آسان
- یکپارچه‌سازی قوی با اکوسیستم .NET

### قابلیت‌های کارکردی

NBomber از موارد زیر پشتیبانی می‌کند:

- تست بار
- تست فشار
- تست اوج
- تست استقامت
- شبیه‌سازی کاربران همزمان

## ۱۰. ارزیابی k6

### نمای کلی

k6 یک پلتفرم مدرن متن‌باز تست بار است که بر بارهای کاری مبتنی بر HTTP و اعتبارسنجی عملکرد API تمرکز دارد.
برخلاف BenchmarkDotNet که عملکرد الگوریتم‌های داخلی را اندازه‌گیری می‌کند و برخلاف NBomber که به‌طور نزدیک با .NET یکپارچه است، k6 بر رفتار خارجی سیستم از طریق تست سطح پروتکل تمرکز دارد.
در MachineryManagerEnterprise، k6 به‌عنوان راه‌حل تست بار API و زیرساخت ارزیابی می‌شود.

### نقش معماری

```
        کاربران مجازی
              │
              ▼
             k6
 ┌──────────────────────────┐
 │ درخواست‌های HTTP         │
 │ سناریوهای API            │
 │ تولید بار                │
 │ جمع‌آوری معیارها         │
 └──────────────────────────┘
              │
              ▼
   APIهای REST / درگاه‌ها
```

k6 عملکرد قابل‌مشاهده خارجی سیستم را از طریق ترافیک HTTP ارزیابی می‌کند.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- پلتفرم تست بار استاندارد صنعتی
- طراحی با اولویت HTTP
- مقیاس‌پذیری بالا
- اسکریپت‌نویسی مبتنی بر JavaScript
- پشتیبانی از اجرای ابری
- داشبوردهای عالی
- یکپارچه‌سازی قوی با اکوسیستم Grafana
- سازگار با CI/CD

### قابلیت‌های کارکردی

k6 از موارد زیر پشتیبانی می‌کند:

- تست بار
- تست فشار
- تست اوج
- تست تحمل طولانی‌مدت (Soak)
- تست عملکرد API
- اندازه‌گیری توان عملیاتی
- اندازه‌گیری تأخیر
- اعتبارسنجی SLA

### مدل تست API

گردش اجرای معمول:

```
کاربران مجازی
      │
درخواست‌های HTTP
      │
API برنامه
      │
معیارهای عملکرد
```

این پلتفرم رفتار قابل‌مشاهده خارجی را به‌جای جزئیات پیاده‌سازی داخلی اعتبارسنجی می‌کند.

### معیارها

k6 موارد زیر را اندازه‌گیری می‌کند:

- درخواست بر ثانیه
- زمان پاسخ
- تأخیر
- نرخ خطا
- صدک‌ها
- توان عملیاتی
- کاربران مجازی فعال

### مقیاس‌پذیری

k6 قادر است موارد زیر را تولید کند:

- هزاران کاربر همزمان
- میلیون‌ها درخواست HTTP
- اجرای توزیع‌شده
- اجرای مبتنی بر فضای ابری

مقیاس‌پذیری **عالی** ارزیابی می‌شود.

### گزارش‌دهی

- CSV
- HTML
- Grafana Cloud

- InfluxDB

مصورسازی غنی از طریق اکوسیستم Grafana در دسترس است.

### سازگاری CI/CD

خودکارسازی اجرا ساده است.

موتور k6 برای تولید بار سطح پروتکل در مقیاس بزرگ بهینه شده است.
عملکرد **عالی** ارزیابی می‌شود.

مزایا شامل موارد زیر است:

سادگی عملیاتی **عالی** ارزیابی می‌شود.

این ابزار گردش‌های کاری تجاری داخلی .NET را مستقیماً اجرا نمی‌کند و بنابراین مکمل BenchmarkDotNet یا NBomber است نه جایگزین آن‌ها.

### استراتژی آزمون توصیه‌شده

مسئولیت اصلی:

- تست بار گردش کاری تجاری
- شبیه‌سازی کاربران همزمان

- توان عملیاتی پیام‌رسانی
- تست استقامت

NBomber به چارچوب اصلی تست بار سازمانی تبدیل می‌شود.

#### k6

مسئولیت اصلی:

- عملکرد REST API
- اعتبارسنجی نقاط پایانی HTTP
- ظرفیت زیرساخت
- عملکرد درگاه
- تست بار رابط عمومی

k6 رفتار قابل‌مشاهده خارجی سیستم را اعتبارسنجی می‌کند.
