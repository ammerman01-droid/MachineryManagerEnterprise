## هدف

این سند فناوری‌های نامزد را برای ارزیابی فناوری امنیت در MachineryManagerEnterprise ارزیابی می‌کند.
هدف، ایجاد یک انتخاب فناوری یکپارچه است که تمام الزامات عملکردی و معماری را برآورده کند و در عین حال اصول معماری تمیز (Clean Architecture) را حفظ نماید.
فناوری‌های انتخاب‌شده باید موارد زیر را فراهم کنند:

- حفاظت از داده‌ها
- رمزنگاری
- مدیریت گواهینامه‌ها
- چرخش کلید
- پیکربندی امن
- حفاظت از اسرار
- انطباق نظارتی
- حاکمیت امنیت سازمانی

## محدوده ارزیابی

این ارزیابی فناوری موارد زیر را ارزیابی می‌کند:

- ASP.NET Core Data Protection
- رمزنگاری AES-256
- مدیریت گواهینامه‌های X.509
- چرخش خودکار کلید
- توصیه‌های امنیتی OWASP

این سند موارد زیر را تعریف نمی‌کند:

- معماری احراز هویت
- معماری مجوزدهی
- ارائه‌دهنده هویت
- استراتژی ممیزی
- فرآیند توسعه امن

این تصمیمات معماری به‌طور جداگانه در ADRهای اختصاصی مستند شده‌اند.

## ۸. ارزیابی ASP.NET Core Data Protection

### نمای کلی

ASP.NET Core Data Protection چارچوب رسمی مایکروسافت برای حفاظت از داده‌های حساس برنامه‌ها است.
این چارچوب موارد زیر را فراهم می‌کند:

- مدیریت کلیدهای رمزنگاری؛
- رمزنگاری احراز هویت‌شده؛
- مدیریت خودکار چرخه عمر کلید؛
- انتزاع ذخیره‌سازی امن.

اگرچه این چارچوب در ابتدا برای ASP.NET Core معرفی شد، اما APIهای Data Protection مستقل از ASP.NET هستند و می‌توانند توسط برنامه‌های دسکتاپ، سرویس و پس‌زمینه استفاده شوند.
در MachineryManagerEnterprise، Data Protection به‌عنوان پلتفرم اصلی برای حفاظت از داده‌های حساس برنامه که به‌صورت محلی ذخیره می‌شوند، ارزیابی می‌گردد.

### نقش معماری

```
           داده‌های حساس
                  │
                  ▼
     ASP.NET Core Data Protection
      ┌──────────────────────────┐
      │ مدیریت کلید              │
      │ رمزنگاری                 │
      │ احراز هویت               │
      │ چرخش کلید                │
      └──────────────────────────┘
                  │
                  ▼
          بار مفید محافظت‌شده
```

این چارچوب حفاظت سطح برنامه از اطلاعات حساس را فراهم می‌کند.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- پیاده‌سازی رسمی مایکروسافت
- پیش‌فرض‌های رمزنگاری قوی
- مدیریت خودکار کلید
- پشتیبانی چندسکویی
- ذخیره‌سازی کلید قابل توسعه
- API امن
- مستندات عالی
- پشتیبانی بلندمدت

### قابلیت‌های عملکردی

Data Protection از موارد زیر پشتیبانی می‌کند:

- رمزنگاری احراز هویت‌شده
- تولید خودکار کلید
- نسخه‌بندی کلید
- چرخش کلید
- حفاظت از بار مفید
- جداسازی هدف
- چندین ارائه‌دهنده ذخیره‌سازی کلید

### مدل رمزنگاری

این چارچوب رمزنگاری احراز هویت‌شده را فراهم می‌کند.

```
متن ساده
     │
رمزنگاری
     │
حفاظت از یکپارچگی
     │
بار مفید محافظت‌شده
```

هم محرمانگی و هم یکپارچگی حفظ می‌شوند.

### مدیریت کلید

این چارچوب به‌طور خودکار موارد زیر را مدیریت می‌کند:

- تولید کلید
- فعال‌سازی کلید
- انقضای کلید
- جایگزینی کلید

برنامه‌ها نیازی به پیاده‌سازی منطق سفارشی چرخه عمر کلید ندارند.

### پشتیبانی چندسکویی

محیط‌های پشتیبانی‌شده:

| پلتفرم|پشتیبانی|
| ---|---|
| ویندوز|✅|
| لینوکس|✅|
| مک‌اواس|✅|

API یکسان در تمام پلتفرمهای پشتیبانی‌شده در دسترس است.

### تناسب سازمانی

مناسب برای حفاظت از:

- اسرار پیکربندی محلی
- اطلاعات اتصال
- اعتبارنامه‌های ذخیره‌شده موقت
- متادیتای حساس برنامه
- بارهای مفید امن داخلی

### عملکرد

عملیات‌ها سبک هستند.
سربار رمزنگاری برای بارهای کاری مورد نظر ناچیز است.
عملکرد **عالی** ارزیابی می‌شود.

### سادگی عملیاتی

مزایا شامل موارد زیر است:

- حداقل پیکربندی
- چرخه عمر خودکار
- پیش‌فرض‌های قوی
- بدون نیاز به پیاده‌سازی سفارشی رمزنگاری

سادگی عملیاتی **عالی** ارزیابی می‌شود.

### ارزیابی امنیتی

این چارچوب با موارد زیر از بسیاری از خطاهای رایج پیاده‌سازی جلوگیری می‌کند:

- جلوگیری از انتخاب نادرست الگوریتم؛
- اعمال رمزنگاری احراز هویت‌شده؛
- مدیریت خودکار کلیدها.

### ارزیابی فناوری

| معیار|ارزیابی|
| ---|---|
| آمادگی سازمانی|عالی|
| قدرت رمزنگاری|عالی|
| یکپارچه‌سازی با مایکروسافت|عالی|
| چندسکویی|عالی|
| قابلیت نگهداری|عالی|
| سادگی عملیاتی|عالی|
| عملکرد|عالی|
| قابلیت دوام بلندمدت|عالی|

### مزایا

- راه‌حل رسمی مایکروسافت
- چرخه عمر خودکار کلید
- پیش‌فرض‌های قوی
- قابلیت نگهداری عالی
- پیاده‌سازی درجه سازمانی

### معایب

- برای رمزنگاری فایل طراحی نشده است
- جایگزین زیرساخت کامل مدیریت کلید نیست

این محدودیت‌ها برای نقش معماری مورد نظر مناسب هستند.

### نتیجه‌گیری اولیه

ASP.NET Core Data Protection به‌طور کامل الزامات حفاظت از داده‌ها در سطح برنامه MachineryManagerEnterprise را برآورده می‌کند.
این فناوری به‌عنوان پلتفرم استاندارد برای حفاظت از داده‌های حساس برنامه تأیید می‌شود.

## ۹. ارزیابی رمزنگاری AES-256

### نمای کلی

AES-256 (استاندارد رمزنگاری پیشرفته با کلیدهای ۲۵۶ بیتی) الگوریتم رمزنگاری متقارن استاندارد صنعتی است که توسط موارد زیر تأیید شده است:

- NIST
- ISO
- FIPS
- مایکروسافت

این الگوریتم به‌طور گسترده به‌عنوان الگوریتم رمزنگاری ترجیحی برای نرم‌افزارهای سازمانی شناخته می‌شود.
در MachineryManagerEnterprise، AES-256 به‌عنوان الگوریتم رمزنگاری استاندارد برای داده‌های محرمانه ارزیابی می‌گردد.

### نقش معماری

```
داده‌های حساس
      │
      ▼
رمزنگاری AES-256
      │
داده‌های رمزنگاری‌شده
      │
ذخیره‌سازی امن
```

AES-256 محرمانگی قوی برای اطلاعات محافظت‌شده فراهم می‌کند.

### قدرت رمزنگاری

AES-256 موارد زیر را فراهم می‌کند:

- طول کلید ۲۵۶ بیتی
- مقاومت قوی در برابر حملات نیروی brute-force
- امنیت استاندارد صنعتی
- تحلیل امنیتی گسترده

قدرت رمزنگاری **عالی** ارزیابی می‌شود.

### قابلیت‌های عملکردی

AES-256 از موارد زیر پشتیبانی می‌کند:

- رمزنگاری متقارن
- رمزنگاری داده‌های بزرگ
- پردازش سریع
- رمزنگاری جریانی
- سازگاری سازمانی

### یکپارچه‌سازی با مایکروسافت

AES-256 به‌طور کامل توسط موارد زیر پشتیبانی می‌شود:

- APIهای رمزنگاری .NET
- ویندوز
- لینوکس
- مک‌اواس

هیچ کتابخانه رمزنگاری خارجی مورد نیاز نیست.

### عملکرد

AES-256 از شتاب‌دهی سخت‌افزاری در پردازنده‌های مدرن بهره‌مند می‌شود.
عملکرد **عالی** ارزیابی می‌شود.

### تناسب سازمانی

مناسب برای:

- داده‌های تجاری حساس
- ذخیره‌سازی رمزنگاری‌شده محلی
- فایل‌های امن صادراتی
- رمزنگاری پشتیبان‌گیری

### ارزیابی فناوری

| معیار|ارزیابی|
| ---|---|
| آمادگی سازمانی|عالی|
| قدرت رمزنگاری|عالی|
| عملکرد|عالی|
| چندسکویی|عالی|
| مستندسازی|عالی|
| قابلیت دوام بلندمدت|عالی|

### مزایا

- استاندارد صنعتی
- شتاب‌دهی سخت‌افزاری
- رمزنگاری قوی
- پشتیبانی گسترده اکوسیستم

### معایب

- نیازمند مدیریت امن کلید
- فقط رمزنگاری متقارن

### نتیجه‌گیری اولیه

AES-256 به‌طور کامل الزامات رمزنگاری MachineryManagerEnterprise را برآورده می‌کند.
این الگوریتم به‌عنوان الگوریتم رمزنگاری متقارن استاندارد تأیید می‌شود.

## ۱۰. ارزیابی مدیریت گواهینامه‌های X.509

### نمای کلی

X.509 استاندارد بین‌المللی برای گواهینامه‌های دیجیتال است که برای ایجاد هویت، اعتماد و ارتباطات امن استفاده می‌شود.
در MachineryManagerEnterprise، گواهینامه‌های X.509 برای موارد زیر ارزیابی می‌شوند:

- امنیت لایه انتقال (TLS)
- احراز هویت متقابل
- امضای دیجیتال
- اعتماد مبتنی بر گواهینامه
- ارتباط امن بین سرویس‌ها

گواهینامه‌ها برای جایگزینی مکانیزم‌های احراز هویت برنامه طراحی نشده‌اند؛ آن‌ها اعتماد بین طرفین ارتباطی را ایجاد می‌کنند.

### نقش معماری

```
        کلاینت / سرویس
               │
               ▼
      گواهینامه X.509
               │
احراز هویت
               │
               ▼
      ارتباط امن
```

گواهینامه‌ها تأیید هویت رمزنگاری قبل از شروع ارتباط امن را فراهم می‌کنند.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- استاندارد بین‌المللی
- پشتیبانی بومی مایکروسافت
- هویت رمزنگاری قوی
- سازگاری با زیرساخت کلید عمومی (PKI)
- یکپارچه‌سازی با TLS
- احراز هویت متقابل
- اعتبارسنجی زنجیره گواهینامه
- مدل اعتماد سازمانی

### قابلیت‌های عملکردی

گواهینامه‌های X.509 از موارد زیر پشتیبانی می‌کنند:

- احراز هویت TLS
- TLS متقابل (mTLS)
- امضاهای دیجیتال
- اعتبارسنجی گواهینامه
- تأیید زنجیره گواهینامه
- بررسی لغو گواهینامه
- یکپارچه‌سازی با فروشگاه اعتماد
- زیرساخت کلید عمومی

### یکپارچه‌سازی با زیرساخت کلید عمومی (PKI)

گواهینامه‌ها به‌طور طبیعی با PKI سازمانی یکپارچه می‌شوند.

```
ریشه CA
    │
CA واسط
    │
گواهینامه سرور
    │
برنامه
```

برنامه زنجیره اعتماد کامل را قبل از برقراری ارتباط اعتبارسنجی می‌کند.

### موارد استفاده از گواهینامه

موارد استفاده تأیید شده شامل:

- HTTPS
- gRPC TLS
- ارتباط سرویس به سرویس
- احراز هویت API
- تأیید امضای دیجیتال

گواهینامه‌ها نباید برای موارد زیر استفاده شوند:

- اسرار برنامه؛
- ذخیره‌سازی کلید رمزنگاری؛
- مدیریت رمز عبور.

### یکپارچه‌سازی با مایکروسافت

پشتیبانی بومی در موارد زیر وجود دارد:

- .NET 10
- فروشگاه گواهینامه ویندوز
- فروشگاه گواهینامه لینوکس
- Keychain مک‌اواس
- Kestrel
- HttpClient
- SslStream

هیچ چارچوب گواهینامه شخص ثالثی مورد نیاز نیست.

### امنیت

گواهینامه‌ها موارد زیر را فراهم می‌کنند:

- تأیید هویت قوی
- رمزنگاری انتقال
- مقاومت در برابر دستکاری
- اعتماد رمزنگاری

امنیت **عالی** ارزیابی می‌شود.

### ویژگی‌های عملیاتی

چرخه عمر گواهینامه شامل:

```
صدور
   │
استقرار
   │
اعتبارسنجی
   │
تمدید
   │
لغو (در صورت لزوم)
```

پیچیدگی عملیاتی متوسط است اما در محیط‌های سازمانی به‌خوبی شناخته شده است.

### عملکرد

اعتبارسنجی گواهینامه سربار حداقلی در مقایسه با ارتباطات شبکه ایجاد می‌کند.
عملکرد **عالی** ارزیابی می‌شود.

### تناسب سازمانی

مناسب برای:

- استقرارهای سازمانی
- زیرساخت ترکیبی
- سرویس‌های ابری

- یکپارچه‌سازی‌های خارجی

### ارزیابی فناوری

| معیار|ارزیابی|
| ---|---|
| آمادگی سازمانی|عالی|
| امنیت|عالی|
| یکپارچه‌سازی با مایکروسافت|عالی|
| چندسکویی|عالی|

## ۱۱. ارزیابی چرخش خودکار کلید

### نمای کلی

چرخش کلید جایگزینی کنترل‌شده کلیدهای رمزنگاری در طول زمان برای کاهش مواجهه بلندمدت در صورت افشای کلید است.
به‌جای اتکا به کلیدهای رمزنگاری دائمی، سیستم‌های سازمانی به‌صورت دوره‌ای کلیدهای جدید تولید و فعال می‌کنند و در عین حال دسترسی به داده‌های رمزنگاری‌شده قبلی را حفظ می‌نمایند.
در MachineryManagerEnterprise، چرخش خودکار کلید به‌عنوان یک قابلیت امنیتی سازمانی اجباری ارزیابی می‌گردد.

### نقش معماری

```
کلید فعال
     │
رمزنگاری داده
     │
بازه چرخش
     │
تولید کلید جدید
     │
فعال‌سازی کلید جدید
     │
حفظ کلیدهای قدیمی
```

فقط جدیدترین کلید فعال برای رمزنگاری استفاده می‌شود در حالی که کلیدهای قبلی برای رمزگشایی در دسترس باقی می‌مانند.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- کاهش مواجهه کلید
- امنیت رو به جلو
- آمادگی انطباق
- مدیریت خودکار چرخه عمر
- کاهش ریسک عملیاتی
- مقیاس‌پذیری سازمانی

### قابلیت‌های عملکردی

چرخش خودکار کلید از موارد زیر پشتیبانی می‌کند:

- تولید زمان‌بندی‌شده کلید
- فعال‌سازی کلید
- انقضای کلید
- حفظ کلیدهای تاریخی
- رمزگشایی شفاف
- کلیدهای نسخه‌بندی‌شده

### چرخه عمر کلید

```
تولید
    │
فعال
    │
منقضی‌شده
    │
بازنشسته
    │
نابود شده
```

برنامه‌ها به رمزگشایی داده‌های تاریخی ادامه می‌دهند در حالی که تمام داده‌های جدید را با کلید فعال رمزنگاری می‌کنند.

### مزایای امنیتی

چرخش خودکار موارد زیر را کاهش می‌دهد:

- تأثیر افشای کلید؛
- مواجهه رمزنگاری بلندمدت؛
- ریسک عملیاتی.

بهبود امنیتی **قابل‌توجه** ارزیابی می‌شود.

### یکپارچه‌سازی با مایکروسافت

ASP.NET Core Data Protection از قبل شامل چرخش خودکار کلید است.
هیچ پیاده‌سازی اضافی فراتر از پیکربندی مناسب مورد نیاز نیست.

### ویژگی‌های عملیاتی

چرخش خودکار است.
مسئولیت‌های مدیریتی محدود به موارد زیر است:

- پشتیبان‌گیری؛
- نظارت؛
- سیاست نگهداری.

بنابراین پیچیدگی عملیاتی **کم** ارزیابی می‌شود.

### عملکرد

چرخش به‌صورت نامکرر انجام می‌شود و تأثیر ناچیزی بر زمان اجرا دارد.
عملکرد **عالی** ارزیابی می‌شود.

### تناسب سازمانی

چرخش خودکار برای موارد زیر مناسب است:

- استقرارهای سازمانی
- انطباق نظارتی
- برنامه‌های بلندمدت
- داده‌های تجاری حساس

### ارزیابی فناوری

| معیار|ارزیابی|
| ---|---|
| آمادگی سازمانی|عالی|
| بهبود امنیتی|عالی|
| سادگی عملیاتی|عالی|
| عملکرد|عالی|
| یکپارچه‌سازی با مایکروسافت|عالی|
| قابلیت دوام بلندمدت|عالی|

### مزایا

- چرخه عمر خودکار
- بهبود وضعیت امنیتی
- عملکرد شفاف
- داخلی در Data Protection مایکروسافت

### معایب

- نیازمند پشتیبان‌گیری مناسب کلید
- کلیدهای تاریخی باید به‌طور مناسب حفظ شوند

### نتیجه‌گیری اولیه

چرخش خودکار کلید به‌طور کامل الزامات چرخه عمر کلید سازمانی MachineryManagerEnterprise را برآورده می‌کند.
این فناوری به‌عنوان استراتژی اجباری مدیریت کلید تأیید می‌شود.

## ۱۲. ارزیابی توصیه‌های OWASP

### نمای کلی

پروژه امنیت برنامه‌های وب جهان‌باز (OWASP) شناخته‌شده‌ترین سازمان ارائه‌دهنده راهنمایی‌های امنیتی برای توسعه نرم‌افزار مدرن است.
OWASP به‌جای اینکه یک محصول نرم‌افزاری باشد، اصول امنیتی، شیوه‌های توسعه امن و توصیه‌های معماری را تعریف می‌کند که آسیب‌پذیری‌های رایج برنامه‌ها را کاهش می‌دهند.
در MachineryManagerEnterprise، OWASP به‌عنوان استاندارد امنیتی اصلی حاکم بر معماری نرم‌افزار، پیاده‌سازی و شیوه‌های عملیاتی ارزیابی می‌گردد.

### نقش معماری

```
            استانداردهای OWASP
                   │
                   ▼
      تصمیمات معماری امن
                   │
        پیاده‌سازی امن
                   │
          استقرار امن
                   │
          عملیات امن
```

OWASP بر هر لایه از چرخه عمر برنامه تأثیر می‌گذارد نه فقط یک مؤلفه نرم‌افزاری واحد.

### نقاط قوت معماری

مزایا شامل موارد زیر است:

- استاندارد امنیتی شناخته‌شده صنعتی
- مستقل از فناوری
- بی‌طرف نسبت به فروشنده
- راهنمایی‌های به‌روزشده منظم
- مستندات گسترده
- پذیرش گسترده جامعه
- کاربردپذیری سازمانی
- همسویی نظارتی

### قابلیت‌های عملکردی

OWASP برای موارد زیر راهنمایی فراهم می‌کند:

- کدنویسی امن
- مدل‌سازی تهدید
- احراز هویت
- مجوزدهی
- اعتبارسنجی ورودی
- رمزنگاری
- مدیریت نشست
- لاگینگ
- نظارت
- استقرار امن

معماری باید به‌طور صریح دسته‌بندی‌های فعلی OWASP Top 10 را کاهش دهد.

| مؤلفه‌های آسیب‌پذیر|✅|
| شکست‌های احراز هویت|✅|
| شکست‌های یکپارچگی نرم‌افزار|✅|
| شکست‌های لاگینگ و نظارت|✅|
| جعل درخواست سمت سرور|✅|

### راهنمایی توسعه امن

توصیه‌های OWASP باید در طول موارد زیر اعمال شوند:

- طراحی معماری
- کدنویسی
- بازبینی کد
- تست
- استقرار
- نگهداری

بنابراین امنیت به‌عنوان یک فعالیت مهندسی مداوم تلقی می‌شود نه یک مرحله اعتبارسنجی نهایی.

### سازگاری با معماری تمیز

OWASP به‌طور طبیعی با معماری تأیید شده همسو است.
نمونه‌ها شامل:

- اعتبارسنجی در مرزهای برنامه؛
- وارونگی وابستگی برای کاهش سطح حمله؛
- جداسازی زیرساخت؛
- مدیریت متمرکز استثناها؛
- مدیریت پیکربندی امن.

### لاگینگ و نظارت

OWASP موارد زیر را توصیه می‌کند:

- لاگینگ ساختاریافته؛
- ثبت رویدادهای امنیتی؛
- قابلیت ممیزی؛
- نظارت بر رفتار غیرعادی.

این توصیه‌ها با استراتژی لاگینگ تأیید شده پروژه همسو هستند.

### احراز هویت و مجوزدهی

راهنمایی OWASP از موارد زیر پشتیبانی می‌کند:

- حداقل امتیاز؛
- دفاع در عمق؛
- اعتبارسنجی امن هویت؛
- مدیریت امن نشست.

پیاده‌سازی دقیق به‌طور جداگانه در معماری احراز هویت بررسی می‌شود.

### رمزنگاری

OWASP موارد زیر را توصیه می‌کند:

- الگوریتم‌های تأیید شده؛
- مدیریت مناسب کلید؛
- رمزنگاری احراز هویت‌شده؛
- تولید اعداد تصادفی امن.

این توصیه‌ها با موارد زیر همسو هستند:

- ASP.NET Core Data Protection؛
- AES-256؛
- چرخش خودکار کلید.

### امنیت عملیاتی

OWASP همچنین موارد زیر را توصیه می‌کند:

- پیکربندی امن؛
- مدیریت وابستگی‌ها؛
- اسکن آسیب‌پذیری؛
- مدیریت وصله‌ها؛
- بازبینی‌های امنیتی.

این فعالیت‌ها بخشی از چرخه عمر عملیاتی می‌شوند.

### تناسب سازمانی

OWASP برای موارد زیر مناسب است:

- نرم‌افزار سازمانی
- نگهداری بلندمدت
- استقرارهای ابری
- استقرارهای ترکیبی
- صنایع تحت نظارت

### ارزیابی فناوری

| معیار|ارزیابی|
| ---|---|

| قابلیت نگهداری|عالی|

### مزایا

- مستقل از فروشنده
- نگهداری منظم
- پذیرش گسترده سازمانی
- راهنمایی جامع

### معایب

- یک چارچوب پیاده‌سازی نیست
- نیازمند نظم مهندسی
- نیازمند اعمال مداوم در طول توسعه

این ویژگی‌ها برای یک استاندارد امنیتی مورد انتظار هستند نه یک محصول نرم‌افزاری.

### نتیجه‌گیری اولیه

OWASP مناسب‌ترین راهنمایی امنیتی سازمانی را برای MachineryManagerEnterprise فراهم می‌کند.
توصیه‌های آن باید بر معماری امنیتی، پیاده‌سازی و شیوه‌های عملیاتی در طول چرخه عمر پروژه حاکم باشند.
