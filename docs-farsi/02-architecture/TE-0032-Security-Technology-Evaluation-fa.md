# ۸. ارزیابی ASP.NET Core Data Protection

## مرور کلی (Overview)

فریم‌ورک ASP.NET Core Data Protection ابزار رسمی مایکروسافت برای محافظت از داده‌های حساس برنامه‌ها است.

این فریم‌ورک موارد زیر را ارائه می‌دهد:

- مدیریت کلیدهای رمزنگاری؛
- رمزنگاری احرازشده (Authenticated Encryption)؛
- مدیریت خودکار چرخه زندگی کلید؛
- انتزاع ذخیره‌سازی امن.

اگرچه این سیستم ابتدا برای ASP.NET Core معرفی شد، اما APIهای Data Protection کاملاً مستقل از ASP.NET هستند و می‌توانند در برنامه‌های دسکتاپ، سرویس‌ها و پردازش‌های پس‌زمینه نیز استفاده شوند.

در MachineryManagerEnterprise، فریم‌ورک Data Protection به‌عنوان پلتفرم اصلی برای محافظت از داده‌های حساس برنامه‌ها که به‌صورت محلی ذخیره می‌شوند ارزیابی می‌گردد.

---

# نقش معماری (Architectural Role)

```text
           داده‌های حساس (Sensitive Data)

                   │
                   ▼

      ASP.NET Core Data Protection

       ┌──────────────────────────┐
       │ مدیریت کلیدها             │
       │ رمزنگاری                 │
       │ احراز هویت               │
       │ چرخش کلید                │
       └──────────────────────────┘

                   │
                   ▼

           بارکاری حفاظت‌شده (Protected Payload)
```

این فریم‌ورک محافظت از اطلاعات حساس را در سطح برنامه فراهم می‌سازد.

---

# نقاط قوت معماری (Architectural Strengths)

مزایا عبارتند از:

- پشتیبانی کامل چندپلتفرمی
- ذخیره‌سازی کلید با قابلیت توسعه
- API امن و مطمئن
- مستندات عالی
- پشتیبانی بلندمدت (LTS)

---

# قابلیت‌های عملکردی (Functional Capabilities)

سیستم Data Protection از موارد زیر پشتیبانی می‌کند:

- رمزنگاری احرازشده (Authenticated Encryption)
- تولید خودکار کلید (Automatic Key Generation)
- نسخه‌گذاری کلیدها (Key Versioning)
- چرخش کلید (Key Rotation)
- محافظت امن از بارکاری (Secure Payload Protection)
- ایزوله‌سازی بر اساس هدف (Purpose Isolation)
- ارائه‌دهندگان متعدد برای ذخیره‌سازی کلیدها

---

# مدل رمزنگاری (Cryptographic Model)

این فریم‌ورک رمزنگاری احرازشده را ارائه می‌دهد.

```text
متن صریح (Plaintext)

     │
بارکاری حفاظت‌شده (Protected Payload)
```

هم محرمانگی و هم یکپارچگی داده‌ها حفظ می‌شوند.

- ISO

این الگوریتم به‌طور گسترده به‌عنوان الگوریتم رمزنگاری برتر برای نرم‌افزارهای سازمانی شناخته می‌شود.

# ۱۰. ارزیابی مدیریت گواهینامه‌های X.509

## مرور کلی (Overview)

استاندارد X.509 یک استاندارد بین‌المللی برای گواهینامه‌های دیجیتال است که برای احراز هویت، ایجاد اعتماد و برقراری ارتباطات امن استفاده می‌شود.

در MachineryManagerEnterprise، گواهینامه‌های X.509 برای موارد زیر ارزیابی می‌شوند:

- امنیت لایه انتقال (TLS)
- احراز هویت متقابل (Mutual Authentication / mTLS)
- امضای دیجیتال
- اعتماد بر پایه گواهینامه
- ارتباط امن بین سرویس‌ها

گواهینامه‌ها قرار نیست جایگزین مکانیزم‌های احراز هویت برنامه شوند؛ بلکه اعتماد بین طرفین ارتباطی را برقرار می‌سازند.

---

# نقش معماری (Architectural Role)

```text
        کاربر / سرویس (Client / Service)

                       │
                       ▼

              گواهینامه X.509

                       │
                احراز هویت
                       │
                       ▼

               ارتباط امن (Secure Communication)
```

گواهینامه‌ها تأیید هویت رمزنگاری‌شده را پیش از آغاز ارتباط امن تضمین می‌کنند.

---

# نقاط قوت معماری (Architectural Strengths)

# ۱۱. ارزیابی چرخش خودکار کلید (Automatic Key Rotation)

## مرور کلی (Overview)

چرخش کلید (Key Rotation) عبارت است از جایگزینی کنترل‌شده کلیدهای رمزنگاری در طول زمان تا میزان افشای بلندمدت کلید در صورت لو رفتن کاهش یابد.

سیستم‌های سازمانی به‌جای اتکا به کلیدهای رمزنگاری دائمی، به‌طور دوره‌ای کلیدهای جدیدی تولید و فعال می‌کنند و هم‌زمان دسترسی به داده‌های رمزنگاری‌شده قبلی را حفظ می‌نمایند.

در MachineryManagerEnterprise، چرخش خودکار کلید به‌عنوان یک قابلیت امنیتی الزامی سازمانی ارزیابی می‌شود.

---

# نقش معماری (Architectural Role)

```text
کلید فعال (Active Key)
     │
رمزنگاری داده‌ها (Encrypt Data)
     │
بازه زمانی چرخش (Rotation Interval)
     │
تولید کلید جدید (Generate New Key)
     │
فعال‌سازی کلید جدید (Activate New Key)
     │
حفظ کلیدهای قدیمی (Old Keys Retained)
```

تنها جدیدترین کلید فعال برای رمزنگاری استفاده می‌شود، درحالی‌که کلیدهای قبلی برای رمزگشایی باقی می‌مانند.
