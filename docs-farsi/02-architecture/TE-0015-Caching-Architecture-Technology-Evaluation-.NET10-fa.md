# هدف

این سند فناوری‌های کاندید برای «ارزیابی فناوری معماری کشینگ» در MachineryManagerEnterprise را ارزیابی می‌کند.

# خلاصه مدیریتی

این ارزیابی فنی به مقایسه راه‌حل‌های کشینگ (Caching) درون‌حافظه‌ای (In-Memory)، توزیع‌شده (Distributed) و ترکیبی (Hybrid) پرداخته تا معماری کشینگ مناسب برای پلتفرم MachineryManagerEnterprise مطابق با ADR-0020 انتخاب شود.

هدف، شناسایی یک استراتژی کشینگ دو لایه‌ای (Hybrid L1/L2) با کارایی بالا، تاخیر کم و سازگار با معماری تمیز (Clean Architecture) است.

---

# دامنه ارزیابی

این ارزیابی موارد زیر را پوشش می‌دهد:

- کشینگ درون‌حافظه‌ای (In-Memory L1 Cache)
- کشینگ توزیع‌شده (Distributed L2 Cache)
- کشینگ ترکیبی (Hybrid Caching) و ابزارهای مدیریت همگام‌سازی آن
- ابطال کش (Cache Invalidation) و استراتژی‌های انقضا (Expiration Strategies)
- یکپارچه‌سازی با .NET 10 (از جمله `HybridCache` جدید در .NET 9/10)
- پشتیبانی از محیط‌های On-Premise، Cloud و Hybrid
- عملکرد، قابلیت اطمینان و لایسنس

# ارزیابی گزینه‌ها

---

## ۱. .NET 10 `HybridCache` (موتور جدید بومی .NET)

### بررسی کلی
مایکروسافت در .NET 9 و .NET 10 قابلیت جدید `HybridCache` را برای جایگزینی و بهبود `IDistributedCache` و `IMemoryCache` معرفی کرد. این API به طور هوشمند کش لایه اول (In-Memory) و لایه دوم (Distributed) را با هم ترکیب می‌کند و به صورت داخلی شامل Cache Stampede Protection (مکانیسم Lock زدن روی کلیدهای همزمان) است.

### مزایا
- انتزاع رسمی و بومی دات‌نت بدون نیاز به پکیج‌های شخص ثالث ناپایدار.
- عملکرد فوق‌العاده بالا و مدیریت حافظه بهینه.
- جلوگیری خودکار از مسئله Cache Stampede.
- یکپارچگی ۱۰۰٪ با تزریق وابستگی و اکوسیستم .NET 10.

### معایب
- برای همگام‌سازی ابطال کش در L1 بین چندین گره (Node)، همچنان نیازمند اتصال به یک لایه L2 (مانند Redis) است.

---

## ۲. Redis / Garnet (به‌عنوان کش لایه دوم L2)

### بررسی کلی
Redis یک ذخیره‌ساز ساختار داده درون‌حافظه‌ای توزیع‌شده بسیار معروف است. Garnet نیز پروژه جدید و با کارایی بسیار بالای مایکروسافت مبتنی بر پروتکل Redis است.

### مزایا
- استاندارد دی‌فاکتوی صنعت برای کشینگ توزیع‌شده.
- عملکرد فوق‌العاده بالا و زمان پاسخ‌دهی زیر میلی‌ثانیه.
- پشتیبانی عالی در .NET از طریق `StackExchange.Redis`.
- پشتیبانی کامل به عنوان L2 Backing Store برای `.NET HybridCache`.

### معایب
- تغییرات اخیر لایسنس Redis (پروژه‌های Garnet یا KeyDB جایگزین‌های با لایسنس پروانه‌ای مناسب‌تر هستند).

---

## ۳. FusionCache

### بررسی کلی
یک کتابخانه فوق‌العاده قدرتمند متن‌باز دات‌نت برای کشینگ ترکیبی (L1+L2) که قبل از معرفی `HybridCache` دات‌نت محبوبیت زیادی کسب کرد.

### مزایا
- ویژگی‌های بسیار غنی مانند Fail-Safe، Soft/Hard Expiration و Backplane integration.
- عملکرد عالی.

### معایب
- شخص ثالث بودن در مقایسه با API رسمی `HybridCache` دات‌نت ۱۰.

---

# تحلیل مقایسه‌ای و معماری پیشنهادی

برای دستیابی به بالاترین کارایی و رعایت کامل Clean Architecture:

1. **لایه انتزاعی و API اصلی کشینگ در کد:** استفاده از **`.NET 10 HybridCache`** در لایه Application/Infrastructure.
2. **لایه اول کش (L1 Cache):** کش درون‌حافظه‌ای بومی که توسط `HybridCache` مدیریت می‌شود.
3. **لایه دوم کش (L2 Cache - توزیع‌شده):** استفاده از **Garnet / Redis** به عنوان Distributed Cache Backing Store.
