# ۱. هدف (Purpose)

این سند به ارزیابی فناوری‌های کاندید برای رابط کاربری کلاینت در MachineryManagerEnterprise می‌پردازد.

هدف اصلی، دستیابی به یک انتخاب یکپارچه از فناوری‌ها است که تمام الزامات عملکردی و معماری را برآورده ساخته و هم‌زمان اصول معماری پاک (Clean Architecture) را حفظ کند.

فناوری‌های انتخاب‌شده باید قابلیت‌های زیر را ارائه دهند:

- رابط کاربری مدرن دسکتاپ
- قابلیت اجرا در چندپلتفرم
- معماری MVVM
- قابلیت نگهداری سازمانی
- عملکرد نیتیو و بومی
- تجربه کاربری غنی دسکتاپ
- پشتیبانی بلندمدت
- بهره‌وری عالی توسعه‌دهندگان

# ۸. ارزیابی Avalonia UI

## مرور کلی (Overview)

فریم‌ورک Avalonia UI یک فریم‌ورک مدرن و چندپلتفرمی رابط کاربری برای برنامه‌های .NET است.

این فریم‌ورک توسعه برنامه‌های دسکتاپ نیتیو را با استفاده از موارد زیر امکان‌پذیر می‌سازد:

- XAML
- MVVM
- رندرینگ شتاب‌یافته سخت‌افزاری
- کنترل‌های نیتیو دسکتاپ

برخلاف فناوری‌های منحصر به ویندوز مانند WPF یا WinUI، فریم‌ورک Avalonia به‌طور یکنواخت در Windows، Linux و macOS اجرا می‌شود.

در MachineryManagerEnterprise، فریم‌ورک Avalonia UI به‌عنوان فریم‌ورک اصلی برنامه‌های دسکتاپ ارزیابی می‌شود.

---

# نقش معماری (Architectural Role)

```text
لایه کسب‌وکار (Business Layer) -> ViewModels -> Avalonia UI -> [Windows, Linux, macOS]
```

فریم‌ورک Avalonia لایه ارائه (Presentation Layer) را پیاده‌سازی می‌کند، درحالی‌که کاملاً مستقل از منطق کسب‌وکار باقی می‌ماند.

---

# نقاط قوت معماری (Architectural Strengths)

مزایا عبارتند از:

- فریم‌ورک واقعی دسکتاپ چندپلتفرمی
- پشتیبانی از XAML
- یکپارچگی نیتیو با .NET
- رندرینگ شتاب‌یافته سخت‌افزاری
- معماری سازگار با MVVM
- زیست‌بوم فعال متن‌باز
- ابزارهای عالی
- نقشه راه بلندمدت

# ۱۰. ارزیابی CommunityToolkit.Mvvm

## مرور کلی (Overview)

کتابخانه CommunityToolkit.Mvvm فریم‌ورک رسمی MVVM مایکروسافت برای برنامه‌های مدرن .NET است.

این کتابخانه زیرساخت سبک MVVM را فراهم کرده و کاملاً همراستا با زیست‌بوم .NET مایکروسافت باقی می‌ماند.

برخلاف فریم‌ورک‌های سنگین‌تر MVVM، تمرکز CommunityToolkit.Mvvm بر سادگی، تولید کد در زمان کامپایل (Source Generators) و حداقل بار اضافی در زمان اجرا است.

در MachineryManagerEnterprise، کتابخانه CommunityToolkit.Mvvm به‌عنوان فریم‌ورک اصلی MVVM ارزیابی می‌شود.

---

# معماری Source Generator

این فریم‌ورک به جای رفلکشن در زمان اجرا، کدها را در زمان کامپایل تولید می‌کند:

```text
سمبل‌ها و ویژگی‌ها (Attributes) -> Source Generator -> کدهای کلاسی تولیدشده MVVM -> اسمبلی کامپایل‌شده
```

این امر هم عملکرد و هم قابلیت نگهداری را بهبود می‌بخشد.

# ۱۱. ارزیابی ReactiveUI

## مرور کلی (Overview)

در MachineryManagerEnterprise، فریم‌ورک ReactiveUI به‌عنوان یک گزینه جایگزین برای MVVM ارزیابی شد اما به‌دلیل پیچیدگی بالا و عدم نیاز به معماری کاملاً واکنشی **رد شد (Rejected)**.
