# ۱. هدف (Purpose)

این سند استراتژی نسخه‌بندی API را برای MachineryManagerEnterprise تعریف می‌کند.

---

# ۲. استراتژی نسخه‌بندی (Versioning Strategy)

APIها باید از نسخه‌بندی در مسیر URI (URI Path Versioning) استفاده کنند.

فرمت:

```
/api/v{major}/{resource}
```

مثال:

```
/api/v1/assets
```

---

# ۳. قوانین نسخه‌بندی (Versioning Rules)

- افزایش نسخه اصلی (Major Version) نشان‌دهنده تغییرات شکننده (Breaking Changes) است.
- تغییرات جزئی/وصله (Minor/Patch) مسیرهای URI را تغییر نمی‌دهند.
- چندین نسخه اصلی می‌توانند در طول دوره‌های منسوخ‌سازی (Deprecation Periods) به‌طور هم‌زمان اجرا شوند.

---

# ۴. تغییرات شکننده (Breaking Changes)

نمونه‌هایی از تغییرات شکننده:

- حذف یک اندپوینت
- حذف یا تغییر نام یک ویژگی (Property)
- تغییر انواع داده فیلدهای موجود
- افزودن پارامترهای اجباری به درخواست

---

# ۵. تغییرات غیرشکننده (Non-Breaking Changes)

مثال‌ها:

- افزودن فیلدهای اختیاری جدید
- افزودن اندپوینت‌های جدید
- بهینه‌سازی‌های عملکردی داخلی
